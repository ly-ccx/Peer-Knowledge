# 产品体验开发执行规程

创建时间：2026-10-23
最后更新：2026-10-23

> 状态：生效。将体验规范接入后续需求、实现和评审；不新增逐日测试门槛。
> 入口：[Frost 体验规范](../knowledge/specifications/peer-product-experience-standard.md)、[人机交互契约](../knowledge/specifications/peer-human-agent-interaction-contract.md)、[动效规范](../knowledge/specifications/motion-system.md)、[过渡规范](../knowledge/specifications/transition-system.md)。

## 1. 开工时先定位

1. 按代码仓 AGENTS 解析知识根，不提交本机路径。
2. 读产品北极星和本次涉及的 UI、交互、动效、过渡规范章节；找到现有同类界面、组件和 token。
3. 分级：纯表达为 C；涉及 chat/tool runtime、IPC、task-thread 为 B；移动权限、Evidence、协议、System Context 或存储边界为 A。规范落地不自动授予越界权。
4. 一次只处理用户授权的范围；存量大文件不继续长大，共享逻辑放既有 reducer/kernel/组件 seam。

## 2. 本次体验契约（写进任务说明或 PR）

小修可用一段话，复杂功能用下表；不要求机械填写与本次无关的长表单。

| 项目 | 必须明确 |
|---|---|
| 用户目的 | 用户要完成什么；什么情况下会看到这个界面 |
| 行动权 | Peer 推进、等待外部、需要用户决定分别怎样表达 |
| 事实源 | 显示值、接收回执、权限、执行结果、验证结论分别从哪里来 |
| 状态 | 默认/加载/空/禁用/处理中/成功/失败/失效/恢复中，哪些不适用 |
| 用户控制 | 键盘、输入法、焦点来回、滚动、停止/取消、自由回答 |
| 视觉与动效 | 复用哪些 token/部件/基元；为什么发生动画；减少动效终态 |
| 恢复 | 保住什么、如何重试、如何防止重复副作用 |
| 宿主与边界 | Desktop/TUI/CLI/远程的适用能力；是否需 A/B 级契约工作 |
| 实际验证 | 已做的内容/diff 审阅；未运行的验证与发布时覆盖项 |

不要把“精致、丝滑、符合规范”当作上表的替代内容。

## 3. 实现落点

| 问题 | 优先落点（代码仓内） |
|---|---|
| 字体、颜色、圆角、空间、焦点 | `apps/desktop/renderer/src/styles/tokens.css` 的既有语义层 |
| 通用动画 | `styles/motion.css` 与 `app/hooks/useMotionPresence.ts` |
| 模态焦点、键盘边界 | 共享 overlay / `app/hooks/useFocusScope.ts` |
| 图标 | `ui/icons/PeerIcon.tsx` 或已有 SVG |
| 设置分组与行 | `ui/settings/SettingsGroup.tsx` 及其共享样式 |
| 阅读意图、跟随与每帧滚动 | `chat/state/threadScrollPolicy.ts`、`streamingScrollScheduler.ts` |
| 业务事实与授权 | 既有 protocol、main/runtime 投影与执行链；不在组件另造真源 |

这里是导航，不规定所有问题必须改这些文件。应先读调用链，优先复用；不能为了“统一”扩大一个小修的范围。

## 4. 日常交付：审阅内容与 diff

- 结构是否围绕委托和行动权，关键内容是否默认可见。
- 是否复用已有 token/组件；图标是否 SVG；没有新 CDS/硬编码主题分叉。
- 状态是否有真实来源；没有 timer 成功、假回执、假百分比或文本冒充 Evidence。
- 输入法、焦点、滚动、停止、错误和恢复的路径是否被本次实现保留。
- 动效是否只负责表达；可中断、有清理、减少动效时终态完整。
- 文字放大、长名称、多语言、窄容器与无障碍是否有明确处理；未实现写缺口。
- 文档、示例和产品文案是否一致；不将模拟数据称为真实产品验收。

**日常不自动运行 unit/integration、截图/交互回归、build、type、architecture、IPC 检查，也不等待测试 CI 作为交接前提。** 用户明确要求时按要求提前验证。必要的契约测试可以编写并留待发布运行；纯文档、指令、小样式不增加镜像实现的测试。

## 5. 发布验收

发布必须先完成代码仓 AGENTS 的全部开放 PR 合并门槛；冻结最终组合候选后执行完整 build、测试、类型、架构/IPC 与产品回归。体验检查进入同一份回归证据，不另造第二份“设计已通过”账本。

在既有 [product-regression.md](product-regression.md) 的捕获与 verify 流程中，按本次变更覆盖：

| 类别 | 必须考虑的交互与证据 |
|---|---|
| 主路径 | 委托 → 推进 → 需要你 → 结果；同一真实任务可回到原现场 |
| 视觉 | 浅/深、注册主题、字号、长文案、窄布局、空/加载/失败/失效 |
| 输入 | 中文/日文等组合输入，Enter/Escape，补全，附件失败，排队，重试去重 |
| 视口 | 主动上滚不抢回、回到最新、引用定位、内容增高与虚拟重测 |
| 焦点 | 键盘完整主路径、最上层 Escape、模态背景隔离、关闭恢复 |
| 交接 | 授权不等于成功，部分/未验证可见，停止与取消区分，重启失效决定 |
| 动效 | 减少动效、反向/快速重复操作、卸载兜底、不重播历史状态 |
| 可访问性 | 文字/关键线索对比度、目标尺寸、放大、读屏状态与静音策略 |

AI 必须逐图查看标准 packet 要求的全部截图并填写 `review.json`，再运行 verify。截图不能证明 IME、去重或读屏，需要相应交互依据。脚本目前没有覆盖的场景记录缺口，不能假称已自动覆盖。说明是否独立复核、真实模型、安装包和辅助技术的实际范围。

## 6. 缺陷与例外

- **阻塞**：假成功、丢失/误发输入、越权表达、决策作用范围错误、无法停止/恢复、关键路径键盘不可达；按实际影响纳入发布阻塞。
- **体验偏差**：不一致 token/几何、滚动或焦点被抢、错误难恢复、长文案挤压、动效过度；触及路径优先收敛。
- **可选增强**：边缘羽化、共享元素转场、轻量触感；不挤占正确性、恢复和可达性。

例外记录：涉及位置、偏离条款、用户收益/限制、替代路径、退出条件。不得用“特效”豁免事实、权限和用户控制。

## 7. 本次规范落地与后续顺序

本次只交付规范、来源研究与开发入口。已复用的基础包括 Frost token、集中 keyframes、退场/focus helper、共享设置组和滚动策略；这不表示所有调用处已经统一。

后续按实际需求逐处收敛：先解决误发/草稿与决策事实，再解决焦点/滚动/恢复，再统一控件和状态，最后做可选动效。具体缺陷须有源码或复现依据，本列表不是对存量产品的未经验证缺陷宣告。

新增类型、协议、事实投影或存储的工作仍按 A/B 分级先处理契约。要修改规范本身，写清用户收益、被替代条款和兼容影响，并更新两个仓库的入口；普通功能 PR 不悄悄另立一套规范。

## 8. 全产品矩阵如何进入实际任务

入口：[页面/组件交互矩阵](../design/product/peer-interaction-standardization-matrix.md)、[UI/动效/过渡覆盖表](../design/product/peer-ui-motion-transition-matrix.md)、[当前改造计划](../design/product/peer-product-renovation-plan.md)。页面用 P、组件用 C、体系用 U/M/T、源码差异用 G 编号；这些是文档索引，不是新业务 ID。

每张实际实现卡引用涉及编号，记录允许文件、状态模板、事实来源、恢复责任和共享 seam。状态从已登记→待实现/待核→实现已审阅→候选验证通过推进；最后一项绑定 source/包/证据，不能由文档提交代填。

E02–E12 承担具体闭环与宿主工作；E15 维护 UI 角色与组件状态收敛，E16 管动效终态/中断/减少动效，E17 管上下文过渡。复用同一次实现和 E13 发布证据，不分别建重复状态机、重复 PR 或三套验收系统。新增/拆分/移除页面组件同步矩阵；不以“这个文件已改过”代表全部状态已经合规。

本轮矩阵只做内容、路径与 diff 审阅；测试/构建/类型/架构/IPC、截图和交互回归仍依最新 Validation Scope 留待发布或用户明确要求。
