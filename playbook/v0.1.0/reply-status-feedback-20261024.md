## 思考强度误拒绝与非宿主重试：根因复核

用户指出模型已测试通过，不能把本地错误提示当成模型能力结论。复核确认：

- 本机模型配置中 GPT-6.1 Sol 声明了 `max`，机器人保存的选择也是该模型与 `max`。原失败仅约 114 ms、执行轮次为 0，是本地路由拒绝，未进入模型请求。
- 实际执行权仍由旧终端开发包 `86eb3fbb` 持有，而非新开的桌面。对照该包对应源码与当前集成线，`tui-turn-executor.resolveGoalRole` 把共享模型元数据转成路由输入时漏传 `supportsReasoning`、强度列表与默认值。机器人模型设置新增的显式强度校验因此拿到空列表，把已声明的 `max` 误判为不支持。模型连通性测试并未覆盖这一层适配。
- 桌面“继续尝试”先检查租约；该现场由终端持有租约，因此返回 `HOST_OFFLINE`。原 `cardActionErrorKey` 没有映射此码，显示泛化的“操作失败，请重试”。这与模型服务是否支持强度是两件事。
- B 级补修保留原有共享元数据的 `supportedReasoningEfforts` / `defaultReasoningEffort` 到路由接口；没有放松真实不支持强度的校验，不改变用户保存的模型或强度。C 级补修让非宿主错误指向已有宿主接管流程；历史本地强度拒绝明确写成本地校验拦截，不能再声称是模型端拒绝。
- 新增终端路由边界用例：声明的 `max` 在主 Bot/执行/复核角色均保留，默认强度不丢失，未声明的 `xhigh` 仍拒绝；补非租约持有方不得派发重试及错误提示用例。遵照验证约定未运行这些测试。

首次排查只读了错误文案就归因为“模型不兼容”，缺少执行宿主和能力投影核对；本节更正这一结论。旧错误仍是历史记录，不自动重发，未知执行和接管继续沿既有宿主租约与停止/释放流程。

本地处理：开发窗口热更新后空白，整窗重载未恢复，已重启同一开发实例，未清理数据。通过原有“在桌面接管”按钮请求交接后，实际租约已由旧终端变为当前桌面进程；原终端进程保留，但不再持有该机器人租约。机器人档案文件修改时间与模型/`max` 配置均未变。未替换全局终端安装包、未点击继续尝试或发送模型请求，真实模型回复仍待用户本地试用/发布验证；完整测试未运行。

## 用户目标与现场

让连续回复表达已有内容和真实进展；不把所有阶段都压成“等待/耗时较久”，不让无关设置刷新打断对话。

1. 用户提供的两张截图均为回复占位：“这次回复耗时较久 / 刷新状态”。源码确认原 `ReplyPresence` 从输入或回合开始计时 15 秒后覆盖正常阶段；计时只说明经过时间，无法证明卡住或失败。
2. 当前开发实例的最新回复已是失败卡；第一层只写“本次回复未完成”，详情才显示宿主诊断“所选模型不支持该推理强度”。这证明错误被过度概括；不能据此认定用户两张截图当时也是同一故障，或认定当前模型能力仍不兼容。
3. 模型菜单可打开，当前选择和思考强度可读；未改变模型或强度，未点击继续尝试，未发送真实模型请求。无法从这次只读观察证明模型端时延或请求成功率。
4. “正在读取设置…”来自 `useBotModels` 的窗口 focus/事实通知重读，经 `BotModelFeedback` 投到对话底部。截图结束后回到窗口可以触发该重读；没有证据表明截图本身发起模型请求。短暂闪字来源由代码确认，现场截图未捕获该瞬间。
5. 首次补修显示具体强度文案，后续根因复核发现它把本地校验错误归给了模型，现已更正为“本地模型配置校验未通过，尚未发起本次请求”。原始详情保留，个人模型配置不改。

现场截图和笔记只留临时审查包，不提交私人对话。步骤 2 的主界面和详情均已记录；动态等待、读屏播报、减少动效和真实模型时延仍待候选验证。

## 状态、事实与恢复

| 状态 | 事实来源 | 本轮表达 | 用户控制 / 恢复 |
|---|---|---|---|
| 待发送 | pending.sending | 正在发送 | 原输入恢复链，不提前声称已收到 |
| 已收到但无活动 | 持久接收回执 / pending | 已收到，等待处理进展；静态 | 可读状态刷新，不重发输入、不伪造模型运行 |
| 无公开正文的活动 | ProjectAgentActivity.phase / 安全工具标签 | 等待模型、思考、阅读、核对等实际阶段 | 同一个状态/详情入口；正常活动不增加刷新按钮 |
| 已有公开进展 | 当前连续回复 paragraphs | 保持正文，普通过程在详情 | 不叠加按时间生成的警告，不自动展开内部过程 |
| 待授权 / 恢复 / 停止中 | 宿主 activity / 原停止请求 | 保留明确状态 | 专用授权与停止链不变；界面不调度业务重试 |
| 中断 / 停止 / 已结束待同步 | terminal activity | 各自准确文字，停止循环 | 保留已生成正文；可重新读取，持久卡到达后由卡接管 |
| 已有失败卡 | 宿主 card / recovery / failureStatus | 本地强度校验拦截和服务端拒绝分开；非宿主重试说明执行权及接管位置 | 保留原诊断详情、实际 canContinue 约束和手动恢复入口；不自动降强度、换模型或越过租约 |
| 设置首次读取 | useBotModels | 仅设置现场可显示读取；对话模型控件表达忙碌 | 不阻塞文本编辑；失败仍可重读 |
| 设置后台读取 | 同一 workspace 已加载数据 + reading | 保留已有模型选择，静默重读 | 不向对话插入“读取设置”；真实读/写错误、保存中、待重试/无模型仍可见 |

## 涉及入口与实现

- E04/E08 补修；P06/P13/P17/P34，C137/C144/C152/C154/C203。
- `replyPresenceState` 复用 `replyActivityLabel`，只做展示投影；`ReplyPresence` 删除 15 秒状态替换和计时器。公开正文、同一回复 ID、原详情记录不改。

- U12/U14/U15，M08，T06：不加动画或固定防闪延迟，循环仅由真实活跃状态驱动；窗口 focus 不改变草稿、正文或阅读意图。
- 已补状态投影与已知诊断的边界测试，更新既有产品脚本对公共正文安静呈现的断言；未运行本地测试/build/type/architecture/IPC 或完整产品回归，不以静态实现宣称动态场景已通过。
