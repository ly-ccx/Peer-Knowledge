# Bot 流式回复与交互验收

日期：2026-10-04。关联实施卡 `rc-chat-streaming.md`、ADR85。本文件针对 RC5 之后的源码修复；安装版 RC5 不包含本修复，版本号、安装包和正式发布不在这张卡内。

## 验证范围

受控提供方通过现有 AgentTurnExecutor 注入，后续走实际 runner、宿主、IPC、preload、React 和 Electron。测试明确控制“首片到达”和“提供方完成”的不同时间，禁止把最终回复截图当作流式成功证据。它验证流式事件在产品中的表达，不证明真实云端模型延迟、语义质量或实际文件/命令执行；权限与 Evidence 仍按原测试和治理链验证。

停止只中止本轮 Bot 回复生成。已派发任务继续由任务暂停/取消管理。已执行的真实工具事实保留；部分文字明确标为未完成，不成为已验收成果。宿主拒绝或抑制的 post_reply 草稿必须退出可见回复，自动唤醒、silent、digest 不提前显示正文。

## 工程复验

在代码仓库根运行；Node 25、pnpm 10.22、Bun 和 macOS 可见桌面按开发手册准备。原生脚本创建临时隔离 home 和源码副本，不重置真实用户数据，不下载或安装更新。

```sh
pnpm build
pnpm typecheck
pnpm architecture:check
pnpm --filter @peer-agent/protocol test
pnpm --filter @peer-agent/runtime-node test
pnpm --filter @peer-agent/desktop test
node scripts/rc-response-interaction-smoke.mjs --accessibility --output /tmp/peer-chat-stream-report.json
```

脚本输出 `root` 指向本次临时证据目录：`stream-waiting.png`、`stream-first-chunk.png`、`stream-tool-and-draft.png`、`stream-complete.png`、`stream-stopped.png`、`stream-narrow-{dark,light}.png`、report 与 trace。版本页在源码 Electron 实验中显示 Electron 版本；不能据此当作签名安装包版本测试。每次必须记录 sourceHead 和 sourceDirty。

## 负责人手工评测

准备两个测试机器人 A/B；给 A 配置一个实际可用的模型；在测试目录进行只读请求。先用 A 输入：“分段解释这个测试项目，使用标题、列表和代码块”。录屏应包含点击发送、首片到达及最终完成。

| 编号 | 操作 | 通过标准 |
|---|---|---|
| S01 | 发出普通问题，提供方尚未输出 | 用户正文先出现，发送/已收到位于正文下方；等待或思考提示在本轮回复位置；输入区域有 SVG 停止入口。 |
| S02 | 观察首片至完成 | 首片在请求仍进行时可见，正文随真实分片增长；不能整段完成后才出现，也不能对完成正文伪造打字。 |
| S03 | 使用 post_reply 回复 | 根 text 参数增量同样可见；私有推理、其它参数、原始工具输出不进入聊天正文。 |
| S04 | 标题、列表、链接、代码围栏逐片到达 | Markdown 随内容恢复排版；不会执行 HTML；长行不会把整个聊天区域撑出横向滚动。 |
| S05 | 等待时引用用户输入 | 引用使用相同 SVG 上下文入口，生成/完成前后可定位原消息；没有左侧强调线、消息光晕。 |
| S06 | 模型发起只读工具 | 过程是小字号 SVG 行；仅实际 tool-call/result 推进状态；失败或拒绝不能标为成功，不把正文声明当执行证据。 |
| S07 | 处于底部，持续接收分片 | 跟随最新内容；完成后预览被正式回复替换一次，没有两份正文。 |
| S08 | 生成中向上滚动阅读旧消息 | 阅读位置保持，新增分片不强行拉回底部；出现“回到最新消息”SVG 按钮；点击后恢复跟随。 |
| S09 | 点击引用定位跨页旧消息 | 正确加载并突出原消息；后续分片保持阅读位置；返回最新仍能看到本轮。 |
| S10 | A 生成中切换 B，再回到 A | B 不显示 A 的文字；回到 A 从快照恢复当前前缀，不重跑请求，不闪回较旧内容。 |
| S11 | 生成中输入下一条草稿，再停止 | 只停止本轮生成；已到达部分保留并明确“内容未完成”；草稿及引用保留，停止入口收起。 |
| S12 | 连点停止，或完成边界点击停止 | 对已完成/旧 turn 返回 stale，不覆盖正式回复，不停止另一轮或其它机器人。 |
| S13 | 对停止回合点击重发 | 一次显式新回合；已有部分仍标为未完成；完成后重发入口解析/收起，不重复派发多轮。 |
| S14 | 停止后退出并重开 | 历史部分与停止标记仍在；已停止输入不会自动重放；宿主失效时不得绕开租约执行停止/重试。 |
| S15 | 网络失败，再手工重发 | 未验收草稿退出正式回复；失败卡明确提供重发；不会把失败表现成已完成或重复最终正文。 |
| S16 | 中文输入法选词、Shift+Enter、多行粘贴 | 选词 Enter 不发送；Shift+Enter 换行；输入框自动增高至上限后内部滚动，不挤满窗口；空白不能发送。 |
| S17 | 生成期间再次发送一个问题 | 第二条先收到，按项目串行队列执行；第一轮结束不能误称第二条已回答。 |
| S18 | 760px 窄窗口、明/暗主题、键盘 Tab/Enter | 无横向溢出；引用、停止、发送、最新按钮都有 SVG 和可读标签；焦点可见，键盘停止保留草稿。 |
| S19 | 打开“查看过程” | 仍可查看正式回合的结构化过程；Evidence 引用、记忆披露和任务入口按原事实展示。 |
| S20 | 自动唤醒/安静/小结场景 | 不泄漏静默草稿；宿主允许投递后才进入正式消息；没有通过流式绕开档位或去重规则。 |

填写每项：通过/失败/未测、模型与渠道、实际版本/提交、触发步骤、录屏起止、错误内容。真实模型没有发出文本 delta 时，应记录所用适配器和事件事实，不把提供方不支持流式解释为已经验证通过。
