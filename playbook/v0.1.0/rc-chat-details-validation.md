# RC 对话选择与过程详情验收

2026-10-04。此表配合 `rc-chat-streaming-validation.md` 使用。范围是对话选择的生命周期、原聊天视觉风格及本轮过程；不是所有功能或正式发布验收。

## 环境与记录

- 使用含本卡源码的候选包，记录安装版本、提交和模型渠道；当前签名 RC5 还没有这次修复。
- 两个测试机器人 A/B，测试目录无敏感数据。请求模型提出 2–3 个可点击的选择，允许自填答案；记录屏幕和实际最终消息。
- 每项记通过/失败/未测，失败记录原问题、输入方式、是否收到、是否切换或重开、截图及时间。未收到的失败发送不能当成已回答。

## 手工案例

| 编号 | 操作 | 通过标准 |
|---|---|---|
| D01 | A 回复一个有选项的问题 | 选项紧接所属回复，使用同等权重的按钮，没有默认选中第一个；不会浮在整段聊天末尾，也不遮挡输入框。 |
| D02 | 不点选项，在输入框手输答案并发送 | 正文先出现，回执在正文下方；收到后原问题的选项收起；模型继续本轮，历史提问正文保留。 |
| D03 | 点击一个选项 | 经既有输入入口产生一条用户答案；原选项收起；没有重复答案或重复回合。 |
| D04 | 答案发送失败，点击重发 | 失败时原选项仍可见；重发保持同一个问题关联；收到后收起，仅一条 canonical 输入。 |
| D05 | 回答完成后切换 A→B→A，再退出重开 | 已回答选项不复活；其它机器人没有串入 A 的选择。 |
| D06 | 旧 RC5 历史中，问题后紧跟一条无 answerTo 的手输用户输入 | 本次纯投影将旧对话问题收起，并减少对应“需要你”计数；不改写原历史。 |
| D07 | 引用另一条消息回复，或明确回答另一个问题 | 不自动解决这张旧问题。普通用户文字不会批准权限、计划、任务签收或目标卡。 |
| D08 | 加载提问所在历史页，再回最新 | 选择仍归属原回复，仅出现一次；所属回复不在本页时，不把它追加到本页末尾。 |
| D09 | 两轮分别调用不同只读工具，各自点“查看过程” | 每条回复显示自己精确 turnId 的记录，即使回合事实存储在回复之后；明确身份缺失显示空记录，不借前一轮代替。 |
| D10 | 查看默认过程 | SVG 操作图标、本地化名称、结果状态与有界摘要；发送回复不重复正文。默认无 post_reply/原始 JSON；工具结果缺失不能称成功。 |
| D11 | 用 Tab/Enter 展开和收起“技术详情” | 焦点清楚；展开才显示原名、参数与结果；长内容有界并可滚动。该区域是只读，不代替 Evidence 或形成执行入口。 |
| D12 | 在明/暗主题、760px 窗口查看长回复、引用和选项 | 原聊天 token、字号、行距、细边框；无消息光晕和引用左侧强调线，无横向溢出或巨大双层选择卡。 |
| D13 | 在恢复的风格里生成、停止、重发，生成时切换机器人或上翻历史 | 仍满足 S01–S20 流式验收表，不能退回整段完成后才显示，也不能拉走历史阅读位置。 |

## 自动复现

先构建依赖和桌面 renderer，然后执行：

```sh
pnpm --filter @peer-agent/desktop build
pnpm typecheck
pnpm architecture:check
pnpm --filter @peer-agent/runtime-node test
pnpm --filter @peer-agent/desktop test
node scripts/rc-response-interaction-smoke.mjs --accessibility --output /tmp/peer-chat-details-report.json
```

原生脚本使用隔离数据目录和实际 Electron main/preload/renderer、输入队列、卡片投影与回合持久化。认知、工具回执和一次提交失败是受控夹具；不证明真实渠道、云模型延迟或实际工具成功。200 个机器人、10000 条聊天、100000 个收件箱事件、10000 条记忆；聊天明暗截图为 `chat-question-{dark,light}.png`，过程为 `chat-process-summary.png`。
