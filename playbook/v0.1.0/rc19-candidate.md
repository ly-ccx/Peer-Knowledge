## 根因与修复

现场两次 post_reply 已成功返回9420/9142字符的完整结果，界面4000字符预览丢掉成功结构后又被主Bot当成交付事实，造成“已执行却回复失败”，并触发后续失败熔断。有效复核报告又曾被正文关键词误拦；旧认知请求挡住新输入；SSE协议已结束仍等待EOF，headers后的取消信号也丢失。大历史下，完整计划扫描、历史重复解析/克隆、列表缓存反复淘汰与界面刷新放大共同造成卡顿。

修复保持 Provider → Manifest → Projection → Tool Call → PermissionGrant → Evidence 链：宿主使用当前配对调用的完整本地回执；展示预览继续有界。已配对检查点允许安全换模型，不重放原执行；新输入抢占无活跃能力的后台认知。协议终态、取消与无数据超时能够收尾。历史读取按用途和严格文件版本分离；协调状态使用紧凑事实；缓存仍有内存上限；刷新合并、消息身份稳定、密集历史虚拟化。
