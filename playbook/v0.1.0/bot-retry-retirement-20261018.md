# RC15 重复“继续失败”残留

日期：2026-10-18；级别：C（展示与窗口回归）。
代码沿用 [PR162](https://github.com/ly-ccx/Peer-Agent/pull/162)，本次修复候选 `10215c074bd7504f17997eb9fca33b398c592b21`。

## 真实记录与确定性缺陷

只读核对安装版 RC15 的对话、协调快照和 Provider trace：10 月 17 日 23:25 与 23:30（UTC+8）的两个回合各请求两次，上游均 HTTP 200 / response.completed，但公开文本为空且没有工具调用。随后两次续接因 `continuity_model_changed` 被拒绝，再触发连续失败熔断。23:48 的正式答复已交付，后续工作仍等待子任务；不能把答复交付解释为整个原任务已验收。

这四个响应在 text.done、content_part.done 和最终 message.content 中都没有可用公开文本，没有证据支持“解析器丢掉非空 done 文本”。上游为何生成空响应仍未知。模型/连接改变的续接保护保持有效，不用旧原生检查点强行接入另一配置。

每次失败形成独立的持久化中断卡是实际历史。宿主已把被后续进展接替的旧卡标为 resolved，Renderer 却无条件保留 CardItem 的本地 error；迟到或已返回的失败回执继续显示“操作失败，请重试”。旧卡仍有完整机器人头像和消息气泡，放大了重复失败的观感。

修复前，以真实 Runner、检查点存储和 retry IPC，受控认知模拟首次中断、继续再次失败。窗口断言 `failed receipt cannot outlive its superseded interruption` 实际失败：旧卡的 alert 数量为 1。该结果是源码缺陷的复现；不需要写入用户真实数据。

## 实现与边界

- CardItem 只在尚未结束时展示本地动作错误，host resolved 真值优先于旧 RPC 回执。
- 新 RecoveryHistory 展示模块只接收宿主已 resolved 的 agent_unavailable 卡。默认折叠为带实际时间的“先前的中断”，移除纯历史项的重复头像与气泡；同记录中的真实公开进展仍保留。
- 展开历史可打开原回复详情和原始诊断；保留原消息 ID 与定位锚点，定位到历史时展开。关闭抽屉恢复当前入口的键盘焦点。
- 当前未结束的失败仍保留原入口和允许的动作；问题卡、授权卡、用户停止以及混合卡不折叠。
- 继续失败的动作反馈说明“本次继续未完成，具体原因见最新进展”。空模型响应和模型/连接配置改变有各自说明；后者不提供无法执行的原生续接按钮。

不修改 Provider 恢复、检查点、执行预算、熔断、PermissionGrant、Evidence、协议或持久化真源。没有自动重放任务、静默删除失败记录、补写成功、修改原任务或绕过配置变化保护。当前 C 级修复不声称解决上游空响应的生成原因。

原 PR 的 B 级让出反馈修复和旧候选验收记录见 [前一记录](bot-reply-yield-feedback-20261016.md)。旧 156 图报告只绑定前一候选，不能充当当前源码验收。
