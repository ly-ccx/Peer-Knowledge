## 1. 使用规则与测试层次

本设计将 G0–G8 各阶段拆成前端、后端、跨层三组可实现用例。此处“后端”包括 Electron main、Protocol/IPC、本地 Runtime、Provider、权限、Evidence 与存储；受控网页服务器是测试夹具，不是新增产品云后端。

本文规定用例设计；对应代码分批实现，状态以实施记录和实际执行回执为准。用户未要求本轮执行测试，不运行单元/集成测试、构建、截图或交互回归。日常仍遵守当前 Validation Scope；后续用户明确要求提前验证，或准备版本/RC 时，再实现/执行相应范围。没有实现或没有运行的用例不能登记通过。

## 2. 用例格式、覆盖总览与共同断言

每行按“前置数据 → 操作/故障 → 可观察断言”实现，包含稳定 ID 和对应层次。表中多分支条件在编码时拆成具名子用例，各自保留结果；某分支通过不能代表整行已通过。

默认均为本批承诺范围内的必要回归。涉及未启用的后续编辑功能，状态为“该候选未纳入”，不能写为通过，也不能阻塞只承诺只读工作区的候选。缺失网页、文档、目录或基本 Diff 则不能称第一实施阶段完整通过。

混合标签与启动器属于第一阶段范围。G1 的布局/引用接口先验，依赖真实内容的入口/混合交互随 G2–G5 接通后收口，不制造循环门槛。G4/G6 中独立窗口、guest 迁移和 owner 切换用例在 R5w 窗口包实际纳入时验收；不支持的保活迁移须同时验证动作隐藏与地址副本语义，不能假称移动已通过。

每次记录：caseId、阶段、实现/未实现、执行状态、source identity、实际运行实例身份、夹具版本、步骤、期望、观察、证据、错误及清理结果。适用窗口用例另记 windowId/viewId/owner/generation 与 copy/move 支持矩阵；源码身份包含必要未提交差异摘要，不能只记 Git HEAD 就假设运行的是该源码。

所有用例共享下列底线，适用项失败即阻塞相应阶段：

- 目标、Bot、conversation、session、root、版本和作用范围不串用；文本、点击和 UI 状态不创建权限、执行或完成事实。
- 普通 UI 读取和布局路径不得触发文件写入、网页提交或原任务工具重放；明确验证工具读取/控制的用例只发生本次预期调用及回执。需要副作用的用例只修改隔离夹具，原生产任务与成果不被调用或改写。
- 未知、拒绝、缺失、过期、取消和部分完成分别断言；不能只检查一个笼统 error 或一条“成功”文案。
- 同步结果验证数据；异步结果同时验证顺序、身份与副作用。失败后仍核对最终状态和清理，不能把进程结束当作无重复操作的证明。

| D1 文件来源 | 代码根 C、已确认知识根 K、另一个已登记根 W、范围外临时根 O；同名文件、相同前缀根、符号链接、被移除根 | 路径完整性、候选、realpath、根与权限边界；O 内只放合成标记 |
| D2 文档 | 中文 Markdown、嵌套相对链接、代码、空文件、未知扩展名、二进制、非法/异常编码、临界大小 N−1/N/N+1、恶意 HTML/链接和远程图片 | 格式、边界、源码/正文与主动内容；N 来自实际读取契约 |
| D3 Git/比较 | 临时仓库提交 C0/C1，未暂存、已暂存、混合、未跟踪、删除、重命名、二进制、真实冲突、无变更及无 Git 目录；独立的原有修改 U | Diff 端点、索引、变化和任务成果归属；只在隔离仓库准备提交 |
| D4 网页 | 本地受控 HTTP 服务：导航页、表单页、加载暂停页、错误页；服务端计数导航/提交；页面记录 instance nonce、history、表单值 | 真实网页交互、保活、停止、迟到导航与无重复 POST；不使用真实登录站点 |
| D5 执行故障 | 原工具链内可控 Provider，对临时文件真实写入；受控 journal/Evidence；在准入、版本核对、写前、写后、回执保存前后设置 barrier | Grant、条件写入、幂等、部分完成和恢复；不是只返回成功的桩 |
| D6 旧数据 | 旧文档/浏览器设置、未知 schema、未登记引用、仅索引 Evidence、缺正文历史、完成/取消任务及其历史“开始”事件 | 兼容、只读恢复、历史身份与任务动画 |
| D7 表达矩阵 | 深/浅主题、长中英文名称、200% 字体、宽/窄窗、减少动效、键盘及组合输入序列 | 几何、标签、焦点、IME 与静态降级 |
| D8 多窗口与入口记录 | 主窗口、两个受控资源窗口、显式 window/view/owner/generation、复制/迁移能力开关、不同归属最近记录、创建失败与半迁移 barrier | 混合标签、启动器、元数据过滤、跨窗口实例/草稿归属和失败恢复；不操作用户真实窗口 |

EACCES 等错误先由 Adapter 精确注入验证错误契约；实际 OS 拒绝路径在宿主覆盖中单独记录。符号链接或原生能力在某平台不可用时记录具体限制，不能静默跳过所有范围反例后仍宣称跨平台通过。

## 15. 异步、故障注入和清理设计

1. 每用例独立数据根、应用数据与 server port。只能访问显式夹具根，不复用真实用户应用目录或当前任务实例。截图与日志仅含合成数据。
2. 先建立监听/barrier，再触发动作；用可观察就绪条件等待。禁止固定 sleep 充当“应该已完成”，也不能仅把 timeout 延长掩盖未就绪或错误 fixture。
3. 竞争场景通过 barrier 控制“请求、版本核对、读/写、回执”的顺序；不依赖偶然调度。版本不一致时断言真实冲突，不对不可控外部竞争作虚假的原子保证。
4. `try/finally` 或 runner 的异步清理必须 await：abort 未完成请求，释放 barrier，关闭 watcher/Registry/guest/窗口/HTTP server，等待子进程退出，再删临时目录。主断言失败也执行；清理失败单独记录，不吞原失败。
5. 超时必须有有界失败和诊断，所有 pending Promise 有明确结束路径。失败分支的 fixture readiness、等待与清理均纳入用例，避免出现测试结束后仍执行、悬空 Promise 或清理没发生。
6. 计数器至少区分读取、导航、表单 POST、工具调用、文件实际写入、Grant/Evidence 持久化。幂等验收以执行记录与文件结果共同判断，不能只看一次 UI 点击或一次成功 toast。
7. 使用仓库当前 CI/engine 的工具链；测试依赖 workspace `dist` 时在实际授权执行的准备阶段构建。此次设计不提前构建或启动应用。
8. BrowserView 保活使用真实 Electron identity/nonce/导航观测；网页控制使用原注册与权限链。模拟 DOM 只覆盖组件表达，不代替 guest 与原生窗口结果。
9. 前端组合事件可做确定性组件测试，原生 IME、辅助技术、实际 OS 拒绝、签名包与真实模型需在对应环境另记证据。没有条件时标未覆盖，不能统一写“全部通过”。
10. preload、宿主和 Provider 测试替身按真实 Interface/生产类型构造，明确提供当前调用需要的方法、字段和 readiness；接口变化同步更新替身。不得靠 `any`、空成功对象或静默缺方法掩盖契约变化。fixture 创建后立即登记可处理半初始化状态的清理，初始化失败同样 await 清理并保留失败原因。
11. 多窗口夹具明确登记每个窗口/guest 的真实 owner，按宿主所有权逆序清理。迁移中断时先解除可继续执行的请求并核对 journal，再清理窗口/Registry；不能以关窗口、强杀进程或删目录来隐藏重复执行和幽灵句柄。
