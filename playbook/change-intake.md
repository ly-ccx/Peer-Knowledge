# 变更入口

创建时间：2026-08-17
最后更新：2026-11-06（所有修改和新增功能先过 ADR）

> 用途：决定一条需求从哪开、先写哪、交到哪。
> 适用场景：新开 Agent 会话、跨机开发、判断要不要先改知识仓。

## 一、默认入口

日常从代码仓开始。`Peer-Agent` 的 `AGENTS.md` 已经关联本知识库；需要读治理合同时按该文件的解析规则打开本仓，不必把会话开在知识仓。

推荐工作区：代码仓为第一根，知识仓按需并列。不要把本机绝对路径写进任一仓库。

## 二、先过 ADR，再分级动手

2026-11-06 起，后续所有修改和新增功能都先过一遍 ADR，再写代码。目的是让新改动落在已有决定上，并把替代、修订和未完成的历史债务留在文档里，减少实现时的返工和互相覆盖。

过档顺序：

1. 打开 `knowledge/decisions/00-adr-map.md`。编号冲突时按文件名读，不按数字猜。图谱还没合并时，直接在 `knowledge/decisions/` 里按主题找。
2. 写出这件事已经由哪几篇 ADR 决定。页头 Accepted 只表示决定曾被接受，不表示实现已经发布验收。草案、未接受、以及被标明替代的条款，不能当成现行契约。
3. 已有决定而且这次不改那篇的边界：按那篇实现，不另开一篇。
4. 没有决定、两篇决定冲突、或这次要改已写明的边界：先修订或新增 ADR，再写代码。新编号用图谱里还没占用的号。修订写上日期，以及新增、删减、修复、优化了什么，哪一条款被替代。同一天更新图谱里的对应行。
5. 纯文档、注释、不改变行为的测试修正，也要先确认没有碰上决策边界。确认之后不必新开 ADR。

过档没有完成时，不开工。回复里写出读过的 ADR 文件名；边界未动要写明，边界改了要给出 ADR 的修订位置。

## 三、先分级，再动手

分级不能跳过第二节的 ADR 过档。

| 级别 | 判断 | 入口 | 提交 |
|---|---|---|---|
| C | UI、文案、样式、测试、小修复；过档确认未碰能力、权限、Evidence、协议、prompt 或已有 ADR 边界 | 过档后改代码 | 只交代码仓 |
| B | Chat / Tool Runtime、Prompt 组装、compaction、task-thread、IPC；过档确认边界没动 | 过档后改代码，回复里点名 ADR | 代码仓；边界变了就升为 A |
| A | 运行时契约、能力暴露、权限、Evidence、System Context 顺序、存储边界，或过档发现要改已有决定 | 先更新 ADR 和图谱，再改代码 | 知识仓先于或并行于代码仓 |

C 级升 A/B 的条件：改着改着碰到了能力执行、权限真值、Evidence、协议对象、prompt 边界，或和已有 ADR 冲突。

## 四、三件不要绑在一起

| 角色 | 含义 | 由什么决定 |
|---|---|---|
| 入口 | 会话默认开在哪 | 日常仍从代码仓开；动手前先过 ADR。A 级先改知识仓 |
| 执行 | 工具读写哪 | 本机解析出的仓库根，或 Goal 的 origin/target |
| 交付 | git 提交进哪 | 改动归属：代码进代码仓，决策进知识仓 |

从知识仓发起 ≠ 向知识仓交付。

## 五、Commit 必须立刻 Push

本地一旦 commit，必须在同一轮 push 到当前跟踪的远程分支。多设备同步以 `origin` 为准；只 commit 不 push，另一台机器拉下来会丢这次改动。

例外只有用户明确说「先不要推」。除此之外，Agent 不得把已提交改动留在本机。

## 六、本机根目录

不要在 Playbook 或 `AGENTS.md` 里写 `/Users/...`。按 `AGENTS.md` 解析：

1. `PEER_AGENT_ROOT` / `PEER_KNOWLEDGE_ROOT`
2. 各仓根目录的 `.peer-workspace.local.json`（不提交）
3. 同级目录别名
4. 已打开的多根工作区

可选本地文件示例见 `.peer-workspace.local.example.json`。复制为 `.peer-workspace.local.json` 后按本机填写。

## 七、Agent 快捷判断

可对 Agent 说：

```text
按 playbook/change-intake.md 给这条需求分级，并决定从哪开、写到哪、交到哪。
```

Agent 应先给出读过的 ADR、边界有没有动、A/B/C 和入口，再开始改文件。产品方向以 `design/product/peer-product-alignment.md` 为准，不要另写一套品类故事。
