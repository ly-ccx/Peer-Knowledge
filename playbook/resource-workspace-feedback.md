# R8：资源选区与明确用户反馈

日期：2026-10-27
状态：实施中，未验收。
级别：A/B/C；依据 ADR109 §37。

工作：有界 typed resource/version/selection + 固定 Bot 收件对象；复用本机输入草稿、幂等输入队列与 user-role 历史投影；源码/正文/Diff/目录/网页的实际选择适配；独立窗口准备草稿的真实回执。未发送不入模型、不写原文件、不获得权限。

分段：01 输入契约、存储/恢复及准入；02 资源控件/Composer；03 原生与网页交接。每段均需源码和实际范围记录，未执行验证不得写验收通过。

回归集：协议限额/范围/版本/错 Bot；草稿 CAS/重启/未确认发送/同 ID 重试；缓存按值隔离；历史投影只 user 材料；恶意摘录不产生权限/工具/Evidence；多标签/切 Bot/IME；失败保留；原生错 sender/代次/来源/导航/超时。此轮先编写不执行。

## 01/02 进展（2026-10-27，部分源码完成，未验收）

- Protocol 已提供严格、有预算、无权限/执行字段的 ResourceFeedback：文档 observation、Git 完整提交、比较/目录摘要、网页文档代次及明确 recipient；UTF-16 源码范围与 discussion 分开。缺字段的旧输入兼容，非法/超额整项失败，不伪造精确坐标。
- InputDraftStore 保存引用及未确认输入，首次写入升 v2、后续不降级，整个恢复记录引用 1MiB 限额；旧二进制拒绝未知 v2。InputRecovery 保留引用、原 inputId 与后来新草稿，准备/保存不提交队列，未知结果仍原 ID 对账/重试。
- InputQueue 的接收、消费与执行恢复都检查固定收件会话；已接收的原 inputId 重试返回第一次事实，不因换会话重投。引用缓存/返回值按值复制，不由外部修改旧队列。主 Bot 当前输入、持久历史恢复与明确委托锚点使用同一 canonical user-role 材料投影，版本升 v2；原消息不重写，不新增 System Context 注入，也不获得文件工具权限。
- 现有主窗口文档/Markdown/源码和具体比较接上显式“针对这段提问”；仅选择不发消息，按钮加入捕获的 Bot 的 desktop 草稿，保留文字/附件/消息引用。源码映射排除 gutter；渲染正文、Diff 或无法映射时使用讨论引用。选区超过预算不截断。引用卡展示固定版本/来源/收件对象、有限摘录和移除；原会话已变化时阻止前端发送。动作与局部保存反馈不撑开正文阅读面。
- 以上是 R8 已接通的主窗口源码子集，不代表 R8 已全部完成。目录选择、网页宿主选区、独立窗口准备草稿的 sender/代次/截止回执仍待 03 接入；目前不显示这些尚未接通的动作。R9 编辑草稿正文/快照/写者、R10 修改执行仍待后续。

已编写协议/限额/恶意材料、恢复 v2/CAS/固定收件/同 ID 重试、缓存按值、历史 user-role 投影、委托明确锚点、准备草稿幂等失败保留、真实 DOM Source/Markdown/外部/超额选区用例，并更新相关 VM 替身及组合测试清单。DOM 用例是显式 Playwright fixture，未运行、不称通过。仅内容/diff 自审；未运行 build/typecheck、模块/集成测试、截图或原生联调，历史 R6a 通过不覆盖本包。未提交/推送/重启/发布，未操作原个人任务及其已有写入。

01/02 收口补充：发送后的乐观用户消息和真实分页历史同样保留只读引用卡，不能在 Composer 清空后让用户失去“本条消息发了哪些材料”的可见依据。规范化损坏的引用只说明材料不可用，不丢原用户文字、不假造可访问目标。Interaction Reader 已按原 row 保留可选字段，此次不更改 SQLite schema 或重建个人缓存。


## 03 进展（2026-10-27，源码完成，未验收）

本节更新 01/02 时未接入的范围；R8 的计划源码已接线，运行和产品验收仍未执行。用户目标是在原右侧工作区、原生只读副本或网页中围绕明确材料提问，保留当前工作、读位与输入草稿，不靠打开预览自动触发对话。

- 主窗口与原生目录可显式引用已读的根清单及选中路径：最多 50 项、总摘录预算 8192 字符，列出完整/部分清单计数并说明文件正文未读；不递归、不把未读内容当事实。仅操作当前控件，保存提示固定行高；连续点击在摘要计算前已有即时互斥，重试保留同一引用 ID。异步完成不覆盖后来目录/选择的状态。
- 原生文档/源码/Markdown、目录子文件和比较共用既有选择适配。新 resource-window:feedback 仅 resource role 可调用；宿主重新核真实 sender、原租约/代次/owner/task/revision、物理 root/target、目录后代或比较基准，不能借子路径扩出已读范围。只读元数据核查沿现有 scoped reader，不创造写入权限。
- 宿主 preparation broker 固定原主 sender、请求/引用 ID、窗口代次和 3 秒截止，最多 32 全局/每原窗口 8 待办。原主窗口先 claim，再复用 InputRecovery 准备并 flush 草稿，只有持久确认才 ack 成功；超时报告未确认，迟到回执不改旧结论，不自动重试/发送。来源在 claim 前失效拒绝；claim 后捕获材料不随新页面更换，仍核原 Bot 收件对象。来源销毁/dispose 清掉监听与等待。
- 网页从真实 Electron context-menu 选区提供显式“针对这段提问”，不注入或执行远程脚本。核实际 embedded hostWebContents/native 原主窗口、标签、frame 实例和导航代次；iframe 保存实际 frame URL 及所在 pageUrl；同 URL 导航同样使旧菜单失效。选区超限或来源不支持时显示原因。引用保留实际子会话/网页标签，主 Bot 收件对象只沿宿主已有索引祖先解析，链断/归档/循环/冲突拒绝，不读整段历史、不唤醒任务。
- embedded 重注册复用一个选区监听，真实宿主改变时卸载旧绑定；native 浏览器关闭清理自己的监听。网页准备结果只发到捕获的主窗口或原生外壳，原生外壳固定单行反馈不挤动 WebContentsView；不以反馈改变活动网页执行目标、焦点或任务。普通预览仍默认右侧并排。
- 发送后只读卡片保留 iframe 所在页/实际来源说明；草稿数量、收件变化、来源变化与未确认保存分别解释，成功只称已加草稿，绝不称发送或执行。
