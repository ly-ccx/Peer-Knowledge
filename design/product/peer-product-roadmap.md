## 2. 一句话方向

引用 alignment，不另写：

> Peer 是一个人把真实工作交给本机代理、只在关键节点回来验收的**任务委托系统**。

面向用户：

> 把工作交给 Peer，只在真正需要你的时候回来。

工作关系：用户负责目标、边界与关键判断；Peer 负责持续推进，并在交还之前证明结果。聊天是介质，不是主语，也不是状态真源。

### 2.1 体验北极：对话与手机即本机操控面

体验上向 **Grok Bot 一类「对话 / 手机 = 自己机器的远程手」** 看齐：人用自然语言——在桌面说话，或在手机上说话——把真实需求交给自己的电脑，端到端驱动本机，而不是只能在桌面里聊代码。

这不是换品类，也不改 alignment。主语仍是任务委托；聊天仍是表达意图和处理例外的介质。变的是**入口能走到哪、手能伸到哪**：

| 层 | Peer 怎么落 |
|---|---|
| 人感受到的 | 对话或手机就能推进本机上的真实工作（文件、终端、浏览器、桌面应用） |
| 执行与 Evidence | **仍在用户侧电脑 / 节点**。手机和远程对话是新的*表面*（表达 + 远程入口），不是拥有机器的云端大脑 |
| 本机 Desktop | 继续零账号默认（ADR 74） |
| 手机 / 远程对话 | 必须走 ADR 74 的远程+注册：身份、设备绑定、capability 委派 |
| 「接管任何需求」 | 产品语言 = 在受治理能力链上做任务委托（文件、Shell、浏览器 / Computer Use 阶梯、应用），Permission → Evidence |

Desktop / TUI / CLI 已经是同一 Runtime 的三个入口；手机伴随应用与远程对话是第四类入口，不另起执行真相。近景先收口当前开发线的集成与真实验收（见 §4）；手机与远程体验体现在中景 #4 / #4b / #9，远景才谈「任意需求」铺开。

顺序不能倒着抄近道：

- 没有步骤 1–2，内网 / 远程会各自发明存储和旁路。
- 没有步骤 3，不要先做公网注册。
- 没有 #4 的配对与委派，不要先做手机端「接管电脑」。
- 没有可信单机闭环，Memory / Skill 进化只会放大错误。
- Canvas 与 L3 都有前置：稳定 ID、可订阅状态、L1/L2 先可用。
- 「任意需求」铺开要等 L1–L2 的手够稳、远程配对可信；L3 系统 UI 更晚。

## 6. 远景：团队与探索项

这些**不是当前主叙事**。alignment 的顺序仍是：个人本机闭环稳定 → 小团队可信协作 → 更远的企业网络。

| 项 | 含义 | 前提 |
|---|---|---|
| 「任意真实需求」铺开 | 对话 / 手机覆盖代码以外的日常本机工作（文档、浏览器流程、桌面应用） | **L1–L2 的手够稳 + #4/#4b 远程配对可信**。这是能力覆盖变宽，不是改成通用 RPA 或消费级遥控 |
| L3 系统 UI Computer Use | 操作系统级点选 / 窗口 / 辅助功能，作为更晚的手 | L1–L2 先成为默认可信路径；不把 L3 当中景交付 |
| 小团队可信协作 | 转交、共同验收、共享 Skill 审查 | 个人闭环稳定；第三阶段，不是现在对外故事 |
| 有预算的 Agent swarm | 并行探索 / 验证，仍由主导任务流托管 | 先有单任务多角色（中景 #7）和预算 |
| 超出简单 OIDC 的企业身份 | SSO、组织策略、审计保留 | **先有内网 Gateway + 远程基本面**（中景 #3–4） |
| 云增强的长时 Agent | 人在远端、执行仍在用户节点 | 不得做成云端大脑的薄壳；认知可插拔，Evidence 不默认上云 |

更远、只评估不承诺：广义 OS Computer Use 的产品化、团队实时 Canvas、Skill 交易市场、多 Peer 网络。每条先问：它是否提高可信委托，还是只扩大演示。

## 7. 明确不做什么

对齐 alignment 的禁止句，并加上部署 / 存储上已经拍板的否决项。

**品类与叙事：**

- 不做企业 Agent OS、多人协作平台、工单台。
- 不做多 Agent 角色扮演。
- 不把会话做成一等公民。
- 不说「模型说做完就算完」。
- 不把工作台做成唯一入口或默认落地页。
- 不把客户端做成云端大脑的薄壳。
- 「接管任何需求」不是无约束 RPA、不是企业 Agent OS、不是静默高风险自治。

**部署与数据：**

- 本机模式不强制注册。
- 不默认把对话、工作区、密钥或 Evidence 同步到云。
- Gateway / 云端不得成为执行或 Evidence 真相。
- 知识仓 / ADR / playbook 不迁业务库。
- 不做「全部 SQLite」大爆炸。
- 不为远程另开无 PermissionGrant / Evidence 的控制通道。
- 第三方 IM 桥不是远程第一刀。
- **手机不是薄云客户端**：不在云端拥有或执行这台机器。
- **密钥 / Evidence 不默认同步到手机云**；手机只投影已委派的任务、批准与证据摘要。
- **手机不能绕过 PermissionGrant**：远程通道权限不得高于本机已授权面；高风险动作仍要人签。

**当期不绑：**

- 不把 Linux Desktop 正式包装塞进 ADR 74 或 0.0.12 keep-alive 同一刀。
- 不把每一篇 `design/product/*.md` 升成中景赌注。
- 手机伴随应用不是 `0.0.12` 近景项；排在 #4 配对之后。

| 项目代理壳 | 中景 #0 | **阶段 F（Proposed）** | — | 远程 / 手机入口对接项目代理 |
| 多 Agent（一任务内） | 中景 #7 | 子 Agent 是手段不是主语 | Phase 2 Executor / Phase 5 协作 | 不覆盖 |
| Canvas | 中景 #8 | 不覆盖 | **Phase 5** | 不覆盖 |
| Computer Use L1→L2→L3（本机的手） | 中景 #9；L3 远景 | 不覆盖 | Phase 1 内嵌 / Phase 6 外部 | 不覆盖 |
| Skill 进化 | 中景 #10 | 不覆盖 | **Phase 4** | 不覆盖 |
| 「任意需求」铺开 / L3 | 远景 | 不覆盖 | Phase 6 + 远期探索 | 执行仍在用户节点 |
| 小团队 / swarm / 企业身份 / 云增强长时 | 远景 | 「团队不是当前主叙事」 | Phase 6 + 远期探索 | 企业身份晚于内网+远程 |

读法：要改壳，先改 charter；要改理念，先改 alignment；要开 Gateway / 注册 / 迁存储，先对照 ADR 74；要排「下一步押什么」，看本文。

## 9. 修订约定

本文随发版修订，不按日历空转。

| 何时 | 谁更新 | 改什么 |
|---|---|---|
| `peer_agent` 发稳定版（stamp `VERSION`、写 release notes） | 发版负责人或同轮 Agent | 「现在到哪了」的版本线；近景里已发布项改标为已交付 |
| 近景票合入或明确砍掉 | 改代码的那一轮 | 近景表状态；不要把未合入写成已交付 |
| ADR 74 从 Proposed 变为 Accepted / 实现开工 | 决策作者 | 对照表与中景 #1–4 / #4b 的状态句；**不在本文件重写 74** |
| 中景赌注完成或顺序被评审改写 | 提出改序的人，先对照 alignment | 只改序号与状态，不改禁止句 |
| 新主题要进中景 / 远景 | 先走第 1 节接入顺序 | 加一行赌注或远景项，并写清对照文档 |

不更新本文的情况：像素级 UI、单测、文案、与产品视距无关的 C 级修复。那些走代码仓即可。

发版时的仓库分工仍见 `playbook/release-process.md`：版本事实在 `peer_agent`；路线图与 ADR 在本仓。本地一旦 commit，必须立刻 push 到当前跟踪分支。
