## 1. 主线与适用范围

以 [产品北极星](peer-product-alignment.md) 为唯一定位来源：Peer 是本地工作委托系统。对外主张为“把工作交给 Peer，只在真正需要你的时候回来”。每个项目一个 Bot；用户给目标、边界与关键判断，Bot 理解、协调执行、跟进普通工作问题并核对结果。任务、计划和成功标准仍是执行与治理基础。

首页按用户了解产品的顺序组织：价值主张 → 当前真实界面与交互讲解 → 可委托的工作 → 协作方式 → 能力与边界 → 下载。MCP、Skills、多模型与 Runtime SDK 是支撑能力，不取代委托主线。

本次允许修改代码仓官网首页、文档站、站点静态资源和中英文 README。官网单独从 main 开分支，不把开发线运行时代码混入官网 PR；保持现有 GitHub Pages 发布管线与更新日志入口。知识和设计记录只留在本知识仓。

## 3. 文案与文档组织

- 首页标题表达交出工作后的价值；副标题说明项目 Bot、执行 Agent、本地授权与证据。
- 使用路径：选项目 Bot → 交代目标和边界 → 过程中补充、纠正或决定 → 查看结果与依据。
- 普通执行问题由主 Bot 跟进；权限、关键业务取舍和真正需要人的决定留给用户。停止指令优先，不承诺所有异常自动恢复。
- 完成、核验、签收和代码合回分别表达。撤回委托保留历史，不等同未知操作成功或副作用回滚。
- Desktop 入门围绕项目 Bot；CLI 和经典模式保留对应的 Agent/Plan/Goal 说明。
- 中英文官网与 README 同步。知识仓旧 README 叙事记录保留历史，本文件取代其与项目委托主线冲突的 Task Flow 首屏定位。

## 4. 演示素材与体验契约

素材来自隔离、虚构项目的真实 Desktop renderer；不发布个人数据、私有会话或凭证，不通过图像修改伪造已实现界面。截图标明预览版本/源码界面和演示数据；场景讲解标为示意，不是实际执行回执。

首页讲解由用户选择阶段，不用计时器伪造运行、核验或成功。主题、语言、场景切换保持当前对象和焦点；无动画、减少动效和脚本不可用时仍能读核心内容、打开文档和下载。图标沿共享 SVG；官网沿用 Frost 中性表面、石墨主操作和少量 Azure，不导入另一套设计系统。

## 5. 交付与验证边界

交付官网与知识 PR、可打开的本地静态预览。普通开发按最新 AGENTS 做内容/diff 审阅；本轮不自动运行测试、构建/类型/架构检查或全产品截图/交互回归。素材采集是经批准的官网内容制作，不作为产品回归验收。新版本/RC 的全量验证与真实模型/安装包验收仍沿原发布约定。

官网合并发布与软件版本发布分别处理；本次不发布新软件版本，也不影响正在运行的个人开发实例。
