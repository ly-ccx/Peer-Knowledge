## 0. 结论

0.1.0 把 Peer 从「会话 + 工作台」换成「机器人列表」：每个项目一个机器人，你只和机器人对话，机器人自己开任务、自己验证、按「值得打扰」的规则汇报。范围按用户 2026-09-26 的选择：机器人列表默认开启；并行任务、项目目标、记忆自动提取、TUI、远程入口全部进 0.1.0；旧会话迁为历史；中途以 `0.1.0-beta.N` 预发布日用，最后正式发 0.1.0。

路径：开 `PeerAgent/dev/0.1.0` 开发线 → 五个 beta（地基 → 骨架 → 可日用并默认开启 → 并行与主动 → 多入口）→ rc → 0.1.0。全程每个 beta 都能正常安装、升级、降级。

## 1. 0.1.0 做成什么样（发布验收故事）

一个 0.0.18 老用户升级到 0.1.0 之后：

1. 打开应用，看到的是机器人列表：他原来的每个工作区都变成了一个机器人，名字是文件夹名，头像各不相同；原来的会话在机器人档案 → 任务 → 历史对话里，一条不少，内容未改。设置里可以切回经典界面。
2. 点进 Peer-Agent 机器人，说「把设置页的用量面板改成按天分组」。机器人引用这条消息回复「在做了」，开一条任务；任务需要跑测试时，列表上出现「需要你」角标、系统通知一次；他在对话里点「允许」。
3. 他关掉窗口去开会。任务在后台继续推进、验证通过；机器人按策略代签，在对话里汇报一句话结论，不发通知（因为不需要他做什么）。
4. 回来后他追问「怎么验证的」，机器人展开验证细节和证据；他说「以后复核都用 GPT」，机器人记住并在设置的模型分工里体现。
5. 他同时让机器人做两件互不相干的写代码的事：两条任务各在自己的 worktree 里并行，互不污染；合回时按原有交付流程。
6. 他给机器人一个目标：「发 0.1.0 之前把已知 bug 修掉，CI 挂了就告诉我」。机器人定时 / 按事件检查，只在变化时说话。
7. 他新建一个空白机器人「竞品研究」，应用在 `~/Peer/竞品研究/` 建了文件夹；机器人问他负责什么，记下职责。
8. 在终端里进入项目目录运行 `peer`，打开的是同一个机器人的对话；桌面开着时终端作为客户端，消息由桌面宿主处理。
9. 在手机网页上看到机器人列表和对话，能给机器人发一句话；需要批准的事显示「需要在电脑上批准」。
10. 他删掉 0.1.0 装回 0.0.18，数据能正常打开；再升级回 0.1.0，机器人、记忆、目标都还在。

### 2.2 不进 0.1.0（放 0.1.x 或更后）

- 结果时间线（M9）、程序性记忆 → Skill Patch 候选（MM5）。
- 远程批准、远程附件、IM 渠道接入、网关离线排队。
- 更多事件触发器（Webhook、邮件、日历等）；目标之间的依赖。
- 机器人之间互相派活或群聊；机器人模板与市场（ADR 84 已排除）。
- 经典界面的移除（最早 0.2.0）。

## 4. 决策

### 4.1 已由用户拍板（2026-09-26）

| 决策 | 选择 |
|---|---|
| 0.1.0 的定位 | 机器人列表成为默认界面，项目代理可日用 |
| 额外范围 | 并行 + 自动 worktree、项目目标、记忆自动提取、TUI、远程入口全部进 0.1.0 |
| 发版节奏 | `PeerAgent/dev/0.1.0` 开发线，中途发 `0.1.0-beta.N`，最后正式 0.1.0 |
| 旧界面 | 退场；旧会话迁为对应机器人的历史；保留过渡期「经典界面」开关 |
| 受管文件夹 | `~/Peer/<名字>/`；老的 `~/PeerAgent` 迁为普通绑定机器人；机器人模式首启不再自动建 `~/PeerAgent` |
| 远程范围 | 看列表、对话与任务，能发消息；批准只在电脑上 |
| 桌面与 TUI | 每个项目一个宿主租约；另一端作为客户端，经持久输入队列 |
| 未归属旧会话 | 「我 → 历史对话」，只读，可交给某个机器人继续 |

### 4.2 本计划采用的工程决定（写进 ADR 85 或任务卡，执行方不得自行改变）

1. **一条输入路径。** 桌面界面发给机器人的消息也写输入队列，由宿主消费；不存在「界面直接写机器人对话」。
2. **迁移不改写旧数据。** 旧会话迁为历史是投影，不是搬家：按 `workspacePath` 归属，原 jsonl 一字不改。只有设置迁移会写文件，写前备份。
3. **新数据落新目录。** 机器人档案、记忆、目标在 `projects/<workspaceId>/`；运行态（租约、队列、收件箱、待批准）在 `project-runtime/<workspaceId>/`；索引在缓存目录，可重建。
4. **开关到默认的过渡。** beta.1–beta.2：开发者开关 `developer.projectAgentMode`（默认关）。beta.3 起改为用户设置 `projectAgent.shell: 'bots' | 'classic'`，所有用户默认 `bots`，开发者开关迁移后废弃。
5. **新代码的落点。** 可移植运行时进 `packages/runtime-node`（桌面与 TUI 共用），主进程只做装配与 Electron 适配；界面进 `apps/desktop/renderer/src/project-agent/`；旧的大文件不再长大（手册 §2.2 第 4 条）。
6. **模型调用的成本默认值。** 代理回合、事件唤醒、今日小结、记忆提取默认走快档或省档；任务执行按档位默认强档；复核默认不同源。

## 9. 横切要求

### 9.1 安全与权限

- `project_agent` 模式：投影白名单 + 执行硬闸双重保证；写类能力在该模式下一律拒绝，不管投影是否漏网。
- 任务（`work_session`）沿用正常权限链；需要询问时写待批准；远程不能批准。
- 记忆准入：`stated` 只来自用户消息锚点；来自工具结果、网页、文件的「以后都这样做」一律不记；密钥类内容经 shell-redaction 规则拦截；想放宽权限的记忆不生效。
- 上下文分层：记忆、任务报告、目标观察只进 `L7_CONTINUITY`；代理规则进 `L1_AGENT`；不把工具输出提升为系统指令。
- 用户上传头像只接受 png / jpg / webp，≤ 1 MB，复制进 `projects/<id>/`，渲染层通过 main 提供的受控 URL 读取。

### 9.2 性能预算（RC-01 验证）

| 指标 | 预算 |
|---|---|
| 机器人列表（200 个机器人）首屏投影 | < 100 ms |
| 列表搜索（本机 1 万条消息）输入到结果 | < 150 ms |
| 发送消息到出现「已收到」标记 | < 300 ms |
| 输入队列消费延迟（宿主在线） | < 200 ms |
| 代理回合 p50（快档模型） | < 6 s |
| 记忆检索（1 万条） | < 50 ms |
| 收件箱 10 万事件后冷启动恢复 | < 1 s |
| 空闲机器人常驻内存 | < 2 MB / 个；不为空闲机器人保持模型流 |

### 9.3 成本默认值

- 事件唤醒合并：同一项目 2 秒内的事件合成一次唤醒回合。
- 今日小结每天最多一次；项目目标的探测只读、不调用模型，只有观察到变化才唤醒代理。
- 用量记录带 `role` 与 `workspaceId`；设置 → 用量按角色与机器人分组展示（B1-09 记账，B1-10 展示）。

### 9.4 可观测性

- 日志统一前缀 `[project-agent]`，带 `workspaceId`、`sessionId`、`inputId`、`approvalId`。
- 开发者设置分区展示：租约持有方、输入队列深度、收件箱游标、待批准数、调度槽位占用（B1-11 建分区，后续卡片补数据）。
- 诊断导出（RC-03）：以上状态 + 最近 200 条事件，全部脱敏。

### 9.5 i18n、可访问性、动效

- 新文案全部进 `packages/i18n/src/index.ts`，中英文同时补；不新增 `isZh ? … : …` 内联。
- 机器人列表支持键盘上下选择、回车进入；档案抽屉打开时焦点进入、Esc 关闭并归还焦点；角标有可读文本。
- 动效只用 `styles/motion.css` 的基元；新增 `@keyframes` 必须登记白名单（`assertMotionPrimitivesAreCentralized`）；尊重 `prefers-reduced-motion`。

### 9.6 测试策略

| 层 | 做法 |
|---|---|
| 纯函数 | 协议与 runtime-node 的决策函数全部单测（投影、签收、送达、模型解析、排序、准入） |
| 运行时集成 | 用 B1-02 的脚本化回合执行器（按脚本返回文本与工具调用）跑「一句话 → 开任务 → 事件 → 回复 → 代签」全链路，不调真实模型 |
| 主进程 | IPC 通道测试；应用服务用假依赖测试 |
| 渲染层 | 逻辑下沉到纯函数 / reducer 测试；组件做源码契约测试（沿用现有风格） |
| Electron smoke | RC-01 新增 `bot-shell-electron-smoke.mjs`（参照 `task-monitor-electron-smoke.mjs`），在 `dev:lab` 隔离目录跑 |
| 迁移 | RC-04 矩阵；每个迁移步骤有幂等与失败回退测试 |
| 真实运行 | 每个 beta 的证据（§12）必须包含真实模型的运行记录 |

### 9.7 文档

- 架构知识只写 `peer-knowledge`；每个 beta 发布后更新本文 §5.2 实际情况、交付状态清单 D10。
