## 6. 源码可确认的优先缺口

### C1：跨机器人草稿与失败待发状态

本地 `cb2f5695` 中，`BotComposer.tsx` 使用局部 `useState` 保存文本，`useComposerAttachments.ts` 保存附件；`BotConversation.tsx` 以 `key={workspaceId}` 重建 Composer。发送回调是 void，Composer 发起调用后立即清空本地文本与附件。`useBotConversation.ts` 已有按 inputId 的 pending/failed/retry，**不能说所有发送失败都会丢失**；但 pending 在切换 workspace 的 effect 中清空，本次看到的路径没有承接未接收输入的跨切换恢复。

E02 本轮已先记录 A 级本机存储/协议约束，再用既有 projectRuntime device 目录恢复正文、引用、附件和未确认 envelope；renderer 不新增 fs 或 localStorage 真源。实际改造与待验证边缘见首页进度。

### C2：组合输入的共享事件边界

初始源码已有 `nativeEvent.isComposing` 与 `Process`，没有证据证明“中文必然误发”。本轮 E03 已把 composition、229/Process、keyup 和 IME→补全→提交的优先级纳入共享 seam，主 Bot/经典/Quick Chat 已接入，候选 Escape 保留正文；TUI 依实际终端信号处理。未使用全引擎 500 ms 吞键窗口，行为验证留到发布。

### C3：验证记录与新规范覆盖不是同一个集合

RC26 有完整的当时发布验证；新规范新增的跨切换草稿、完整读屏、文本放大及部分宿主边缘不能由旧截图数推导达标。现有集中 keyframe 检查也不覆盖全部语义、性能、焦点和减少动效要求。E13 将条款映射到已有回归场景，缺的记录为待覆盖，不虚构已完成的全产品审计。

### C4：从源码差异补齐到三个标准化体系

矩阵 G01–G03 将输入恢复扩到主 Bot、Quick Chat 和 TUI 项目输入；不能把经典 composer 的修复当成全部入口完成。G04–G09 对应设置静默失败/dirty 离开、tabs 键盘、分割条取消、tooltip、图片失败与记忆读取/写入回执。G10–G12 对应品牌等待、粒子 JS 减少动效与问题折叠 API 降级；G10 已随 E12 移除固定等待并补重读，G11/G12 已随 E16/E17 实现静态/中断/API 兜底；三者实际行为仍待 E13。

这些差异都附固定源码；其余状态列具体待核边缘，发布再取行为证据。E15–E17 接住 UI、动效和过渡的横向责任，具体修改仍由已有闭环工作包与当前允许文件承接，不启动一次全产品重写。

## 9. 发布与验收策略

- 日常只做实现和内容/diff 审阅，不自动跑 unit/integration、build/type/architecture/IPC 或截图/交互回归；测试可按契约要求编写，运行留待发布。用户针对当次明确要求时才提前执行。
- 发布前重新盘点所有 open PR（包括 draft、其他目标分支），完成审查与正常合并，再冻结唯一候选。未合并或阻塞项阻断发布；不能用未提交工作区替代已提交来源。
- E13 把两张矩阵编号映射到 acceptance guide、现有 packet 字段或明确的新人工交互步骤；没有覆盖的标待覆盖/限制，不能从旧图数推导通过。
- 最终组合候选执行全 build/test/type/architecture/IPC 与完整产品回归；Capture 在仓库外隔离目录，AI 逐张审图写 review，再 Verify。说明实现者自审还是独立审阅。
- 发布包、真实模型、源构建受控流程、辅助技术和七天日用分别记录。GA 依然需要既有完整流程、无 P0/P1、用户日用与明确决策；本计划不降低门槛，也不强制远景功能阻塞 GA。
- 不安装/重启个人实例；升级或回退仅在用户授权与兼容备份策略下执行。RC25/26 以后不能沿旧故事承诺任意降级继续写同一份新数据。

## 10. 效果指标与非目标

| 指标 | 希望看到的变化 | 取证方式 |
|---|---|---|
| 输入安全 | 未确认输入有恢复路径；一次输入只被处理一次 | 持久回执/输入身份与发布交互场景，不只看按钮 |
| 判断成本 | 第一层能知道下一步是谁、为什么、点什么 | 决策卡/结果卡的实际流程审阅 |
| 注意力 | 后台变化不抢焦点/阅读；只在有意义变化时打扰 | 视口、焦点和送达事实，按发布场景验证 |
| 恢复能力 | 失败、重启和重连后无未知副作用重放 | 同一任务/attempt 的回执和恢复记录 |
| 一致性 | 同一事实在列表/对话/详情/入口含义相同 | 统一投影与消费者映射 |
| 维护成本 | 同类控件和动画复用共享接口 | diff 中的重复与例外清单 |

矩阵已登记且本轮 E02–E04 已做实现审阅；未做全产品实机审计，因此没有计算现有产品的“规范符合率”，也不把上述目标编成未经测量的百分比。首轮发布覆盖基线建立后再记录改善。

明确后置：团队/代理群聊、市场、无限 Canvas、额外默认云同步、远程批准/附件、L3 系统 UI、全新存储拓扑。它们必须另走既有路线图与 ADR；不能借“全面改造”获得实施授权。
