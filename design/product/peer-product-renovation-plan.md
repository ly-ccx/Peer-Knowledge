## 1. 当前判断

Peer 已进入 **0.1.0 项目代理闭环的收敛期**。机器人壳、任务派发、授权、验证、记忆、目标、多入口与恢复已有实现和发布记录。接下来的主任务，是让它们在同一条委托链里保持一致、可靠、可恢复的体验。

下一阶段围绕六件事：意图有回执、行动有归属、执行有边界、结果有依据、中断可恢复、注意力归用户。先保护真实工作与用户控制，再统一组件和动效；共享元素、羽化、品牌特效最后安排。

0.1.0 继续以修复、兼容与验收收口；大范围视觉重排、远程新权限和新能力另列后续版本。新规范不自动把所有存量差异升级成 GA 阻塞，阻塞与否由对核心流程的实际影响决定。

## 6. 源码可确认的优先缺口

### C1：跨机器人草稿与失败待发状态

本地 `cb2f5695` 中，`BotComposer.tsx` 使用局部 `useState` 保存文本，`useComposerAttachments.ts` 保存附件；`BotConversation.tsx` 以 `key={workspaceId}` 重建 Composer。发送回调是 void，Composer 发起调用后立即清空本地文本与附件。`useBotConversation.ts` 已有按 inputId 的 pending/failed/retry，**不能说所有发送失败都会丢失**；但 pending 在切换 workspace 的 effect 中清空，本次看到的路径没有承接未接收输入的跨切换恢复。

E02 本轮已先记录 A 级本机存储/协议约束，再用既有 projectRuntime device 目录恢复正文、引用、附件和未确认 envelope；renderer 不新增 fs 或 localStorage 真源。实际改造与待验证边缘见首页进度。

### C2：组合输入的共享事件边界

初始源码已有 `nativeEvent.isComposing` 与 `Process`，没有证据证明“中文必然误发”。本轮 E03 已把 composition、229/Process、keyup 和 IME→补全→提交的优先级纳入共享 seam，主 Bot/经典/Quick Chat 已接入，候选 Escape 保留正文；TUI 依实际终端信号处理。未使用全引擎 500 ms 吞键窗口，行为验证留到发布。

### C3：验证记录与新规范覆盖不是同一个集合

RC26 有完整的当时发布验证；新规范新增的跨切换草稿、完整读屏、文本放大及部分宿主边缘不能由旧截图数推导达标。现有集中 keyframe 检查也不覆盖全部语义、性能、焦点和减少动效要求。E13 将条款映射到已有回归场景，缺的记录为待覆盖，不虚构已完成的全产品审计。

### C4：从源码差异补齐到三个标准化体系

矩阵 G01–G03 将输入恢复扩到主 Bot、Quick Chat 和 TUI 项目输入；不能把经典 composer 的修复当成全部入口完成。G04–G09 对应设置静默失败/dirty 离开、tabs 键盘、分割条取消、tooltip、图片失败与记忆读取/写入回执。G10–G12 对应品牌等待、粒子 JS 减少动效与问题折叠 API 降级；G10 已随 E12 移除固定等待并补重读，G11/G12 仍待 E16/E17。

这些差异都附固定源码；其余状态列具体待核边缘，发布再取行为证据。E15–E17 接住 UI、动效和过渡的横向责任，具体修改仍由已有闭环工作包与当前允许文件承接，不启动一次全产品重写。
