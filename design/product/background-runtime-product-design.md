### 入口与状态归属

- 唯一入口是对话标题栏搜索旁的单个后台运行图标，不是顶部一级导航。侧栏底部整行入口及占位样式已删除；设置与版本保留原行。Workbench 不恢复重复入口，仍复用同一个非模态锚定面板。

- Runtime 快照仍是运行状态唯一事实源，应用层保存的是展示和请求反馈，不建立第二张运行事实表。停止回执已受理不等于已停止；只有 Runtime 终态才清除旧反馈。本轮不改 Runtime、IPC、权限链或进程生命周期。

## 历史设计结论（2026-09-05，入口位置已被替代）

> 从本节至文末保留最初评审稿，包括当时的候选方案取舍、底部线框、状态矩阵及设计阶段授权边界；不代表当前入口要求。后续用户反馈已用标题栏搜索旁单图标替代底部整行，现行要求与实际验证以上方「当前方案与验收」为准。保留历史中对顶部方案的否决理由，不将其改写成当时已经选择顶部。

**后台运行是一种应用状态，不是与用户任务并列的产品模块。** 建议删除顶部「后台任务」导航及右侧 Workbench「后台任务」标签，以侧栏底部一个低优先级「后台运行」状态入口承接全局查看。只提供一个管理面板，列表、详情和停止在原位完成，不再打开第二个管理中心。

本方案现已获用户批准，实施范围仍限于以下减法设计。用户要求的「简单、简约、高端」在本方案中的含义：少一个一级概念、少一个重复管理面、默认少显示技术信息；可查看、可追溯、可接管的能力不减少。

## 问题诊断与边界

- problem_rewrite：界面把 Runtime 的全局归属升级为一级产品导航，并在 Workbench 再投影一个管理面；用户难以判断应该在哪管理。居中大浮层缺少圆角赋值，视觉上像硬矩形管理后台。
- constraints：只读调查代码，交付知识仓设计稿；不改 UI、CSS、运行时，不操作 5198，不重启用户应用，不进行 Git 提交。保留已完成的应用全局托管与前台隔离。
- root_cause_hypotheses：主要问题是信息架构映射错误，而非图标、间距或圆角单独失调。若删掉顶部入口但用户仍需在两个面板间选择，说明修正失败；若只补圆角而默认仍出现技术双栏，复杂度未下降。
- source_of_truth：本机 Runtime 的受管后台运行记录；所有入口与详情引用同一运行 ID，不建立 UI 私有任务表。用户委托的「任务」与受管 shell 运行不是同级对象。
- causal_chain：信息架构 → 唯一入口 → 渐进披露 → 浮层语义与 token → 交互和视觉验收。此次只定义这条链，不实施。
- success_checks：文档覆盖删除项、唯一入口、完整查看/停止流程、5×3 状态上下文矩阵、规范冲突、后续视觉验收清单。文档存在不等于实现通过。
- non_goals：不加运行中心首页、不加后台任务分类体系、不做系统进程管理器、不扫描接管外部服务、不重跑上一轮运行时验收、不用调整圆角代替产品设计。

## 依据与现状

## 删除、保留与默认隐藏

| 决策 | 内容 | 理由 |
|---|---|---|
| 删除 | 顶部「后台任务」一级导航及其大尺寸独立管理弹层 | 后台运行不是用户要进入的工作目的地 |
| 删除 | Workbench 的「后台任务」标签及完整管理视图 | 不在两个地方表达同一管理能力 |
| 保留 | 本机全局托管、来源、日志、真实监听观测、显式停止 | 简化表达，不削弱接管能力 |
| 保留 | 侧栏底部唯一「后台运行」入口 | 切换任务、无当前任务也能找到，优先级低于工作内容 |
| 默认隐藏 | 已结束列表、原始命令、工作目录、ID、退出码、stdout/stderr、Evidence 地址 | 这些属于排查详情，不属于第一眼状态 |
| 不新增 | 工具栏入口、Workbench 角标、常驻任务内后台卡片、全局停止按钮、独立历史页 | 防止用多个“快捷入口”恢复复杂度 |

入口总数预算：一个常驻低优先级入口；零一级导航；零 Workbench 管理标签；零新增管理页面。原工具执行回执继续作为证据，不再扩展为第二套实时列表或停止控件。

### 唯一管理入口

- 位置：现有侧栏底部应用区域，设置项之前。不是简单把原导航行搬下来：改为无选中页面态的轻量状态按钮，不参与页面路由，不改变主区内容。
- 名称：统一「后台运行 / Background runs」，避免与用户委托的任务、自动化任务混称。单条称「运行」，不用「线程」。
- 无活动：显示弱化的「后台运行」，无数字、无彩点、无额外空态卡。不彻底隐藏入口，避免用户无法找到刚结束的日志。
- 有活动：显示「后台运行 · 2」，数字仅计算运行中与停止中；状态信息不挤入顶栏。
- 失败：入口用静态提示图形及无障碍描述「有失败的运行」；不闪烁、不动画红点、不重复 toast。打开列表视为看过提示，失败记录仍保留，不把已读当作修复。
- 收窄/折叠侧栏：同一底部入口降为图标，有 tooltip 和完整 accessible name；不另加顶部替代按钮。若现有折叠方式未留底部插槽，实施前适配现存侧栏，不新造导航体系。
- 不按当前任务或当前工作区自动过滤。标题下简短注明「本机」，避免误认为跨设备。

### 为什么不选其他方案

- 只留 Workbench：它随任务上下文出现，无法清楚承接无当前任务的全局运行；为此扩大全局 Workbench 是更大的设计改造。
- 保留顶部但换小弹层：一级概念仍然存在，没解决主次问题。
- 完全隐藏，仅失败时出现：平时无法主动停止，历史日志发现性差。
- 新建全局状态栏/运行中心：为减少一个模块又引入一个模块。

### 第一层：运行列表

```text
╭────────────────────────────────╮
│ 后台运行                 本机  × │
│                                │
│ ● 预览服务             运行中  › │
│   网站改版 · web                 │
│ ● 文件监听             停止中  › │
│   数据整理 · scripts             │
│                                │
│ 最近结束（3）                 › │
╰────────────────────────────────╯
```

- 单列；第一行是短名称和文字状态，第二行是来源任务及工作区简称。名称优先使用已提供的 description，缺失时使用安全截断的命令摘要，不生成虚构用途。
- 不默认暴露端口、日志、ID、技术统计。不做每条套一张卡片。
- 初次打开按失败、活动、最近结束分组；打开期间避免轮询导致行跳动，结束项留在原位直至下次打开；停止确认时锁定运行 ID 而非行号。
- 已结束默认折叠；最多先展示最近 20 条，可在同面板加载更多已保留记录。不承诺重启后恢复内存历史；不是新增持久化需求。
- 列表缺数据时显示加载态；读取失败显示「暂时无法读取后台运行」与重试，不能显示「暂无」。已有快照可保留并标注更新失败，禁止据旧快照假报停止成功。

### 第二层：同一面板内的详情

```text
╭────────────────────────────────╮
│ ‹ 后台运行                   × │
│ 预览服务                运行中 │
│ 来源   网站改版 · web          │
│ 已运行 12 分钟                 │
│                                │
│ 监听   127.0.0.1:5173  [复制]  │
│ 仅表示 TCP 监听，不代表服务就绪 │
│                                │
│ › 日志                         │
│ › 技术信息                     │
│                        [停止…] │
╰────────────────────────────────╯
```

- 详情替换列表，不叠第二个窗口，不形成左右双栏；返回保留列表滚动与折叠状态。
- 来源可跳转到存在的用户任务；跳转先关闭面板。不依赖来源任务仍存在：删除后显示「来源任务已删除」，仍显示工作区与运行状态。
- 没有来源 ID 显示「来源未知」，不伪造归属；没有当前任务也完全可用。
- 监听只展示 Runtime 已观测的地址；未知显示「未观测到监听地址」，不是「服务不可用」。默认只复制，不将未知 TCP 协议擅自转成 HTTP 打开。
- 日志默认折叠；展开后先看最近输出，标明尾部截断及 stdout/stderr；无输出不是故障。用户向上滚动后不强制追尾，提供「回到最新」。结束后可查看已有 Evidence；缺失时明确不可用。
- 技术信息折叠后容纳完整命令、cwd、运行 ID、工具调用 ID、时间、退出码与 Evidence 引用；长内容换行或局部横滚，不撑宽面板。日志/命令可能有敏感信息，不做自动复制与外发。

## 完整交互与停止语义

1. 点击唯一入口：打开面板；再次点击、关闭按钮、Esc 或点击外部关闭。关闭只影响查看，不停止进程。
2. 点列表行：进入详情；浏览不改变当前任务，不自动跳转来源。
3. 点「停止…」：在详情内原位展开确认区域「停止预览服务？它可能仍被使用，停止不会撤销已写入的文件。」默认焦点在取消。所有运行都用一致的显式确认，不猜测是否重要。
4. 确认「停止运行」后禁用重复提交。请求未响应显示「正在请求停止」，Runtime 确认 stopping 后显示「停止中」；只有观测到终态才显示「已停止」。不做乐观终态。
5. 停止被拒绝/失败：保留真实状态，原位可读错误和重试；不清空列表。超时显示「尚未确认停止」，提供刷新，不添加不受控的强杀按钮。
6. 确认期间运行自行结束：更新为已结束，撤掉停止确认，不对其他运行发请求。关闭面板不取消已发送的停止请求；下次打开恢复 Runtime 状态。
7. 已结束运行只有日志/技术信息/来源操作；没有「重新运行」或「删除进程」按钮。重新运行涉及新的执行授权，不属于查看界面。
8. 用户明确选择运行后的停止与模型跨来源停止权限各守原边界；UI 不复用模型隐式“停止当前任务”语义。切换任务不改变已选运行 ID。

## 状态与上下文验收矩阵

两个独立轴：运行状态（无活动、运行中、停止中、失败、已结束）× 使用上下文（当前任务来源、其他任务来源、无当前任务）。下表 15 格是后续实现的命名验收场景，**不是已执行测试**。本轮只检查设计覆盖，不重跑已完成运行时验收。

| 状态 | 当前任务来源 | 其他任务来源 | 无当前任务 |
|---|---|---|---|
| 无活动 | E-C：底部无数量；空态不建议用户先创建任务 | E-O：当前任务无运行但别处有运行时不得误判全局为空；全局确实为空才显示空态 | E-N：入口可用；可展开已保留历史，无历史显示「暂无后台运行」 |
| 运行中 | R-C：列表显示来源；详情可确认停止，不另建任务内管理卡 | R-O：一样可见，来源明确；确认停止固定该 ID，不切任务 | R-N：从首页可查看和停止；不要求选中来源 |
| 停止中 | S-C：状态真实保留，禁止重复提交 | S-O：切换任务不重置停止中，不错误显示当前任务停止 | S-N：关闭再打开仍显示实际状态，未终态不报成功 |
| 失败 | F-C：列表显示失败及摘要；展开日志；不自动重试 | F-O：不把其他来源失败标成当前任务失败；来源可追溯 | F-N：入口静态提示可发现，读后提示可消隐，记录不删除 |
| 已结束 | D-C：默认归入最近结束；保留结果与日志，无停止动作 | D-O：离开来源仍可查；来源删除则降级文案 | D-N：无当前任务也能查看保留历史；重启无记录不宣称全部成功 |

额外边界：运行中×来源删除（不停止）；停止确认×自然退出（不误停）；读取失败×任意上下文（不假空态）；停止失败×任意上下文（不假终态）。这是呈现与交互验收，不重复进程树清理、端口释放和权限引擎的旧测试。

## 视觉规范与冲突处理

### 浮层形态

推荐底部入口锚定的紧凑非模态内容面板：优先向上展开，宽度建议 360px，窄窗为视口宽减 24px；最大高度为 480px 或可用视口高度减 24px，取较小值。边缘至少留 12px。内容内部滚动，标题与返回/关闭保持可达。不使用全屏遮罩、不挤占 Workbench、不铺满主区。

它含列表、详情、日志与确认，不是 `role=menu` 的动作菜单；语义应为有标题的非模态 dialog，不设置 `aria-modal=true`，不锁住整个工作界面。窄窗依旧同一面板，只调整位置和尺寸，不另造移动端大管理页。

**基座规范冲突须在实施前解决：** 设计语言 §11.3.1 要求所有浮层经过 Overlay，而现有基座 CSS 默认全屏模态遮罩。不能把它隐藏后继续谎称模态，也不能业务层私建浮层绕过准入。建议评审通过后在统一基座提供明确非模态锚定变体，集中处理定位、关闭、焦点和动效，并补对应治理检查。本稿不宣称该变体已经存在；如果实现评估无法保持该语义，应返回设计评审，不偷偷退回大模态。

### 圆角与实际 token 映射

代码依据：`apps/desktop/renderer/src/styles/tokens.css` 与 `styles/overlay.css`。

| 部位 | 已存在的 token / 基元 | 使用要求 |
|---|---|---|
| 浮层表面 | `--ui-surface-elevated`、`--glass-popover`、`--blur-popover` | 单层表面；支持透明时用现有玻璃表面，降级用 elevated，不叠加多层磨砂 |
| 浮层边界/阴影 | `--ui-border-subtle`、`--shadow-popover` | 1px 低对比边界，轻阴影，不发光 |
| 外层圆角 | 推荐现存 `--radius-xl`（16px） | 保留悬浮表面语义；不因名字方便直接把非模态当作 modal |
| 行与控件 | `--ui-radius-row`（8px）、`--ui-radius-control`（6px） | 行保持平整，hover 才出现背景，不全员胶囊 |
| 文字 | `--za-text`、`--za-text-faint`、现存 `--ui-font-*` | 名称高于元信息；长名称省略但可访问完整名称 |
| hover / focus | `--ui-surface-hover`、`--ui-focus-ring` | hover、键盘 focus 都可见；颜色不是状态唯一信息 |
| 动效 | `--za-motion-medium`、`--za-motion-fast`、`--za-ease-decelerate`、`--za-ease-accelerate`；现有 `motion-enter-*` / `motion-exit-*` | 统一基座定义，不在业务组件散写 animation |

圆角冲突：产品设计语言 §5.5 写 18px；Frost 规范要求 ≤16px；当前 `--radius-xl` 与 `--ui-radius-modal` 均为16px。**推荐本方案采用16px，并在批准后的规范同步中统一这处矛盾，而不是在此稿伪称全部规范已一致。** 不新增一次性18px，不扩大到全应用圆角重构。玻璃伪元素与表面继承同一圆角；滚动内容不得漏出直角。

深浅主题分别使用主题 token；浅色不整块发白，深色不黑洞化；降低透明度或不支持 blur 时用不透明 elevated 表面。失败使用现存错误语义色并配文字，不使用红底卡片；停止按钮平时中性，仅确认态强调破坏性。

动效只表达开关与状态变化：小于12px位移，无弹跳、扫光或持续旋转状态点；入场 medium、退场 fast。快速开关可打断，以最后一次用户意图为准；列表刷新不触发整面板重入。`prefers-reduced-motion` 下取消位移、不等待装饰性动画才能操作。准确时长由现有 token 统一，不新增业务硬编码。

### 无障碍与后续视觉验收

- 按钮有展开态与关联面板标识；面板有标题、关闭按钮；打开后焦点到标题或首个操作，关闭回到触发入口；若入口卸载则回退到合理的侧栏焦点。
- 非模态不建立模态焦点陷阱；Tab 顺序完整且可离开；Esc 优先取消正在编辑的确认状态，其次关闭面板。返回后保留合理焦点。
- 停止确认与停止结果用适度 live announcement；不把每次轮询日志全部读出。错误有可读文本，禁用态说明原因。
- 点击目标至少32px，主要列表行约48–56px，文字200%缩放后可增长；200%缩放/窄窗不能使停止、关闭被裁切。正文对比度目标4.5:1，焦点等非文本目标3:1。
- 后续必须分别截图检查浅色/深色 × 列表/详情/停止确认，额外检查窄窗、长名称、长日志、降低动态与透明度。六个主场景均需独立记录结果；截图生成或文字设计完成不等于通过。

**当前仅为文字与线框设计，没有运行新界面，也没有通过视觉验收。**
