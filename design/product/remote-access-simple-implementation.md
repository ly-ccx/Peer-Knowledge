# 简化远程接入：文件凭据与一次授权

创建时间：2026-09-14
最后更新：2026-09-14

状态：待实现的 A 级设计；用户已选择文件凭据优先，本文件补齐实现建议。不是上线声明。

## 1. 决策与范围

用户目标是在手机查看自己电脑里的任务，而不是配置身份基础设施。默认流程：电脑开启远程查看 → 手机扫码 → 电脑确认一次访问范围 → 后续自动连接。默认不注册，不填写 Gateway 或工作区 ID，不复制挑战 ID 与 Key，不管理钥匙串。服务地址由发行配置提供；自部署地址留在高级设置。工作区由本机选择器选定，不自动开放全部工作区。

本设计分两期，不能把“文件持久化”误认为“已经取消账号认证”：

- S1：用本地文件保存设备私钥，复用现有 Ed25519 握手与绑定 SQLite；旧登录/认领流程暂不变。
- S2：增加无账号的浏览器授权，扫码和本机确认替代登录认领；浏览器不获得电脑私钥。
- 暂不做远程执行、团队、IM、账号找回、无人登录常驻和跨机身份同步。首版仅任务查看；结果正文外发仍受本机授权控制。

本设计在上述范围替代历史 ADR 75 的账号必经、钥匙串依赖和手工认领体验（旧稿目前在本机尚未提交；本文件为独立完整的交付依据，不依赖旧稿随仓库分发）。其本机执行、主动 WSS、权限与 Evidence 边界继续有效。遵循 [产品对齐](peer-product-alignment.md) 与 [工程治理](../../knowledge/architecture/20-architecture-governance.md)。

## 2. 保持简单的信任模型

文件解决“记住身份”，本机首次确认解决“允许哪个浏览器访问”。单有 deviceId 或 paired=true 不能证明身份。

- 电脑保存 Ed25519 私钥；Gateway 只保存公钥、设备记录与授权元数据。
- 浏览器保存独立的可撤销会话 Cookie，不保存电脑私钥，不在 localStorage 放长期访问令牌。
- Gateway 是路由和会话校验方，不运行工具、不成为任务或 Evidence 真相。
- 本机对每次请求校验设备、浏览器授权、工作区、授权版本、有效期与当前连接；权限检查在读取前和结果外发前各执行一次。
- 请求继续经过 Runtime Projection、Tool Call、PermissionGrant、Evidence。不能新增浏览器直读 SQLite 或直调工具的捷径。

信任 Gateway 负责正确校验会话和路由；本期不声称端到端加密或防御已被攻陷的 Gateway。同一 OS 用户权限下的恶意程序可能读取文件，这是选择文件方案的明确代价。文件权限不是加密，base64 也不是加密。

## 3. S1 文件存储接口与格式

建议位置：应用 userDataPath 下的 remote-access/identity.json。不要放项目目录、Git、云盘或可导出的诊断包。现有 remote-binding.sqlite 保持唯一绑定来源，不把其字段复制进身份文件；现有 enabled 设置保持独立。

建议格式：schemaVersion=1、algorithm=Ed25519、seedBase64（32 字节 seed 的规范 base64）、createdAt。公钥从私钥派生，不维护第二份可漂移的公钥。文件内容不进入日志、Evidence、聊天或异常文本。

实现一个 identityStore Adapter，维持 loadSecret/saveSecret/deleteSecret 的小接口；实现中明确区分 missing、permission_denied、invalid、unsupported_version、io_error，不把读取失败当成不存在。setup 使用通用 identity 初始化，不能继续沿用“损坏就删除，下次生成”的语义。

写入要求：

1. POSIX 目录 0700、文件 0600；检查目录归属与符号链接，拒绝符号链接和非普通文件。
2. 同目录独占创建临时文件，写入、fsync、原子发布并同步目录。首次创建禁止覆盖竞态中别的实例已保存的身份。
3. 串行锁覆盖读取/生成/发布；失败后旧文件不变，重启可清理不含授权真相的临时文件。不能只靠 renderer 状态防并发。
4. 先成功持久化，再发起注册/握手，不能以未落盘的临时身份在线。
5. Windows 使用当前用户专属 ACL；不能把 chmod 成功当成 ACL 验证。未实现安全 ACL 的平台明确不支持，不静默回退宽权限文件。
6. 不支持的版本保留原文并停止；损坏文件不删除、不自动覆盖。UI 提供修复/重新授权入口，不展示密钥。

## 4. 启动与旧数据迁移

启动仅在 enabled=true 时触碰凭据：加载文件 → 加载绑定 → 挑战验签 → 恢复授权范围 → 确认在线。disabled 不触碰钥匙串或发网络请求。

| 文件状态 | 旧钥匙串 | 绑定 | 行为 |
|---|---|---|---|
| 有效 | 任意 | 有效 | 文件为准，不读钥匙串；正常恢复 |
| 有效 | 任意 | 无 | 保持同一私钥，走首次授权，不生成第二把 |
| 缺失 | 有效 | 有/无 | 显式迁移旧 seed；写入后回读并验证公钥/签名一致；再连接 |
| 缺失 | 不存在 | 无 | 生成一次并保存，然后首次授权 |
| 缺失 | 不存在 | 有 | 身份丢失，停止；要求明确重置并重新授权，不能拿新私钥配旧 deviceId |
| 缺失 | 拒绝或读取错误 | 任意 | 停止并显示迁移失败；不删除、不生成替代身份 |
| 损坏/权限错误/未知版本 | 任意 | 任意 | 停止并保留原件，不从钥匙串偷偷覆盖 |

迁移是一次性兼容入口，不是永久双写。保留旧钥匙串条目作为受控回退依据，本期不自动删除；文件后续轮换后不得回到旧私钥。已绑定用户迁移失败时仍能选择旧版运行，但只有公钥、绑定版本未变化才允许这种回退。不能把“missing”和“unreadable”混在一起。

## 5. S2 无账号首次授权协议

下面是新增协议建议，不是当前 API。协议类型必须进入共享 protocol，Gateway、Desktop、Web 同步版本协商；不修改旧接口语义去伪装兼容。

1. 未绑定电脑先持久化私钥，证明持有私钥，Gateway 分配 provisional deviceId。该状态无任务读取权限。电脑签名申请短期邀请。
2. 邀请含随机至少 256-bit 一次性秘密，建议有效期 5 分钟；Gateway 只存摘要。二维码 URL 用 fragment 携带秘密，Web 读取后立即清理地址，以 POST 交换；禁止查询参数、访问日志、Referer 或分析脚本泄漏。页面设置 no-store、no-referrer、严格 CSP。
3. 手机交换邀请后只得到 pending 请求，不得读任务。电脑收到待确认浏览器、时间、请求范围与双方一致的短校验码。浏览器名称不作为身份凭据。邀请被抢先使用可取消重建，不能自动批准。
4. 电脑显示访问范围并确认，签名批准 browserGrantId、deviceId、scope、expiresAt、grantVersion 和请求摘要。拒绝/超时不发会话；确认必须是实际本机用户操作，不能由远端消息替代。
5. Gateway 原子消费邀请并创建浏览器会话，只向原 pending 浏览器交付 Secure、HttpOnly、SameSite Cookie。默认建议 30 天；过期需重新授权，不做隐式无限续期。
6. 授权同时保存在本机浏览器授权表与 Gateway；本机确认持久化 ACK 前，Gateway 不放行。使用幂等 requestId，重复确认不会生成第二份授权。
7. 读取路由携带 browserGrantId 和版本。本机只信本地授权表；撤销或范围缩小时，即使结果已经生成，外发前仍需重新校验。

会话修改接口校验 Origin 和 CSRF；邀请交换限速且限制请求大小；所有未确认、过期、重放、错误设备请求返回明确拒绝，不泄漏设备信息。轮询 pending 时使用独立短期秘密，不仅凭可猜的请求 ID。

账号 ownerId 不能替换成全局 default。旧账号设备保持旧所有权，新增 browser grant 显式关联到设备，兼容路径各自校验身份；移除 OIDC/Dex 必须等旧用户迁移和兼容测试通过，不能本轮直接删除。新设备的设备级 principal 与旧 owner principal 使用不同类型，避免混淆。

## 6. 关闭、撤销与恢复

- 关闭远程查看：停止连接并拒绝读取，保留身份和授权；重新开启可恢复。离线明确显示，不能假装连接成功。
- 移除手机：本机先持久化撤销并递增 grantVersion，再通知 Gateway 使会话失效、终止流。未送达时本机仍拒绝旧授权；重连先同步撤销再接收读取。
- 手机登出：使当前浏览器会话失效，不删除电脑身份或其他手机。
- 重置身份：明确确认，先关闭接入、撤销全部授权和旧设备，随后生成新身份并重新授权。Gateway 不可达时旧服务端记录可能尚未撤销，必须说明风险，不能报告全局完成。
- 文件丢失：不恢复信任位；有绑定时进入身份丢失状态。复制 Git 仓库不会复制授权。另一台开发电脑应生成自己的身份，不拷贝生产私钥或绑定库。
- 文件被复制可能造成克隆身份；服务端单活连接策略只能减少冲突，不能消除被盗凭据风险。发现泄漏应撤销旧设备并轮换，不把账号找回列为本期能力。

## 7. 界面与实施位置

默认只呈现开启按钮、工作区选择、二维码/确认、已授权手机及移除、在线/离线/需重新授权。高级诊断可显示分类错误，但不能显示 seed、Cookie 或邀请秘密。连接失败必须结束“正在连接”状态。

建议修改顺序：

1. runtime-gateway 增加文件 identityStore 及存储/迁移测试；保留 keychain Adapter 仅用于迁移。修改 setup 的默认 Adapter 与错误语义。
2. 复用 runtime-node 的 remote-device-handshake、connector 和 binding-store，验证 S1 不改变线上协议。
3. protocol 增加邀请、pending approval、browser grant 和撤销版本类型；Gateway 增加持久化和 Web 会话校验；先完成集成测试再暴露 UI。
4. Desktop controller/IPC 返回脱敏授权状态；RemoteAccessPanel 隐藏手工配置；Web 实现扫码交换和任务查看。
5. 验证旧账号和新浏览器授权共存后，再单独评审旧登录退役。不要连带改动其他凭据模块。

## 8. 验收矩阵（待开发，不是通过记录）

S1 独立轴为文件状态 F={有效,缺失,损坏,拒绝,未知版本} × 绑定 B={有,无}，必须生成 10 个命名测试 identity-F-B。缺失的两格继续展开旧钥匙串 K={有效,不存在,拒绝,损坏}，产生 8 个 migration-B-K；期望以第 4 节为准，损坏旧条目也必须停止且保留。所有用例断言磁盘写入次数、公钥与是否拨号。

S2 独立轴为授权 G={pending,有效,撤销,过期} × 连接 C={在线,离线} × 范围 S={范围内,范围外}，生成 16 个 read-G-C-S；仅有效+在线+范围内允许读，其他全部拒绝。进一步每个允许读取场景在外发前分别注入撤销、过期、范围缩小、连接替换，必须拒绝外发。

平台 P={macOS,Linux,Windows} × 操作 O={新建,恢复,原子写失败,并发创建,权限不安全}，15 个 file-P-O 测试。未支持平台不得跳过后宣称跨平台完成；应明确拒绝并记录发布范围。

额外精确检查：邀请重放/过期/并发消费/错误设备/CSRF/未本机确认拒绝；撤销后旧 Cookie 不可用；Gateway 与 Desktop 重启后授权版本不倒退；迁移后公钥不变；日志和诊断无秘密；受影响旧协议测试继续通过。

真机验收：新安装与旧安装各走一次首次授权、冷启动、断网重连、撤销；桌面与手机浏览器可见状态一致。S1 全绿不代表 S2 完成。测试名是实现要求，不代表仓库已有这些测试。

## 9. 交付与回滚

S1 与 S2 分提交、分发布。S1 先小范围验证同身份迁移；S2 通过受控开关发布并保留旧路由。回滚 UI 不得回滚撤销版本或恢复被撤销的会话。出错先关闭远程读取，不绕过 TLS 验证、不扩大权限、不删除用户凭据“修复”。

当前进度、提交和接手命令见 [远程接入交接](../../playbook/remote-access-handoff.md)。
