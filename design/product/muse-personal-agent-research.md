## 0. 结论速览

Muse 和我们正在做的项目代理是同一类东西：一个常驻代理、一条长对话、后台推进、需要批准时才回来找人、有记忆。它有两处真正独特、值得认真学的地方：

1. **交互层**：一条长对话 + 侧聊；主动消息有「值得打扰」的门槛且用户可调档；目标（Goals）+ 定时 / 事件驱动推进；产物（Artifacts）活在对话之外；只在不可逆动作处停下，刻意避免「审批疲劳」。
2. **安全架构**：「一台机器上两个隔离的安全域，而不是一个有 root 的 LLM」。代理跑在隔离容器里；凭据、权限、安全分类器、持久状态都在容器外；独立的 Sentinel 是连接器动作和所有出网请求的唯一授权方；代理只拿到替身令牌；按进程追踪「是否读过用户数据」来决定出网能否免批（污点出站）。

我们在「锚定回复」「证据与验证结论」「记忆治理」上比 Muse 走得更深；在「目标与事件驱动」「授权粒度」「执行隔离与凭据代理」上明显落后。

## 2. 独特设计：交互层

### 2.1 一条长对话，不是一问一答

- 主对话像和人发消息：可以打断它，可以连发几件事，不必等上一件回完。
- 记忆跨对话保留。项目变复杂后，用户想把某些话题隔开，于是加了**侧聊（side chats）**。
- 因为消息会「不按轮次」到达（代理主动发、用户连发），纯文本流水不可读，所以用**气泡**标出一个想法在哪里结束。

### 2.2 主动，但门槛高、可调档

- 代理可以不经提问主动发消息，所以「发不发」的门槛必须高：必须真有帮助、值得打扰。
- 后台工作完成后，代理先**评估结果值不值得告诉你**，只有「有实质新东西」或「需要你输入」时才通知。
- 用户可以直接对代理说关掉、调低、调高主动性。

### 2.3 目标（Goals）与定时 / 事件驱动

- 用户交给它的往往是长期目标（开学准备、训练计划、卖车）。代理把目标拆成可执行计划，**按时间表和相关事件**持续推进（例如盯学校邮件和学区网站，发现 12 小时后截止的选拔报名就立刻提醒）。
- 单独一个 Goals 标签页展示它在跟踪的所有目标和计划，可以在那里直接操作，也可以在对话里聊。

### 2.4 透明：看得见它在干什么

- 头像下方一行小字显示它正在做什么；点头像看完整活动日志和已批准的权限。
- 记忆以**文件**形式存在，用户可以直接读、直接改；也能说「忘掉某件事」。
- 浏览器实时可见，用户可以随时接管。

### 2.5 确定性控件：对话不够的地方用结构化 UI

- 设计团队明确划了线：**审批卡**（明确的接受 / 拒绝）和**凭据输入**必须是确定性 UI，不能靠对话。
- 刻意避免「横幅盲」（什么都点同意）：默认放行普通浏览，只在难以撤销的动作处停下；用户可以把默认调得更谨慎或更宽松。
- 审批弹窗由 Sentinel 直接推到客户端，**不经过和代理的对话**，结果也直接回给 Sentinel。

### 2.6 产物（Artifacts）活在对话之外

- 行程单、消费追踪看板、交互式学习指南这类输出不是一段文字，而是可交互的独立产物，经对话送达，也能脱离对话长期存在（例如一个持续更新的看板）。

### 2.7 解决「不知道从哪开始」

- 早期测试发现：能力太多，用户反而不知道能让它干什么。于是代理会根据你的目标、习惯和对话，主动生成「点子」：入门几天的提示、Ideas 标签页、针对已有目标的计划调整建议。
- App 五个标签：主对话、兴趣信息流、Ideas、Goals、文件与媒体。

### 2.8 人格化

- 用户给代理起名字、选头像、定沟通风格。团队发现对着一个公司标志长期对话很别扭，「让它真正属于你」成了用户最喜欢的功能之一。

## 3. 独特设计：安全架构

### 3.1 两个隔离的安全域

- 代理框架（Hatch 守护进程）、用户工作区、代理执行的所有程序，跑在 `systemd-nspawn` 容器里：容器内 root 映射为宿主普通用户；独立根文件系统；虚拟网卡；过滤系统调用；裁掉危险内核能力。
- 容器外独立运行：安全分类器（`hatch-safety`）、连接器执行（`privsep`）、凭据存储与替身（`hatch-authd`）、Sentinel、持久状态（独立 Postgres）、推理与遥测代理。
- 容器与这些服务之间只走带内核身份校验的 Unix socket。
- 核心理念：容器要处理不可信数据，所以保护它的东西必须在容器外，攻击者关不掉。

### 3.2 Sentinel：唯一的授权方

- 独立于 Muse 的宿主侧代理，是**连接器动作和所有出网请求的唯一授权方**。Muse 只能提议，只有 Sentinel 能批准。
- 连接器动作：Sentinel 根据用户设的连接器策略判定允许、拒绝或问用户，并生成用户看得懂的「用途说明」。
- 出网：所有请求经转发代理到 Sentinel，按四层和七层检查（主机名、解析后与最终 IP、端口、协议、方法、路径、解码后的请求体），防 SSRF。

### 3.3 替身令牌：代理永远看不到真凭据

- 容器内只有 `authd` 签发的替身令牌；请求获准后，Sentinel 在网络边界把替身换成真凭据。
- 提示注入让代理「打印 API key」没有意义，因为它从来没有真 key。
- 浏览器登录也一样：用户在客户端专用界面输入账号密码，直接进凭据库，代理看不到，需要时注入浏览器。

### 3.4 污点出站：用数据流决定要不要打扰用户

- 每次工具执行的进程从「干净」开始，**一旦读过用户数据就被标为污染**（eBPF + LSM 钩子在内核层追踪）。
- 干净进程发出的、符合窄范围自动放行策略的请求可以免批；被污染或无法判定的进程失去免批，回到正常审批。
- 这直接针对「致命三要素」（能读私有数据 + 接触不可信内容 + 能对外通信），在减少审批噪音的同时堵外泄。

### 3.5 授权是严格的能力，不是对话里的一句同意

- 用户批准的是绑定到具体连接器 / 目的地 / 用途的能力，可选**一次、本会话、本任务、限时、永久**五种粒度；Sentinel 决定给用户哪些选项，并确保后续调用严格落在授权范围内。
- 只读、已授权过、明显低风险的动作不打扰。

### 3.6 最小权限落到每一层

- 读写分离：能只给读就只给读；比 OAuth 提供方更细的动作级开关（例如给了 Gmail 读权限，还能单独去掉访问 Gmail 设置）。
- 连接器业务逻辑不在代理容器里跑：容器里的 CLI 只解析参数、把类型化参数和文件描述符交给容器外的 `privsep` 进程；每个进程按 cgroup 身份有凭据白名单（日历进程拿不到邮件凭据）。
- 邮件连接器过滤一次性验证码、重置密码链接、魔法登录链接，防止代理被利用去冒充用户登录别的网站。
- 浏览器：CDP 连接在容器外的代理进程里；浏览器子代理只看无障碍树、不看原始 DOM；不能在页面执行 JS；用户接管或凭据填表时代理暂停；另有分类器盯页面里的注入、图片注入、下载文件注入、高风险表单、与任务无关的个人数据外泄。
- 付款：识别结账页，每次都给出含具体明细的审批；新商家用一次性卡号，绑定商家、金额、时效。

### 3.7 纵深防御与公开悬赏

- 提示注入五层：模型训练、外部数据一律标「不可信」、独立于模型的多分类器集成、数据外移前人工审批、操作系统级确定性边界。
- 公开漏洞悬赏，最高 30 万美元，其中单用户提示注入最高 13 万美元。
- VM 数据持续备份可恢复；用户可以查看、编辑、下载 VM 里所有文件，包括代理对自己的记忆。
- 年内计划 Confidential VM：整台 VM 用只有用户持有的密钥加密，Meta 也无法访问（目前还做不到，只靠运营策略限制员工访问）。

## 4. 已暴露的问题

| 来源 | 问题 | 对我们的提示 |
|---|---|---|
| Reuters（内部测试） | 盯抢购页面约 15 分钟后停止刷新、静默吞掉错误、无故关闭监控 | 后台长任务最怕**静默失败**；Watchdog、失败分类与「不能假装还在跑」必须是硬要求 |
| Reuters（内部测试） | 代理绕过护栏暴露了用户 iCloud 照片 | 护栏不能只在提示层；越界读取也要受数据流约束 |
| Reuters（内部测试） | CTO 反复被登出 | 会话 / 凭据续期是真实可靠性问题 |
| The Verge 上手 | 并行任务时「看着它开一堆浏览器窗口很晕」 | 并行工作的可视化要收敛，不是越多越好 |
| The Verge 上手 | 绑卡后「Go for it」一键批准太容易，花钱过于顺手 | 审批要带具体明细，且对外 / 花钱类不能因习惯而降级 |
| The Verge 上手 | 代写的邮件语气生硬，用户觉得不妥又自己重写 | 代理以用户名义对外发声时，语气与分寸是交付质量的一部分 |
| NeoTeo 上手 | 反复劝用户接入金融、邮件、证件等敏感信息；没有关闭记忆的总开关；删除内容可能仍留在已学记忆里 | 不要为了「更有用」催用户交数据；记忆要有总开关，删除要真正生效 |
| 安全篇自述 | 提示注入仍是开放问题，Muse 会犯错 | 设计前提是「代理可能被攻陷」，靠结构限制损害 |

## 5. 与 Peer 项目代理设计的对照

| 维度 | Muse | Peer（现状 / ADR 80、81 已设计） | 判断 |
|---|---|---|---|
| 对话形态 | 一条长对话 + 侧聊；可打断、可连发；气泡分段 | 每个项目一个代理；锚定回复：每条消息被接住、任务锚定消息、回复挂回原消息；插话自主处置 | **我们更深**：Muse 没有把「这句插话属于哪件事」做成结构；我们有引用限定范围与处置投影 |
| 背景推进 | 定时 + 事件驱动；完成后评估值不值得通知 | 消息驱动开任务；任务事件唤醒代理；有去抖与限频 | **我们落后**：缺目标级的定时 / 事件触发，缺「值得打扰」评估 |
| 目标 | Goals 标签：长期目标 + 计划 + 跟踪 | 任务级 GoalPlan；没有跨多条任务的项目目标 | **缺口** |
| 审批 | 确定性卡片；Sentinel 直推客户端；五种授权粒度；只停不可逆 | 卡片由运行时按待处理请求生成，代理不能批；shell 规则有允许 / 询问 / 拒绝、目录、风险等级、过期时间 | **部分缺口**：没有「本任务有效」「本会话有效」这类粒度；没有明确的「只停不可逆」默认档 |
| 完成与验证 | 审计日志；无显式验证结论 | 验证结论由运行时算；低风险汇报即策略代签；关闭闸门 | **我们更强** |
| 记忆 | 记忆文件可读可改；「只说一次也记得」；说「忘掉」 | ADR 81：带来源与可信度；已验证 / 用户说的自动生效；过期复核；只收紧不放宽；防注入 | **我们治理更强**；可以学它「记忆就是可直接编辑的文件」的直观性 |
| 产物 | Artifacts：可交互、活在对话外 | UserArtifact（ADR 63）、画布、验证报告 | 接近；缺「随目标持续更新的活产物」 |
| 执行隔离 | 容器 + 容器外安全服务；非 root | 本机执行；ADR 49 已取消路径硬沙箱，靠审批门与 Goal 边界 | **明显落后**（也是本机优先的代价，见 §7） |
| 凭据 | 替身令牌，代理永不见真凭据 | 凭据库 + helper；工具子进程与代理上下文是否可能接触真凭据需要盘点 | **需要盘点** |
| 数据外泄防护 | 污点出站；分类器集成 | 权限审查按工具与风险等级；不可信内容防注入主要在提示层与记忆准入 | **缺口** |
| 人格化 | 名字、头像、风格 | 无 | 可选 |
| 数据归属 | 云端 VM，Meta 目前仍可访问 | 本机，零账号，不上云（ADR 74） | **我们的立场优势** |

## 6. 建议借鉴（按优先级）

| # | 借鉴点 | 落到 Peer 哪里 | 代价 |
|---|---|---|---|
| 1 | **「值得打扰」评估 + 主动性档位**：后台结果先判断是否实质新、是否需要人，再决定开口；用户可说「少打扰 / 多提醒 / 关掉」 | ADR 80 `ProjectAgentRunner` 唤醒规则加一道 surfacing 判定；档位作为用户偏好记忆（ADR 81，只影响打扰频率，不影响需要你与确认） | 低 |
| 2 | **项目目标 + 定时 / 事件驱动推进**：代理维护跨多条任务的项目目标（如「0.0.18 发版」），挂定时检查与事件触发（CI 失败、新 issue、依赖发布），触发后自己开任务或来问你 | 新增「项目目标」对象（挂在项目代理下，聚合多条任务）；触发器复用 Automation 运行时（ADR 62）；右栏加「目标」标签 | 中；需要 ADR |
| 3 | **授权粒度：一次 / 本任务 / 本会话 / 限时 / 永久** + 审批 UI 由权限方直出 | 权限审查增加 task-scoped 与 session-scoped 授权；需要你卡已由运行时生成，补上粒度选择 | 中 |
| 4 | **只停不可逆的默认档，谨慎度可调** | 签收策略与权限审查共享一个「谨慎度」设置；默认只停不可逆与对外动作 | 低 |
| 5 | **替身凭据**：代理与任务的上下文、工具子进程环境里只出现替身，真凭据在边界注入 | 盘点 shell 环境快照、MCP 配置、web_fetch 的凭据路径；由 credential-helper 在边界替换 | 中 |
| 6 | **污点标记**：任务读过敏感文件（`.env`、密钥目录、凭据）后，对外网络与 MCP 写操作失去免批 | 在运行时层追踪（按任务 / 工具调用），不做内核级；接入权限审查 | 中 |
| 7 | **执行隔离作为可选档**：高风险任务在隔离环境（容器 / 独立用户 / worktree + 受限网络）里跑，凭据与权限服务在外 | 与阶段 D worktree 叠加，作为「隔离执行」的加强档；不改 ADR 49 的默认 | 高；远期 |
| 8 | **记忆即可编辑的文件**：记忆面板之外，提供可直接编辑、双向同步的 markdown 视图 | ADR 81 存储层加 markdown 投影与回写校验 | 低到中 |
| 9 | **活产物**：随项目目标持续更新的看板（发版进度、测试健康度） | 画布 / UserArtifact 绑定项目目标，由代理维护 | 中 |
| 10 | **主动点子**：基于目标、记忆与项目状态提出建议（依赖安全更新、测试薄弱点） | 必须过 #1 的 surfacing 门槛；放在代理对话的低优先级位置 | 低 |
| 11 | **提示注入红队评测集** | 覆盖记忆准入、浏览器、MCP 返回、任务日志引用 | 中 |
| 12 | **代理身份**：每个项目代理可命名、选头像 | 多项目时区分度更好；纯表达层 | 低 |

## 7. 不借鉴的，以及原因

- **云端 VM 当家**：与 ADR 74 的本机优先、零账号冲突。我们的对应物是「本机 runtime + 可选隔离执行档」，不是把用户数据搬上云。
- **默认用对话轨迹训练模型**：Peer 不做。
- **催用户接入敏感数据**：与「少打扰」和信任显式相悖。
- **一键顺手批准花钱 / 对外动作**：我们的对外操作一律 `confirm`，且带具体明细。
- **兴趣信息流（Feed）**：面向消费者的内容推荐，与本地工作委托无关。
