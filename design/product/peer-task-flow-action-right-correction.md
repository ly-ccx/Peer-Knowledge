## 0. 一句话结论

> **Peer 首页不是会话管理器，也不是 Goal 仓库；它是委托任务的行动权交接板。**  
> 用户原话是输入，Conversation 是载体，GoalPlan 是执行事实，首页只投影「下一步谁该动」。

本次纠偏否定的错误主轴：

- ❌「讨论是容器，Goal 是讨论的状态」
- ❌「先做讨论去重，再处理任务展示」
- ❌「用户发起的话 = 任务标题」

本次纠偏确认的正确主轴：

- ✅ **行动权在谁手里，下一步该谁做**
- ✅ 工作基本单位是**可托付、可推进、可交接、可验收的真实工作**
- ✅ 聊天只是表达意图和处理例外的通道，不是状态真源

## 1. 问题现场（为何必须纠偏）

### 1.1 用户可见症状

工作台同时出现：

1. **用户原话被当任务标题**  
   例：`这一段话废话太多了，你看看标题怎么精简一下`
2. **确认语被当当前目标**  
   例：`当前目标 · 好，就这么做`
3. **同一条工作被拆成两个并列入口**  
   上面「Peer 正在推进」有它，下面「最近讨论」还可能再出现它
4. **系统内部词直接露脸**  
   例：`GoalPlan 0 / 1 · Peer 正在推进`
5. **「最近讨论」用原话/命令输出当名字**  
   谁看了都迷糊：这是聊天记录，还是任务清单？

### 1.2 根因不是文案太长，而是主轴错了

| 错误理解 | 导致的产品行为 |
|---|---|
| 讨论是一等公民 | 首页并列「任务区 + 最近讨论」 |
| 用户消息 = 任务 | 原话直接上标题 |
| Goal 形成后讨论仍独立陈列 | 同一工作双入口、双心智 |
| 信息架构优先于行动权 | 关心「谁包含谁」，不关心「下一步谁该动」 |

这不是「标题精简」能治的表面问题，而是**任务流转方向被聊天线偷换**。

## 2. 否定错误主轴：讨论容器思维

### 2.1 被否决的模型

```text
讨论（容器）
├── 普通讨论
└── 执行状态 → GoalPlan
```

以及由此推出的「首页先按 conversationId 去重」——去重可以是投影副作用，**不是产品主轴**。

### 2.2 为什么错

1. **品类定义冲突**  
   总纲定义 Peer 是委托系统，不是聊天产品。基本单位是**一段可托付的工作**，不是一条消息。
2. **状态真源冲突**  
   聊天是介质；GoalPlan / Runner / Acceptance 才是执行与验收事实。
3. **用户问题冲突**  
   用户回家看首页，要问的是：  
   - 现在有什么需要我处理？  
   - Peer 正在推进什么？  
   - 有什么结果等我验收？  
   不是：最近聊了哪些会话。
4. **命名冲突**  
   容器思维会默认「用首条/末条用户消息命名」，必然产出原话标题。

### 2.3 允许保留的次要结论

以下说法**可以保留为实现细节**，但不得升格为产品主轴：

- 同一 `conversationId` 在首页只应出现一次投影（去重）
- Conversation 是 Task 的实现载体
- 无活跃行动权的弱意图可以落在「未构成委托」区

## 3. 正确主轴：行动权任务流

### 3.1 产品第一视觉层

与原型 `DESIGN.md` 一致：

```text
需要你处理 → Peer 正在推进 → 结果待验收
needs_you     peer_advancing    result_ready
```

工作台回答的唯一问题：

> **现在需要关注什么？下一步行动权在谁手里？**

### 3.2 任务流转方向（产品态）

```text
用户发起意图
  → 对齐（是否构成委托 / 目标与边界）
  → 形成计划
  → Peer 推进
  → 需要你时交回（决策 / 权限 / 阻塞）
  → Peer 再推进
  → 结果交回验收
  → 你验收通过
  → 进入历史 / 沉淀
```

对应行动权：

| 阶段 | actionRight | 用户心智 |
|---|---|---|
| 意图未构成委托 | （不进任务流） | 只是沟通 / 咨询 |
| 对齐 / 审批 / 权限 / 阻塞 | `needs_you` | 需要你处理 |
| 计划已确认、Runner 推进中 | `peer_advancing` | Peer 正在推进 |
| 完成但未验收 | `result_ready` | 结果待验收 |
| 暂停 | `paused` | 已暂停（任务抽屉可见） |
| 已验收 / 取消 / 失败 | `terminal` | 历史 |

### 3.3 关键分界（必须死记）

1. **用户原话 ≠ 任务**  
   原话是输入；任务身份在「委托成立」时生成。
2. **`completed` ≠ 历史**  
   未验收 → `result_ready`；已验收 → `terminal`。
3. **GoalPlan 形成 ≠ 讨论消失**  
   讨论作为沟通通道仍在任务内；**首页不再把同一工作当「最近讨论」并列陈列**。
4. **Conversation 不是并列任务实体**  
   用户心智是 Task；Conversation 是实现载体。

## 4. 对象关系（服务流转，不服务嵌套）

```text
Task（用户心智：这项工作）
  │  实现载体：Conversation
  │
  ├── 沟通：消息、确认、例外
  ├── 执行：GoalPlan / Run / Step
  ├── 证明：Evidence / Artifact
  └── 投影：首页 / 任务 / 历史 按行动权展示
```

纪律：

| 对象 | 角色 | 不是什么 |
|---|---|---|
| **Task** | 用户心智中的一项工作 | 不是消息，不是「讨论卡片」 |
| **Conversation** | Task 的实现载体与沟通现场 | 不是首页并列的第二任务源 |
| **GoalPlan** | 执行事实与进度来源 | 不是首页第二套任务列表 |
| **消息 / 用户原话** | 意图输入 | 不是标题真源 |
| **首页** | 行动权 read model | 不是会话列表，不是 Goal 仓库 |

一任务一投影：

> 同一 `conversationId`（或同一活跃 Task）在工作台三桶中**至多出现一次**。  
> 有活跃行动权时，只出现在对应行动权桶；不得再出现在「最近讨论」。

## 5. 生命周期：从意图到历史

### 5.1 状态机（产品语言）

```text
1. 意图
   用户说了一句话
   → 还不是任务，只是输入
   → 若只是咨询 / 闲聊：保持沟通，不进「正在推进」

2. 委托成立
   系统判断：这是可托付工作
   → 生成任务身份（Conversation 即 Task 载体）
   → 生成可读任务名（不是原话）
   → 进入对齐或计划

3. 对齐 / 待你处理
   actionRight = needs_you
   → 缺目标、缺边界、要审批、要权限、Runner 阻塞求助

4. Peer 推进
   actionRight = peer_advancing
   → 用户可以离开
   → 卡片显示：任务名 + 当前步骤 + 进度

5. 中途交回
   再次 needs_you
   → 决策 / 阻塞 / 权限
   → 处理完回到 peer_advancing

6. 结果待验收
   plan completed 且未验收
   → actionRight = result_ready
   → 不是历史，也不是“已完成可忘掉”

7. 验收通过
   → terminal
   → 离开工作台主轴，进入历史
```

### 5.2 三入口语义（与 workbench-flow 对齐）

| 入口 | 收什么 | 不收什么 |
|---|---|---|
| **工作台** | `needs_you` + `peer_advancing` + 未验收 `result_ready` | `terminal`；未构成委托的闲聊 |
| **任务抽屉** | 所有未结束（含 paused / 待验收清单） | 已验收 / 取消 / 失败 |
| **历史抽屉** | `terminal` | 未验收 completed；推进中 |

一句话：

- **工作台** = 现在要你管的（决策 + 盯推进 + 验收）
- **任务** = 所有未结束工作
- **历史** = 已结束且不再验收

## 6. 命名规则（服从任务流）

### 6.1 字段分工

| 展示位 | 取什么 | 绝不取什么 |
|---|---|---|
| 卡片主标题 | `plan.title`（稳定任务名） | 用户原话、`goal` 全文、最后一条消息、确认语 |
| 副行 | 当前步骤 / 下一步行动 | `GoalPlan 0/1` 等内部词 |
| 状态 | 行动权文案（需要你处理 / Peer 正在推进 / 结果待验收） | 内部 status 枚举直出 |
| 当前目标摘要 | 稳定目标契约（可截断） | 「好，就这么做」「认可」等确认语 |

### 6.2 标题生成时机

1. **委托成立时**生成一次稳定任务名  
2. 之后默认不变  
3. 只有目标本身变化时才改名  
4. 用户中途消息可更新**当前步骤**，不覆盖任务名  
5. 禁止用最后一条用户消息覆盖已确认标题  
6. 禁止把审批确认语、短回复（「好」「就这么做」「认可」）写成标题或当前目标

### 6.3 标题质量门槛

- 10～20 个汉字左右（或等价信息密度）
- 「动词 + 对象」优先  
- 去掉会话性表达：你看一下 / 这个有点问题 / 废话太多 / 测试一下  
- 禁止命令输出、路径碎片、tool log 当标题  
- 无法生成时降级为中性名（如「未命名任务」+ 短 id），**不要**回退到用户原话全文

### 6.4 反例 → 正例

| 错误标题 | 正确方向 |
|---|---|
| 这一段话废话太多了，你看看标题怎么精简一下 | 精简任务与讨论的展示标题 |
| 好，就这么做 | （不得作为标题或当前目标） |
| 测试一下 | 验证工作台任务投影 |
| `> tsc -p tsconfig.build.json ...` | 修复 task-overview 构建类型错误 |
| 认可 | （不得作为任务名） |

## 7. 首页投影规则

### 7.1 首页只做三桶（主轴）

```text
需要你处理
  任务名
  事由 / nextAction
  [去处理]

Peer 正在推进
  任务名
  当前步骤 · 进度
  （可进会话查看）

结果待验收
  任务名
  结果摘要
  [确认验收]  [查看结果]
```

不该再出现：

- 用户原话当任务名  
- `当前目标 · 好，就这么做`  
- 同一任务既在推进区又在「正在讨论」  
- `GoalPlan 0/1 · Peer 正在推进` 系统腔  
- 把「正在讨论 / 最近讨论」做成与三桶对等的主轴区块  
- 用已读历史或纯时间序会话墙填满讨论区

### 7.2 「正在讨论」如何处理（已定稿：方案 A + 未读）

**命名：** 首页该区块改叫 **「正在讨论」**（不再叫「最近讨论」）。  
「最近讨论」容易被理解成时间序会话墙；「正在讨论」表达的是**还有未读更新、值得回看的沟通**。

**目标态（纠偏后，产品已确认）：**

> 「正在讨论」是**次级入口**，只回答：有没有我还没看过的讨论更新。  
> 它不是任务主轴，也不与「需要你 / 正在推进 / 待验收」对等。

#### 收录条件（AND）

同时满足才可出现在「正在讨论」：

1. **有未读**：该 conversation 存在用户尚未读过的新内容（相对用户上次打开/已读水位）  
2. **无活跃行动权**：`actionRight` **不在**  
   `{ needs_you, peer_advancing, result_ready, paused }`  
   （即尚未构成委托，或委托已结束且不在工作台任务桶）  
3. **非纯历史闲聊**：已读且无新内容的会话 **不** 进此区（即使时间很近）

#### 明确排除

- 已进入任务桶的会话：**即使又有未读更新，也只留在任务桶**，不双开到「正在讨论」  
- 用户已读过、无新消息的会话  
- 终端态且已验收/已归档、仅适合进历史的会话  
- 把「最近 N 条会话」按时间无脑堆叠（旧「最近讨论」形态）

#### 产品选择（已确认 A）

| 方案 | 说明 | 状态 |
|---|---|---|
| **A. 次级未读入口「正在讨论」** | 主轴仅三桶；下方/折叠区展示未读且无任务投影的沟通；条数克制（建议 ≤3～6） | ✅ **已定稿** |
| **B. 首页移除讨论区** | 讨论只在侧栏/搜索/会话列表；首页纯行动权 | 备选；若 A 仍噪音过大再升 |

#### 卡片与交互纪律

- 标题：短摘要或「未命名沟通」，**禁止**用户原话全文 / 确认语 / 命令输出  
- 状态文案：可用「有未读」；不要假装成任务态（讨论中 ≠ 正在推进）  
- 主 CTA：进入会话阅读；**不**用「继续讨论 →」与任务桶抢主轴视觉  
- 读后行为：用户打开并读完后，该卡片应从「正在讨论」消失（水位更新）  
- 空态：无未读沟通时，整块可隐藏或显示极轻空态，**不要**用已读历史填满

### 7.3 去重是投影副作用

```text
同一 conversationId：
  有 needs_you / peer_advancing / result_ready / paused → 只出现在对应任务桶
  无活跃行动权 + 用户已关注 → 只出现在「关注的讨论」（读完也留；未读只打角标）
  无活跃行动权 + 未关注 + 有未读 → 可出现在「正在讨论」
  无活跃行动权 + 未关注 + 已读无新内容 → 首页不出现
  terminal（已验收/归档） → 离开工作台，进历史
```

去重规则服务于行动权，**不能**反过来定义产品。  
**一会话一投影**：任务桶优先；任务桶已占有的 conversation，永不并行出现在「正在讨论」或「关注的讨论」。

「关注的讨论」是用户手选的主区域轻列表，**不是**把「正在讨论」改名，也不是侧边栏置顶上首页。完整方案见 `design/product/followed-discussions.md`。

## 8. 卡片文案纪律

| 元素 | 目标态 | 禁止 |
|---|---|---|
| 主标题 | 稳定任务名 | 原话、确认语、命令 |
| 状态 chip | 正在执行 / 需要你 / 待验收 | 内部 enum |
| 进度 | `2 / 5` 或步骤名 | `GoalPlan 0 / 1` 字面量当主文案 |
| 副文案 | 当前步骤 or nextAction | 「当前目标 ·」+ 用户确认句 |
| 主按钮 | 去处理 / 确认验收 / 查看结果 | 空泛「继续讨论」抢主轴（任务桶内） |

推进中卡片示例：

```text
Peer 正在推进

重构首页任务流投影
当前：梳理行动权状态机
2 / 5
```

而不是：

```text
这一段话废话太多了…
当前目标 · 好，就这么做
GoalPlan 0 / 1 · Peer 正在推进
```

## 10. 验收标准（产品）

满足以下全部，才算纠偏落地：

1. 首页主轴只有行动权三桶（「正在讨论」若在，必须视觉与语义降级）  
2. 任意有活跃行动权的工作，不会同时出现在「正在讨论」  
3. 「正在讨论」只含**未读**且**无活跃行动权**的沟通；已读会话不占位  
4. 卡片主标题来自稳定任务名，不出现用户原话全文 / 确认语 / 命令输出  
5. 不出现「当前目标 · 好，就这么做」类过程句  
6. 不把 `GoalPlan` 内部计数当主文案  
7. `completed` 未验收只在待验收，不进历史  
8. 用户能在 3 秒内回答：现在谁该动、我要不要点进去；以及有没有未读讨论要回
