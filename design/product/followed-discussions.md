## 1. 一句话定义

> **关注的讨论**是用户亲手订阅的长期沟通线：读完也不消失，未构成委托时也不进任务桶。  
> 它不是侧边栏置顶，也不是首页未读提醒。

首页因此有三套互不替代的讨论相关能力：

| 能力 | 谁决定留下 | 回答的问题 | 读完之后 |
|---|---|---|---|
| **置顶会话** | 用户钉在侧边栏 | 常用对话怎么更快找到 | 还在侧边栏顶部 |
| **正在讨论** | 系统看未读水位 | 有没有我还没看过的沟通 | 必须离开首页 |
| **关注的讨论** | 用户声明「这条线还开着」 | 哪几条讨论我会反复回来 | 继续留在首页主区域的紧凑列表 |

---

## 2. 为什么要单独做

真实场景不是「最近聊过」，也不是「有一条未读」：

- 一条讨论会跨很多天反复回去（方案、取舍、设计对齐）。
- 它还没有变成可委托任务，所以不该进「需要你 / 正在推进 / 待验收」。
- 用户已经读过，所以也不该靠未读水位活着。
- 但用户仍希望回家时一眼看到它，而不是先翻侧边栏或搜索。

现有两套能力都答不对这句：

1. **置顶会话**只改变侧边栏排序。字段是 `pinnedAt` / `pinnedOrder`，入口在 `Sidebar`，首页投影不用它。
2. **正在讨论**已在纠偏文档 §7.2 定稿为「未读 + 无活跃行动权」。打开读完必须消失；禁止用已读历史填满。

如果把首页那块改名叫「置顶讨论」，或直接倒入全部 `pinnedAt`，会同时毁掉两件事：

- 用户以为这是手动钉选架，结果规则却按未读进出；
- 或首页重新变成会话墙（当前截图已是 172 条「已读」）。

所以新品类必须新开一层，名字用 **关注的讨论**。

## 3. 用词边界（必须写死）

首页已经在问「现在需要关注什么」。那边的「关注」是**系统判定的行动权**。  
这里的「关注」是**用户订阅**。两套词不能共用同一条投影。

| 说法 | 语义 | 能否混用 |
|---|---|---|
| 现在需要关注什么 | 系统：下一步行动权在谁手里 | 只用于三桶主轴 |
| 关注的讨论 | 用户：我 follow 的沟通线 | 只用于本方案 |
| 置顶 | 用户：把会话钉在列表上面 | 只用于侧边栏 / 搜索排序 |
| 正在讨论 | 系统：有未读且尚未构成委托 | 只用于未读入口 |

禁止对外文案：

- 「置顶讨论」——会让人以为复用侧边栏置顶。
- 「收藏」——太像以后再看的冷归档，不像还开着的线。
- 把「正在讨论」直接改名成本方案——数据语义完全相反。

英文内部标识建议：`followed discussion` / 字段 `followedAt`。  
不要用 `pinned`，避免和现有 `pinnedAt` 撞名。

## 4. 产品原则

1. **手选，不自动猜。** 最近活跃、置顶、未读，都不能自动变成关注。
2. **读完还在。** 关注区不消费 `lastReadAt`。未读只是角标，不是进出条件。
3. **条数极少。** 这是首页常驻视线，不是会话仓库。默认硬顶 **8** 条；首页只预览 **3** 条。
4. **进主区域，但轻一档。** 放在三桶下面的主视线里，方便回访；形态必须是紧凑列表，不得做成和三桶同级的大卡片墙。
5. **一会话一首页投影。** 同一 `conversationId` 不能同时出现在任务桶、正在讨论、关注的讨论。
6. **关注不是任务。** 关注本身不创造 GoalPlan，不改变行动权，不发系统通知。
7. **关注不是置顶。** 两者独立：可只置顶、只关注，或两者都开。互不隐含。

## 5. 生命周期

```text
普通讨论
  │ 用户点「关注讨论」
  ▼
关注的讨论（已读也留着；有未读只打角标）
  │
  ├─ 用户「取消关注」     → 立刻离开本区；不删会话
  ├─ 出现未读             → 仍留在本区，显示未读；不进「正在讨论」
  ├─ 升级为委托任务        → 离开本区，只出现在对应任务桶
  │                         followedAt 保留，任务结束后若仍无行动权则回到本区
  ├─ 归档 / 删除 / 终端验收 → 离开工作台；关注失效或不再投影
  └─ 超过硬顶              → 拒绝再关注，提示先取消一条
```

### 5.1 进入

同时满足：

- 用户显式执行「关注讨论」；
- 会话 `status = active`，未归档、未删除；
- 当前关注数 `< 8`。

不自动进入的情况：

- 侧边栏置顶；
- 打开过、标已读、发过消息；
- 搜索结果里点开；
- 刚创建的新会话。

### 5.2 留在本区

- 已读或未读都可以；
- 没有活跃行动权（`needs_you` / `peer_advancing` / `result_ready` / 工作台可见的 `paused` 任务）；
- 仍是 active 会话。

### 5.3 暂时退出（订阅仍在）

会话升级为工作台任务后，首页只走任务桶。  
`followedAt` **不清空**。等任务不再占用首页行动权（例如计划取消、回到普通讨论），若订阅还在，再回到关注区。

这样用户不用在「聊完一截任务」后重新关注。

### 5.4 永久退出

- 用户取消关注；
- 会话归档 / 删除；
- 任务已验收并进入历史（终端态）。此时即使曾关注，也不再回首页。

## 6. 与另外两层的互斥

同一 `conversationId` 的首页归属，按下面顺序取**第一个**：

```text
1. 有活跃行动权（needs_you / peer_advancing / result_ready / 工作台 paused）
     → 只进对应任务桶
2. 用户已关注（followedAt 有值）且仍是普通讨论
     → 只进「关注的讨论」
     → 若同时未读，只在本区打「未读」，不进「正在讨论」
3. 未关注 + 未读 + 无活跃行动权
     → 只进「正在讨论」
4. 其他
     → 首页不出现；回访靠侧边栏 / 搜索 / 任务抽屉
```

这是对纠偏文档 §7.3 的补充，不是推翻：

- 「正在讨论」仍然只收未读弱意图；
- 关注区是用户另开的长期入口；
- 两者都不得和任务桶双开。

## 7. 首页信息架构

首页分主区域和次级区，不要再把两套讨论都堆成大卡：

```text
主区域
  需要你
  Peer 正在推进
  结果待验收
  关注的讨论        ← 紧凑列表，读完还在；无关注则整块隐藏

次级区 / 侧栏
  正在讨论          ← 瘦未读条，读完消失；无未读则整块隐藏
  （推进摘要、工作区脉搏等背景信息）
```

「关注的讨论」进主区域，但必须比三桶更轻：

- 一行一条，不要和三桶同级大卡片墙；
- 首页最多预览 3 条；
- 不要用「172」这种仓库计数当主数字。无预览外的余数时，可不显示总数，或只显示「3 / 5」这种克制写法；
- 无关注时**整块隐藏**，不要空态墙，更不要用最近会话填满。

「正在讨论」必须留在次级区，而且要瘦：

- 最多预览 1～2 条未读瘦条，不要三张横卡；
- 无未读则整块隐藏，把次级区高度还给下面的内容。

### 7.1 关注列表结构

| 元素 | 取什么 | 不取什么 |
|---|---|---|
| 主标题 | 稳定讨论名 / 任务名 | 用户原话全文、确认语 |
| 副行 | 工作区名 · 相对时间 | `GoalPlan 0/1`、内部 status |
| 状态 | 有未读才显示「未读」 | 已读不必打「已读」徽章（已读是默认态） |
| 主操作 | 打开 | — |
| 次操作 | 取消关注 | 不要和「取消置顶」混成一个按钮 |

当前截图里每张卡都打「已读」，是旧「最近讨论墙」的味道。关注区不要复刻。

### 7.2 「查看全部」

只打开**已关注列表**（最多 8 条），不是全部会话、也不是任务抽屉里所有 `source === 'conversation'`。

现实现把讨论计数和任务页混在一起（截图「查看全部 166」），本方案禁止沿用。

### 7.3 入口

| 位置 | 动作 |
|---|---|
| 会话列表 / 会话页更多菜单 | 关注讨论 / 取消关注 |
| 首页关注卡 | 打开；悬停或菜单里取消关注 |
| 侧边栏置顶按钮 | **保持原义**，不改成关注 |

不在输入框、发送成功、读完时弹「要不要关注」。关注是冷操作，不是促销。

## 8. 数据与协议

### 8.1 为什么不能复用 `pinnedAt`

侧边栏置顶已经占用：

- `ConversationMeta.pinnedAt` / `pinnedOrder`
- `pinConversation` / `unpinConversation` / `reorderPinnedConversations`
- 置顶时会写 `updatedAt = now`（`conversation-store` 现状）

复用会有三个结构性问题：

1. **语义不同**：置顶服务「好找」，关注服务「这条线还开着」。用户完全可能置顶 20 条，但只关注 3 条。
2. **首页会再次变成墙**：把 `pinnedAt` 直接投影到首页，等于换皮的会话列表。
3. **污染未读**：现有 `pinConversation` 会刷新 `updatedAt`。若关注也这么写，会把已读会话重新打成未读，冲进「正在讨论」。

因此关注必须用**独立字段**。

### 8.2 会话元数据（建议）

在 `conversation-store` 增加：

```ts
followedAt?: string | null;     // ISO；有值 = 已关注
followedOrder?: number | null;  // 仅已关注集合内排序；越小越靠前
```

配套 API：

```ts
followConversation(id: string): ConversationMeta | null;
unfollowConversation(id: string): ConversationMeta | null;
reorderFollowedConversations(ids: readonly string[]): ConversationMeta[];
```

约束：

- `follow` / `unfollow` **不得**改 `updatedAt`，也不得改 `lastReadAt`。否则会误伤未读投影。
- 归档时同时清空 `followedAt` / `followedOrder`（与现有置顶清理一致）。
- 关注数达到 8 时，`follow` 失败并返回明确错误，而不是静默挤掉最旧的一条。长期讨论被系统偷偷拿掉，比点不上更糟。
- 不从现有 `pinnedAt` 做数据迁移。上线后关注区允许为空。

### 8.3 TaskOverview 投影

`projectConversation()` 今天只区分已读/未读，并把无计划会话标成 `actionRight: 'paused'`、`statusLabel: '已读' | '有未读'`。  
这套仍然只服务「正在讨论」和任务抽屉，**不要**把 `paused` 解释成关注。

建议在 `TaskOverviewItem` 增加只读投影字段：

```ts
readonly followed?: boolean;
readonly followedAt?: string;
```

聚合层（`task-overview-aggregator.mjs`）继续负责：

- 有 GoalPlan / 活跃行动权的会话：不进讨论区（已有 `projectedPlanConversationIds`）；
- 其余会话：带上 `followed` / `isUnread`，交给首页按 §6 分流。

首页 renderer **禁止**再写一套「最近 N 条会话」本地过滤来冒充关注区。  
今天 `GlobalWorkbenchPage` 仍把 `source === 'conversation'` 切前 3 条叫做「最近讨论」；`TaskOverviewPage` 标题已是「正在讨论」，却仍展示已读卡。这是实现债，见 §11。

## 9. 「正在讨论」必须先收口

本方案不靠改名救命。关注区要成立，未读入口必须先变回定稿：

| 规则 | 定稿 | 当前实现 |
|---|---|---|
| 区块名 | 正在讨论 | 工作台页已是；全局工作台仍写「最近讨论」 |
| 收录 | 未读 + 无活跃行动权 | `source === 'conversation'` 几乎全收 |
| 已读 | 离开 | 卡片打「已读」仍占位，计数可到三位数 |
| 查看全部 | 未读沟通列表 | 跳进任务页，数字接近全部会话 |
| 空态 | 整块隐藏 | 用已读历史填满 |

P0 先修这条，再做关注区。否则用户分不清「系统提醒」和「我订阅的线」。

## 10. 交互细则

### 10.1 关注

- 文案：「关注讨论」 / 「取消关注」。
- 已关注时菜单项切换为「取消关注」，不要再放一个置顶风格的大头针当唯一入口。
- 达到 8 条：toast / 内联提示「最多关注 8 条讨论，先取消一条再试」。

### 10.2 排序

- 默认按 `followedOrder`；用户可在关注列表里拖拽。
- 新关注插入到最前（order 比当前最小值更小），因为用户此刻就想看见它。
- 不要按 `updatedAt` 自动重排——长期讨论会被刚冒泡的闲聊挤下去。

### 10.3 未读角标

- 关注卡若 `isUnread`，只显示小「未读」，不要改成未读入口的主视觉。
- 打开并 `markRead` 后，角标消失，卡片还在。

### 10.4 升级为任务

- 用户在该讨论里创建 GoalPlan / 出现行动权：卡片从关注区移到对应任务桶。
- 任务桶不必展示「已关注」徽章，避免干扰行动权文案。
- 任务结束后若回到普通讨论且仍关注：卡片回到关注区。

### 10.5 通知

关注**不**新增系统通知。未读通知若已有通用会话通知，沿用；不要因为 follow 再推一次「你关注的讨论有更新」。

## 12. 落地顺序

### P0 — 先把未读入口做对

- 首页 / 全局工作台「正在讨论」只投影 `isUnread === true` 且无活跃行动权。
- 已读立即离开；无未读则隐藏整块。
- 「查看全部」不再把全部会话当讨论。
- 文案统一为「正在讨论」，去掉「最近讨论」。

完成标准：截图里那种三张「已读」卡 + 三位数总数，不再出现。

### P1 — 关注数据

- `followedAt` / `followedOrder` + follow/unfollow/reorder API。
- 不改 `updatedAt` / `lastReadAt`。
- 硬顶 8；归档清理字段。
- 会话菜单可关注 / 取消关注。
- **不上首页**也可以先做：侧边栏或会话页能声明订阅，便于自测。

### P2 — 首页关注区

- 主区域三桶之下增加「关注的讨论」紧凑列表；正在讨论留在次级区并改成瘦未读条。
- 预览 3 条；按 `followedOrder`。
- 与任务桶、正在讨论互斥（§6）。
- 查看全部 = 已关注列表。

### P3 — 打磨（可后置）

- 关注列表拖拽排序。
- 任务结束后自动回到关注区的回归测试。
- i18n：`sidebar` 的「置顶」保持不变；新增 `followDiscussion` / `unfollowDiscussion`。

不在本方案做：从置顶批量导入、跨设备云同步、关注分组、关注即通知。

## 13. 验收标准

1. 置顶 10 条会话，首页关注区仍为空（除非用户另做了关注）。
2. 关注 1 条已读讨论：它出现在「关注的讨论」，不出现在「正在讨论」，读完还在。
3. 该讨论产生未读：仍只在关注区，角标为「未读」，不在「正在讨论」双开。
4. 该讨论创建 GoalPlan 并进入推进/需要你/待验收：只出现在对应任务桶。
5. 取消计划回到普通讨论：若仍关注，回到关注区。
6. 取消关注：立即离开首页关注区，会话本身还在。
7. 第 9 次关注被拒绝，已有 8 条一条都不少。
8. 无关注、无未读时，首页只剩行动权三桶（或它们的空态），没有讨论墙。
9. 关注 / 取消关注不把该会话打成新的未读。
10. 侧边栏置顶按钮的文案和行为不变。

建议测试落点（代码仓）：

- `packages/conversation-store`：follow 字段、硬顶、不碰 `updatedAt`；
- `packages/protocol/src/task-overview.test.ts`：分流与互斥；
- `apps/desktop/electron/main/task-overview-aggregator.test.mjs`：聚合不把已关注已读丢进未读入口；
- 首页组件：有关注 / 仅未读 / 两者皆无 三种渲染。

## 14. 非目标

- 不把首页做成全部会话的第二侧边栏。
- 不把关注做成收藏夹或以后再看。
- 不引入「关注的任务」——任务已经有行动权三桶和任务抽屉。
- 不修改置顶的产品含义，不把 `pinnedAt` 改名为 follow。
- 不在本方案重做搜索面板；搜索仍可按置顶加权，与关注无关。
- 不因为关注就自动创建 GoalPlan。

## 15. 对既有真源的修正范围

纠偏文档 §7.2 仍然成立：「正在讨论 = 未读弱意图入口」。  
本方案只补充首页主区域的**可选轻列表**，以及次级区未读入口必须变瘦：

```text
首页
├── 主区域
│   ├── 行动权三桶        （主轴，系统判定）
│   └── 关注的讨论        （主区域轻列表，用户订阅；可为空）
└── 次级区 / 侧栏
    └── 正在讨论          （瘦未读条，系统未读；可为空）
```

若以后发现用户把大量「其实该变成任务」的线丢在关注区，正确疗法是引导升级为任务，而不是放宽关注上限、也不是把关注并回置顶。
