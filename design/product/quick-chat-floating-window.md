# 快速会话浮窗（Quick Chat）产品与交互方案

创建时间：2026-07-13
最后更新：2026-07-21
状态：Draft（待产品确认，未进入代码实现）

关联文档：

- `design/product/task-completion-system-notification.md`（任务完成系统通知：触发、去重、回流、权限）
- `design/product/status-bar-task-center.md`（状态栏任务中心：投影与未读）

## 一、方案摘要

为 Peer Agent Desktop 增加一个系统级的“快速会话浮窗”：

- 用户在任意应用、任意桌面界面按下 `⌘⇧N`，无需切回 Peer Agent 主窗口。
- 当前屏幕上方出现一个始终浮在其他普通窗口之上的轻量输入窗，并自动聚焦输入框。
- 浮窗内始终展示当前选择的工作区，用户可在发送前快速切换。
- 用户输入任务并发送后，Peer Agent 才在所选工作区创建新会话并开始执行。
- 默认发送成功后收起浮窗，让用户继续留在原来的应用；用户也可以选择“发送并打开”，进入 Peer Agent 主窗口查看完整过程。

一句话定义：

> Quick Chat 是 Peer Agent 的系统级任务入口，不是第二个主窗口，也不是主窗口内部的弹窗。

## 二、问题与目标

### 2.1 当前问题

现有的新建会话路径要求用户：

1. 切回 Peer Agent；
2. 确认或切换工作区；
3. 点击新建会话；
4. 将注意力移动到 Composer；
5. 输入并发送任务。

当用户正在浏览器、IDE、文档或即时通信工具里工作时，这条链路会打断当前上下文。真正需要的是一个类似 Spotlight / Raycast / Gemini 快速输入条的“随处唤起”入口。

### 2.2 产品目标

1. **随处可用**：无论当前前台应用是什么，都可以用统一快捷键召出。
2. **低打扰**：输入、发送后立即回到原任务，不强制切换到 Peer Agent 主窗口。
3. **工作区明确**：发送前能看见并切换目标工作区，避免任务落错目录。
4. **会话真实**：快速入口创建的仍是标准 Peer Agent 会话，可在主窗口继续查看、接管和追问。
5. **执行边界正确**：任务从发送开始就绑定选定工作区，之后不因主窗口切换工作区而漂移。

### 2.3 非目标

首版不做：

- 不在浮窗里完整复刻会话时间线、Goal 面板、Workbench 和设置页。
- 不把浮窗做成长期停靠的桌面小组件。
- 不支持同时打开多个快速浮窗。
- 不因选择浮窗工作区而切换主窗口当前工作区。
- 不在按下快捷键时立即创建空会话。
- 不首发语音输入；可保留后续能力位，但不放无功能图标。

## 三、产品命名

| 层级 | 命名 | 说明 |
| --- | --- | --- |
| 功能名 | 快速会话 / Quick Chat | 面向用户的统一名称 |
| 窗口名 | 快速会话浮窗 / Quick Chat Window | 独立、无边框的系统浮动窗口 |
| 紧凑态 | Quick Bar | 单行或少量多行输入状态 |
| 展开态 | Quick Compose | 在同一浮窗内展开的完整输入状态 |
| 入口动作 | 打开快速会话 | 菜单、设置和快捷键提示使用此文案 |

不使用“新建窗口”作为用户文案。用户的目标是快速发起任务，而不是管理一个新的应用窗口。

## 四、核心原则

### 4.1 独立窗口，不是应用内 Modal

浮窗必须由操作系统窗口承载，才能覆盖在浏览器、IDE 等其他应用上方。它与现有 `Overlay` 基座的关系是：

- 视觉、动效和无障碍语言遵循 Peer Frost；
- 但容器不是主窗口 DOM 内的 Modal，也没有整屏 backdrop；
- 它拥有独立焦点、独立显示/隐藏生命周期和系统级快捷键入口。

### 4.2 先选择上下文，再创建会话

`⌘⇧N` 只打开输入入口，不创建会话。只有用户提交非空内容时才：

1. 锁定浮窗选择的工作区；
2. 创建标准会话；
3. 发送首条用户消息；
4. 开始标准 Peer Agent 执行流程。

这样不会因为反复唤起、误触或按 `Esc` 产生空会话。

### 4.3 浮窗工作区与主窗口解耦

浮窗内的工作区选择是 `quickChatWorkspacePath`，只服务于当前快速任务：

- 不调用“切换主窗口活跃工作区”的交互语义；
- 不刷新主窗口当前会话列表；
- 不抢走主窗口正在查看的上下文；
- 发送链路必须显式携带所选 `workspacePath`，不能临时改全局工作区再改回来。

这是本功能最重要的边界。如果实现时通过修改全局 `activeWorkspace` 来发送，会导致主窗口跳变、并发任务归属错误和难以解释的竞态，因此不可接受。

## 五、入口与窗口行为

### 5.1 系统快捷键

- macOS：`⌘⇧N`
- Windows / Linux 对应设计：`Ctrl+Shift+N`
- 快捷键在 Peer Agent 已启动时全局有效，包括主窗口隐藏或失焦时。
- 默认快捷键为上述组合；首版同时提供“设置 > 快捷键”页面，允许用户修改并检查冲突。
- 如果快捷键被其他应用占用、注册失败：
  - 不静默失败；
  - 在 Peer Agent 主窗口显示一次非阻塞提示；
  - 菜单栏仍保留“打开快速会话”入口；
  - 设置页展示冲突状态和后续修改入口。

### 5.2 重复触发

浮窗是单例：

| 当前状态 | 再次按 `⌘⇧N` |
| --- | --- |
| 未显示 | 在当前屏幕显示并聚焦输入框 |
| 已显示但未聚焦 | 将浮窗置前并聚焦，保留内容 |
| 已显示且已聚焦 | 收起浮窗，保留未发送草稿 |
| 正在提交 | 不重复提交；只将状态置前展示 |

该行为让快捷键同时承担“召出 / 收起”，符合 Spotlight 类工具的肌肉记忆。

### 5.3 显示位置

- 出现在当前鼠标所在屏幕；若无法判断，则使用当前前台窗口所在屏幕。
- 水平居中，顶部位于可用屏幕高度约 `18%` 处，而不是绝对垂直居中。
- 必须避开菜单栏、刘海、安全区和 Dock。
- 从一个屏幕切到另一个屏幕后再次唤起，应迁移到当前屏幕，不记忆跨屏绝对坐标。
- 浮窗不是可自由拖拽的常驻工具，首版不提供位置持久化。

### 5.4 层级与桌面空间

- 显示期间高于普通应用窗口，但低于系统授权、安全输入、锁屏等系统级界面。
- macOS 应能在不同 Spaces 中随快捷键出现在当前 Space。
- 浮窗隐藏后不保留 always-on-top 占位，不出现在 Dock 独立应用列表中。
- 唤起会主动获取键盘焦点，这是用户按下快捷键后的明确意图；不同时拉起 Peer Agent 主窗口。

### 5.5 失焦与关闭

- `Esc`：
  1. 若工作区选择器等二级浮层已打开，先关闭二级浮层；
  2. 再按一次才收起 Quick Chat。
- 点击浮窗外部：默认收起，但保留草稿。
- 关闭/收起不等于清空；下次唤起恢复草稿和光标位置。
- 发送成功后清空草稿。
- 用户可通过输入区的清空动作显式丢弃草稿；不增加高噪声确认框。

## 六、信息架构与布局

### 6.1 紧凑态 Quick Bar

建议尺寸：

- 宽度：`720px`，小屏时为可用宽度减 `32px`；
- 最小高度：`88px`；
- 最大输入高度：约 `168px`，超出后输入区内部滚动；
- 外圆角：`24px`，不做完全胶囊，避免输入多行后形态失衡。

结构示意：

```text
┌──────────────────────────────────────────────────────────────────────┐
│  ◈  peer_agent / dev-0.0.1  ▾                         ↗  ⏎         │
│     交给 Peer Agent 一个任务…                                       │
└──────────────────────────────────────────────────────────────────────┘
      工作区选择器                 输入区            展开   发送
```

实际视觉不使用字符图标，统一使用 Peer Agent 线性 SVG 图标。

布局规则：

1. 第一视觉锚点是输入区，而不是品牌 Logo。
2. 工作区以紧凑 chip 常驻展示，不能藏进“更多”菜单。
3. 工作区名优先展示目录名；空间足够时附加 Git 分支作为次级信息。
4. 工作区过长时中部省略，hover / tooltip 展示完整绝对路径。
5. 发送按钮固定在右下或右侧稳定位置，不因输入行数变化跳动。
6. 展开按钮用于进入 Quick Compose，不直接切换主窗口。

### 6.2 展开态 Quick Compose

点击展开按钮后，仍在同一个浮窗中平滑扩展，而不是打开第二个窗口。

建议尺寸：

- 宽度：`720px`；
- 高度：`360px`，内容增长上限 `480px`；
- 保持相同顶部位置，向下展开，避免视觉锚点跳动。

结构示意：

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 快速会话                     peer_agent / dev-0.0.1 ▾          —    │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  交给 Peer Agent 一个任务…                                          │
│  支持多行输入                                                        │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│  + 添加上下文     Chat / Plan / Goal      本地访问级别 ▾            │
│                                         发送并打开   发送             │
└──────────────────────────────────────────────────────────────────────┘
```

展开态承载与主 Composer 一致的关键任务参数，但不完整复制主会话页面：

- 工作区；
- 模式：Chat / Plan / Goal；
- 本地访问级别；
- 文本与必要的上下文附件；
- “发送”和“发送并打开”。

Provider / 模型选择如当前产品由全局配置决定，首版不在 Quick Chat 重复暴露。只有当主 Composer 已把模型选择定义为每会话能力时，Quick Chat 才同步出现。

### 6.3 紧凑态与展开态的内容一致性

- 展开/收起不得丢失文本、选择区、工作区、模式或附件。
- 多行输入导致 Quick Bar 达到最大高度时，不自动进入展开态。
- 用户主动展开后，本次显隐周期记住展开态；发送成功后下次恢复紧凑态。
- 可选的长期偏好（“总以上次形态打开”）不进入首版。

## 七、工作区选择器

### 7.1 默认选择规则

每次打开 Quick Chat，按以下优先级选择工作区：

1. 上一次 Quick Chat 成功发送所使用的工作区，且该工作区仍存在；
2. Peer Agent 主窗口当前活跃工作区；
3. 最近使用的第一个有效工作区；
4. 若没有任何工作区，进入“需要工作区”空状态。

用户只打开选择器或切换后关闭浮窗，不更新“上一次成功发送的工作区”；避免误操作改变长期默认。

### 7.2 列表结构

```text
┌──────────────────────────────────────┐
│ 搜索工作区…                          │
├──────────────────────────────────────┤
│ ✓ peer_agent                dev-0.0.1│
│   peer-knowledge                  main│
│   demo-app                        main│
├──────────────────────────────────────┤
│ + 添加工作区…                       │
└──────────────────────────────────────┘
```

规则：

- 默认按最近使用排序；当前选择置顶。
- 每项展示工作区名、Git 分支和运行状态；有任务运行时使用低噪声运行点，不阻止选择。
- 工作区超过 6 个时展示搜索框；不超过 6 个时可直接列出。
- 键盘支持：`↑/↓` 移动，`Enter` 选择，`Esc` 关闭。
- “添加工作区…”调用系统目录选择器；完成后返回 Quick Chat 并自动选中新工作区。
- 切换工作区时保留当前输入文本。
- 如附件或引用明确依赖原工作区路径，切换前必须标示不兼容项，并让用户移除或返回；不能静默把越界路径发送给新工作区。

### 7.3 无工作区状态

没有可用工作区时：

```text
选择一个工作区后开始
Peer Agent 需要知道任务在哪个目录中执行。
[添加工作区]
```

- 输入区可见但发送按钮禁用。
- 不能自动把任务落到用户主目录或文件系统根目录。
- 添加成功后恢复输入焦点，已输入草稿不丢失。

## 八、输入与发送

### 8.1 键盘规则

| 操作 | 行为 |
| --- | --- |
| `Enter` | 发送并收起 |
| `Shift+Enter` | 换行 |
| `⌘Enter` | 发送并在主窗口打开该会话 |
| `⌘⇧N` | 召出 / 收起 Quick Chat |
| `Esc` | 关闭二级浮层；再次按下收起窗口 |
| `⌘K` | 打开工作区选择器（建议，若与现有快捷键不冲突） |

在中文输入法组合输入期间，`Enter` 只确认候选，不得误发送。

### 8.2 发送前校验

必须同时满足：

- 有有效工作区；
- 输入文本或附件至少一项非空；
- 当前 Provider 配置可用；
- 未处于重复提交状态。

校验失败时在浮窗内就地说明，不打开主窗口替用户“解释错误”。

### 8.3 两种发送动作

#### 发送

1. 发送按钮进入 loading，禁止重复提交；
2. 后端确认“会话已创建且首条消息已接受”；
3. 浮窗短暂显示“已交给 Peer Agent”；
4. 约 `240–320ms` 后收起并清空草稿；
5. 执行继续在后台进行；
6. 主窗口对应工作区的会话列表通过现有广播机制出现新会话。

“已发送”不能等同于“模型已完成”。这里只确认任务已经可靠进入执行链路。

#### 发送并打开

1. 走同一创建和发送链路；
2. 显示 Peer Agent 主窗口；
3. 将主窗口切换到该会话所属工作区并选中新会话；
4. 关闭 Quick Chat；
5. 主窗口继续展示流式过程。

只有这条显式动作允许改变主窗口当前工作区，因为用户明确选择了进入该会话。

### 8.4 提交失败

- 浮窗保持显示，草稿、工作区和参数全部保留。
- 发送按钮恢复可用。
- 输入区下方展示可行动错误：
  - Provider 不可用 → “打开设置”；
  - 工作区已移除 → “重新选择工作区”；
  - 本地权限不足 → 调整访问级别或查看授权；
  - 其他网络/运行时错误 → “重试”。
- 如果会话已创建但消息未被接受，系统必须保证重试不产生重复空会话；实现上需要幂等提交标识。

## 九、会话与主窗口协同

### 9.1 会话归属

Quick Chat 创建的会话与主窗口创建的会话完全相同：

- 出现在所选工作区的活跃会话列表；
- 支持重命名、归档、置顶、删除；
- 支持 Chat / Plan / Goal 的标准状态和证据链；
- 后台运行时，工作区显示运行状态；
- 用户之后切换工作区不会中止它。

建议会话来源记录为内部可观测字段 `origin: quick-chat`，用于埋点和排障；首版不在会话列表增加可见徽标，避免视觉噪声。

### 9.2 后台任务反馈

发送成功后 Quick Chat 默认收起，任务继续在后台运行。用户再次唤起 Quick Chat 时，可以在输入框下方的任务卡区域查看相关任务，不必先进入主窗口：

- 任务完成时沿用应用内状态，并更新输入框下方任务卡；
- 若主窗口隐藏（或用户不在对应会话前台），由主进程按《任务完成系统通知方案》弹出系统通知（完成 / 失败 / 等待用户）；Quick Chat **不单独**调用系统通知 API；
- 通知去重、`attentionVersion`、点击回流与阅读回执与状态栏任务中心共用同一套规则，详见 `design/product/task-completion-system-notification.md`；
- 通知是否启用应遵循系统权限和产品通知设置；权限关闭时仍可靠任务卡与主窗口感知状态；
- 任务卡只提供轻量状态与必要操作，不复制完整会话过程。

### 9.3 主窗口正在运行其他任务

- 不阻止新建快速会话。
- 不自动中止或切换已有运行任务。
- 工作区列表可显示运行点，帮助用户感知并发，但不把它设计成警告。
- 每个任务从提交时快照自己的工作区和执行上下文。

### 9.4 输入框下方任务卡

#### 9.4.1 产品定位与位置

任务卡是 Quick Chat 的轻量任务接续区，**固定显示在 Quick Chat 输入框下方**。它解决“发起指令后马上需要选择、确认或补充信息”时的快速回流问题，不把浮窗扩展成完整任务中心。

布局顺序固定为：工作区与模式信息、输入框、任务卡区域、底部发送动作。任务卡区域没有符合展示条件的任务时完全收起，不保留空白占位；出现任务后浮窗向下扩展，输入框位置不跳动。

```text
┌──────────────────────────────────────────────────────────────┐
│ 工作区 / 模式                                                │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ 交给 Peer Agent 一个任务…                               │ │
│ └──────────────────────────────────────────────────────────┘ │
│ 任务卡（输入框下方，按需出现）                               │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ 需要你选择 · 选择发布环境              [日常] [预发] […] │ │
│ └──────────────────────────────────────────────────────────┘ │
│                                          发送  发送并打开    │
└──────────────────────────────────────────────────────────────┘
```

#### 9.4.2 展示范围与排序

任务卡消费与状态栏任务中心相同的任务快照，但采用更窄的展示范围：

1. 当前 Quick Chat 本次发送后首次进入 `waiting_user` 的任务立即展示；
2. 用户再次唤起 Quick Chat 时，展示全部“需要你处理”的任务，不限于 Quick Chat 创建的任务；
3. 没有待处理任务时，可展示最近更新的 1 个执行中任务或 1 个完成未读任务，用于确认指令已被接收及快速查看结果；
4. 已读且已完成、失败已处理、已取消的任务不展示；排队中任务仅在它是本次刚提交任务时短暂展示；
5. 首版同时只展开 1 张任务卡，其余折叠为“还有 N 个任务”，点击或使用方向键打开任务选择器。

排序遵循：`等待用户 > 失败未读 > 执行中 > 完成未读 > 本次排队中`；同级按 `updatedAt` 倒序。用户手动选择任务后保持该选择，直到任务终结、退出展示范围或本次浮窗收起。

#### 9.4.3 卡片内容与任务选择

单张任务卡最多包含：状态图标、任务标题、工作区名、更新时间或耗时、简短状态说明、最多 3 个主选项，以及“更多”或“在主窗口打开”。标题最多两行，执行日志和长篇结果不在卡片中展开。

任务选择支持：

- 点击“还有 N 个任务”打开紧凑选择器；
- `↑/↓` 切换任务或选项，`Enter` 执行当前主操作，`Esc` 先关闭选择器而不是收起 Quick Chat；
- 切换任务只改变当前卡片，不改变主窗口活跃工作区；
- 任务状态发生变化时保留用户焦点；当前选项失效则给出说明并刷新可用动作，不误触相邻选项。

#### 9.4.4 快捷操作

首版支持可逆、低风险且参数明确的必要操作：

| 场景 | 卡片内快捷操作 | 完成后的反馈 |
| --- | --- | --- |
| 单选确认 | 直接选择系统提供的有限选项 | 提交后显示“已选择”，任务恢复执行 |
| 简短补充信息 | 聚焦输入框，以“回复任务：{title}”模式提交 | 清除回复模式并显示“已提交” |
| 权限请求 | 允许一次、拒绝 | 明确作用范围，提交后恢复执行或结束等待 |
| 普通确认 | 继续、返回修改 | 二次点击防抖，显示最新状态 |
| 完成未读 | 查看摘要、在主窗口打开 | 成功展示对应最新结果后标记该版本已读 |
| 失败未读 | 查看原因、在主窗口处理 | 仅查看不自动重试 |

当卡片要求文本输入时，复用上方输入框，不在卡片内再造第二个输入框。输入框进入任务回复模式后必须显示任务标题和退出按钮，避免用户误以为正在发起新会话。

#### 9.4.5 安全边界

Quick Chat 不执行以下高风险或复杂操作：永久删除、覆盖不可恢复数据、线上发布、批量授权、凭证输入、金额操作、范围不明确的系统权限提升，以及需要审阅长差异或多步骤表单的确认。这些动作统一显示风险摘要和“在主窗口处理”，深链到对应任务。

卡片内操作还必须满足：

- 服务端或运行时提供结构化动作与幂等 `actionId`，客户端不根据自然语言猜测按钮；
- 操作前展示对象、作用范围和关键后果；一次性授权不得被表述为永久授权；
- 提交中禁用重复点击，失败后保留原选择并提供重试或回主窗口；
- 任务状态过期时拒绝旧动作并刷新卡片；
- 快捷操作不能绕过 Goal/Plan 的审批、证据或权限规则。

#### 9.4.6 已读与跨入口一致性

Quick Chat、状态栏任务中心和主窗口共享同一个 `taskId`、状态归一、`attentionVersion` 与阅读回执：

- 只把卡片显示出来不等于已读；
- 用户展开并看到完整等待请求、失败原因或完成摘要后，才确认对应版本已读；
- 执行快捷操作意味着用户已处理该请求，可同时确认该请求版本已读；
- 在任一入口处理后，其他入口实时移除未读标记并刷新动作；
- 若任务在其他入口已恢复执行，Quick Chat 不再保留可提交的旧按钮；
- 深链成功后由主窗口按实际展示内容确认已读，Quick Chat 不提前清除。

## 十、状态机

```text
Hidden
  └─ shortcut → Ready

Ready
  ├─ open workspace picker → ChoosingWorkspace
  ├─ expand → Expanded
  ├─ dismiss → Hidden (draft retained)
  └─ submit → Submitting

ChoosingWorkspace
  ├─ choose → Ready / Expanded
  └─ Esc → previous state

Expanded
  ├─ collapse → Ready
  ├─ dismiss → Hidden (draft retained)
  └─ submit → Submitting

Submitting
  ├─ accepted + send → Accepted → Hidden
  ├─ accepted + open → OpeningMainWindow → Hidden
  └─ failed → Error

Error
  ├─ retry → Submitting
  ├─ edit → Ready / Expanded
  └─ dismiss → Hidden (draft retained)
```

关键约束：`Submitting` 状态下不得因重复快捷键、双击发送或窗口失焦触发第二次提交。

## 十一、视觉方案

### 11.1 方向

遵循 Peer Frost 的“高端、简约、克制、强大”：

- 冷调半透明表面；
- 细边界和柔和大圆角；
- 低对比层次，Accent 只用于焦点、选中和可执行动作；
- 不照搬示例图的大面积蓝色背景；示例只参考“悬浮、聚焦、随处唤起”的产品形态；
- 不把浮窗做成发光胶囊或高饱和 AI 玩具。

### 11.2 表面与层级

- 使用独立窗口透明背景 + 内层 Peer Frost surface。
- 推荐使用 `floating` 级玻璃参数，而不是 sidebar 的 `chrome` 级参数。
- 单层玻璃：窗口根容器负责 blur，内部工作区菜单使用不透明度更高的 surface，避免多层 blur 叠加发灰。
- 1px 冷钢边界；默认阴影柔和，获得焦点时只轻微提升边界和阴影，不做强光晕。
- 系统不支持透明或用户启用 reduced transparency 时，降级为高不透明度实体 surface，文字对比度不受影响。

### 11.3 动效

- 出现：`opacity 0→1` + `translateY(-6px→0)` + 轻微 scale，时长约 `160–190ms`。
- 收起：反向动效，时长约 `120–150ms`。
- 紧凑态展开：窗口高度与内容 opacity 协同过渡，`180–220ms`。
- 位移不超过 `12px`，不使用弹簧抖动。
- `prefers-reduced-motion` 下取消位移和缩放，仅保留极短淡入淡出。

## 十二、可访问性与国际化

- 显示后输入框自动获得焦点，屏幕阅读器读出“快速会话，工作区：{name}”。
- 工作区按钮使用 `aria-haspopup="listbox"`，列表项用明确 selected 状态。
- 所有纯图标按钮都有 `aria-label` 和 Tooltip。
- 焦点顺序：工作区 → 输入区 → 参数 → 展开/收起 → 发送并打开 → 发送。
- 焦点不得逃逸到透明窗口区域；收起后焦点返回此前的前台应用。
- 中文 placeholder：“交给 Peer Agent 一个任务…”
- 英文 placeholder：“Give Peer Agent a task…”
- 快捷键展示按平台转换，不在 Windows 显示 macOS 符号。
- 文字、工作区名和错误信息必须支持动态宽度与截断，不以固定中文字数布局。

## 十三、隐私与安全

- 浮窗内容可能覆盖在其他应用上方，但不能默认读取当前前台应用内容。
- “添加上下文”只能来自用户显式选择、粘贴或系统已授权的能力。
- 不自动抓取剪贴板；可以在用户粘贴时正常处理。
- 发送时清晰展示工作区和本地访问级别，二者都属于权限边界。
- 若用户选择的附件位于工作区外，沿用主 Composer 的访问授权与提示机制，不新增旁路。
- 锁屏、系统安全输入和退出登录时必须隐藏浮窗并清除敏感渲染内容。

## 十五、验收场景

### A. 随处召出

- Peer Agent 已启动但主窗口被其他应用覆盖。
- 在浏览器中按 `⌘⇧N`。
- 当前屏幕顶部出现 Quick Chat，输入框获得焦点；主窗口不被拉到前台。

### B. 工作区不串扰

- 主窗口正在查看工作区 A。
- Quick Chat 选择工作区 B 并发送。
- 会话创建在 B，执行上下文为 B；主窗口仍停留在 A。
- 只有点击“发送并打开”时，主窗口才切到 B 和新会话。

### C. 不产生空会话

- 连续打开、收起 Quick Chat 三次，不输入、不发送。
- A、B 两个工作区的会话列表都没有新增记录。

### D. 草稿恢复

- 输入多行任务后点击浮窗外部。
- 再次按 `⌘⇧N`。
- 文本、光标位置、所选工作区与展开状态按规则恢复。

### E. 并发运行

- 工作区 A 已有任务运行。
- Quick Chat 在工作区 B 新建任务。
- A 的任务不中止，B 的任务正常启动，两个工作区都能显示各自运行状态。

### F. 防止重复提交

- 在网络较慢时双击发送并重复按 `Enter`。
- 系统只创建一个会话、只发送一条首消息。

### G. 失败可恢复

- 模拟 Provider 不可用或发送失败。
- 浮窗不关闭，草稿和工作区不丢失，展示原因和可执行的重试/设置入口。

### H. 多屏与 Space

- 鼠标位于副屏，在该屏的任意应用按快捷键。
- 浮窗出现在副屏安全区域；切到另一个 Space 再唤起时出现在当前 Space。

### I. 输入法与键盘

- 使用中文输入法输入并按 `Enter` 选词。
- 不触发发送；组合输入结束后再次按 `Enter` 才发送。
- 工作区列表可完全用键盘完成选择和关闭。

## 十六、观测指标

首版建议记录匿名产品事件，不记录用户输入内容或路径全文：

- `quick_chat_opened`：入口、平台、是否注册成功；
- `quick_chat_workspace_changed`：只记录是否切换，不记录路径；
- `quick_chat_submitted`：模式、是否发送并打开、从打开到提交耗时；
- `quick_chat_dismissed`：是否有草稿；
- `quick_chat_submit_failed`：归一化错误类型；
- `quick_chat_open_main_window`：用户是否需要进入完整会话。

核心判断指标：

- 从快捷键到成功提交的中位耗时；
- 打开后成功提交率；
- 工作区切换率；
- “发送并打开”占比；
- 快捷键注册失败率；
- 重复/空会话异常率（目标为 0）。

## 十八、快捷键设置页

### 18.1 定位与入口

在现有“设置”左侧导航新增一级分区“快捷键”，与通用、模型、能力等设置并列；设置搜索输入“快捷键”“Quick Chat”或具体动作名时可直达对应项。Quick Chat 注册失败提示中的“修改快捷键”也直接打开本页并定位“打开快速会话”。

页面承担三件事：查看当前绑定、修改绑定、解释绑定是否真正可用。它不是只服务 Quick Chat 的临时弹窗，而是后续统一承载应用内与全局快捷键的设置页。

### 18.2 信息架构

页面顶部依次包含：

1. 标题“快捷键”与说明“自定义 Peer Agent 的键盘操作”；
2. 搜索框，按动作名、按键组合和作用域过滤；
3. 状态筛选：全部、冲突、已修改；
4. “恢复全部默认”按钮，仅在存在自定义项时可用。

列表按作用域分组：

| 分组 | 示例动作 | 作用域说明 |
| --- | --- | --- |
| 全局 | 打开快速会话 | Peer Agent 在后台时也响应，必须经过系统注册 |
| 应用内 | 新建会话、打开设置 | 仅 Peer Agent 聚焦时响应 |
| 编辑器 | 发送消息、插入换行 | 仅输入区聚焦时响应，可受输入法状态约束 |

每一行固定展示：动作名称、用途说明、作用域标签、当前按键、状态，以及行尾更多菜单。状态不能只用颜色表达，必须同时有图标和文字。首版至少纳入“打开快速会话”，即使其他动作暂不可修改，也应以只读方式展示，避免用户误以为全局快捷键与应用菜单快捷键是一套机制。

### 18.3 查看与修改

点击按键胶囊或行菜单“修改”后，原位进入录制态：

- 胶囊文案变为“请按下新的快捷键…”，页面其余可修改项暂时禁用；
- 监听下一组完整组合键，不要求用户逐个选择修饰键；
- `Esc` 取消，`Backspace` / `Delete` 清除非必填绑定；全局“打开快速会话”不允许留空时应明确说明；
- 单独按修饰键不完成录制；修饰键释放后仍未形成有效组合则继续等待；
- 拒绝仅字母、数字、方向键等高误触组合，要求至少一个平台修饰键；
- macOS 使用符号展示，Windows / Linux 使用文本展示，但持久化为平台无关的规范键值；
- 录制期间屏蔽该组合原有动作，避免按下旧快捷键时召出浮窗或执行菜单命令；
- 中文等输入法处于组合输入时不截获字符键，避免把选词操作误录为快捷键。

录制到合法组合后立即运行冲突检测，但不立刻覆盖旧绑定。行内出现“应用”和“取消”：只有点击“应用”或按 `Enter` 才提交；提交成功后显示短暂的“已保存”反馈，并立即使用新快捷键。离开页面时若仍有未应用录制，应询问“放弃更改 / 继续编辑”。

行菜单还提供：

- “恢复默认快捷键”：只恢复当前动作；
- “清除快捷键”：仅对允许无绑定的动作显示；
- “查看冲突项”：存在应用内冲突时定位另一动作。

“恢复全部默认”必须二次确认，确认文案说明受影响的自定义项数量；执行后逐项重新注册，不能假定默认组合一定可用。

### 18.4 冲突模型与处理

“系统冲突”不能被表达成一个绝对、静态的布尔值。页面需要区分以下结果：

| 级别 | 状态 | 判定来源 | 是否允许应用 | 用户处理 |
| --- | --- | --- | --- | --- |
| 阻断 | 应用内重复 | 与 Peer Agent 另一动作的规范组合及重叠作用域相同 | 否 | 更改当前项，或跳转修改冲突项 |
| 阻断 | 系统保留 | 命中操作系统明确不可覆盖或产品维护的保留组合表 | 否 | 显示系统用途并要求换键 |
| 阻断 | 全局注册失败 | Electron / OS 对候选组合的真实注册返回失败，常见于其他应用已占用 | 否 | 保留旧绑定，建议换键并允许重试 |
| 警告 | 常见系统快捷键 | 命中系统或常见应用的已知组合，但平台允许注册 | 是，需再次确认 | 展示可能覆盖的用途，提供“仍要使用” |
| 正常 | 可用 | 未发现重复且全局注册成功 | 是 | 显示“可用” |
| 中性 | 无法预先确认 | 非全局作用域，或平台无法判断其他应用动态占用 | 是 | 说明仅能在实际作用域内验证 |

检测顺序为：格式合法性 → Peer Agent 内部重复 → 系统保留/常见清单 → 候选全局注册。候选注册成功后才原子替换旧绑定：先确保新组合可注册，再释放旧组合并持久化；任一步失败都回滚到旧绑定，避免用户同时失去新旧入口。

对“被其他应用占用”，系统通常只能知道注册失败，未必能可靠识别占用者。因此文案使用“此快捷键已被系统或其他应用占用”，不得虚构具体应用名。设置页打开时和应用启动时都要刷新真实注册状态；休眠恢复、系统快捷键设置变化后也应重新校验。

### 18.5 关键状态与反馈

- **默认且可用**：显示当前组合与“全局 · 可用”。
- **已修改且可用**：显示“已修改”标记，可恢复默认。
- **旧绑定仍生效**：编辑候选冲突时，清楚提示“尚未应用，当前仍使用 ⌘⇧N”。
- **启动时注册失败**：行标红为“不可用”，页面顶部出现汇总提示；主窗口首次非阻塞提醒并提供直达入口。
- **保存时失败**：录制态保留，错误贴近按键胶囊展示，不关闭设置页、不丢候选组合。
- **默认值也冲突**：恢复动作完成但标记“默认快捷键不可用”，引导继续修改，而不是显示成功假象。
- **无搜索结果**：显示清空搜索与筛选的操作。
- **重启后**：自定义绑定与状态持久化；以本次真实注册结果为准更新状态。

### 18.6 无障碍与键盘操作

- 列表使用语义化分组和可聚焦按钮；屏幕阅读器读出“动作、当前组合、作用域、状态”。
- 录制开始和检测结果通过 `aria-live` 宣告，例如“正在录制，按 Escape 取消”“与打开设置冲突”。
- 不要求鼠标完成任何流程：`Tab` 定位、`Enter` 开始/应用、`Esc` 取消、菜单可用方向键操作。
- 按键胶囊保持可见焦点环；冲突不只依赖红/黄色。
- 提供文本化组合，如 `Command + Shift + N`，避免屏幕阅读器只读出符号。

### 18.7 验收场景

1. **正常改键**：将“打开快速会话”从 `⌘⇧N` 改为可用组合，保存反馈出现；Peer Agent 失焦时旧组合不再触发，新组合可召出浮窗。
2. **应用内重复**：录入已绑定到重叠作用域动作的组合，展示双方动作名且“应用”不可用。
3. **系统保留**：录入平台保留组合，解释系统用途并阻止应用。
4. **常见组合警告**：录入可注册但高风险的系统常用组合，用户必须明确“仍要使用”后才可应用。
5. **真实注册失败**：模拟组合被另一应用占用；页面显示“系统或其他应用占用”，旧快捷键继续有效，候选可修改和重试。
6. **原子回滚**：模拟新组合注册成功但持久化失败；系统恢复旧绑定且显示失败，不出现两个组合都失效。
7. **恢复单项默认**：只恢复目标动作并重新检测，其他自定义项不变。
8. **恢复全部默认**：二次确认显示数量；恢复后逐项呈现真实状态，包括默认值冲突。
9. **录制取消**：录制过程中按 `Esc`，原绑定和状态不变。
10. **输入法与纯修饰键**：中文选词、单按 `Shift` 均不产生错误绑定。
11. **启动校验**：重启应用后自定义绑定保留；若环境变化导致注册失败，状态及时变为不可用并给出入口。
12. **无障碍**：仅用键盘完成搜索、录制、处理冲突和恢复默认，读屏可获得全部状态。

### 18.8 首版范围调整

快捷键设置页及“打开快速会话”的修改能力调整为 P0，不再列为后续项。P0 必须包含：统一列表、录制态、单项/全部恢复默认、应用内重复检测、系统保留与常见组合提示、真实全局注册结果、失败回滚、启动校验和无障碍反馈。批量导入/导出快捷键方案、按工作区覆盖和多套预设不进入首版。

## 十九、与现有产品架构的衔接结论

结合 Peer Agent 当前产品模型，本方案需要坚持以下衔接方式：

1. 复用现有工作区列表、添加工作区、会话创建和消息发送能力，但为 Quick Chat 提供显式 `workspacePath` 的提交语义。
2. 复用标准会话与后台运行投影，确保 Quick Chat 会话能被主窗口发现和接管。
3. 不复用 Sidebar 的“切换活跃工作区”动作来模拟 Quick Chat 选择。
4. 复用主 Composer 的模式、访问级别、附件校验和输入法处理规则，避免形成两套权限语义。
5. 视觉复用 Peer Frost token 和动效原则；窗口生命周期由 Electron 主进程治理，不能仅用 renderer overlay 模拟。

该边界能让 Quick Chat 真正成为“更短的入口”，而不是一套旁路会话系统。
