## 2. 六条体验不变量

1. **意图有回执。** 用户输入后知道是否已被接收；排队、生成、执行、验证各有事实依据。
2. **行动有归属。** 用户首先知道是否需要自己做决定；过程数量不是价值指标。
3. **执行有边界。** 当前项目、动作对象与授权范围可辨；界面只投影本机受治理事实。
4. **结果有依据。** 结论、产物与 Evidence 分别可达；未验证的部分直接说明。
5. **中断可恢复。** 草稿、未决决定、失败现场和已产生的结果尽量保留，恢复不能重复副作用。
6. **注意力归用户。** 不抢输入、不抢焦点、不抢滚动；可自主推进的工作安静进行，例外才打扰。

每个新界面应能回答：用户想完成什么、下一步谁动、依据是什么、失败后怎么继续。不能回答时，先修正信息结构。

## 3. Frost 的识别度

沿用“清晨冰面上的工具集”：中性冷灰底面、石墨文字与主操作、少量冰湖青印记、连续曲线、安静的状态反馈。温度来自语言、排版和对人的尊重。

| 元素 | 必须 | 避免 |
|---|---|---|
| 主阅读面 | 稳定实色，文字与结论优先 | 长消息毛玻璃、逐字模糊、不断闪光 |
| 外壳与临时浮层 | 按角色使用玻璃；有实色降级 | 整窗透明、嵌套 blur、靠透明度区分权限 |
| 主要操作 | 石墨填充，高对比文字；一个局部决定一个主操作 | Azure 大色块 CTA、所有按钮都主色 |
| Azure | 少量定位或状态印记，单屏不超过 3 个主要强调落点 | 把每个链接、图标、边框都当品牌广告 |
| 形状 | 8 / 12 / 16 三档连续曲线；特殊几何按用途 | 任意大圆角、每个组件独立调曲率 |
| 图标 | 共享 `PeerIcon` 或已有 SVG 组件 | 字符箭头、emoji、图标字体、CSS 拼图标 |
| 引用 | 淡底、小型预览、来源和原文定位 | 装饰左竖线、大胶囊、无法回原文 |

标准 Frost 之外的已注册主题继续可用，但不改变主操作、焦点、行动权和证据的语义。不要为借鉴项目引入第二套主题或 `--cds-*` token。

## 4. Token 与几何契约

### 4.1 单一实现来源

优先消费现有 `--ui-*` 的字体、圆角、焦点、选择与表面语义；颜色与材质继续使用 Frost 正名 `--chrome-* / --paper-* / --control-* / --graphite-* / --azure-* / --state-* / --glass-*`。间距使用 `--space-*`。

现有 `--za-motion-* / --za-ease-* / --za-code-font-size` 是仍在使用的共享接口，可以继续消费。旧 `--ink-* / --cinnabar-* / --surface-vellum-*` 不向新组件扩散。组件不得复制一组数值后另起设计系统；新需求先扩展既有语义 token，再在一个位置落值。

以下是研究时的代码快照，便于选型，不是要求把数值重新写入组件：

| 角色 | 当前接口 | 标准字号 / 尺寸 |
|---|---|---|
| 元信息 / 控件 / 正文 | `--ui-font-meta / control / body` | 12 / 13 / 14 px，使用 rem 随字号偏好缩放 |
| 长正文 / 紧凑标题 | `--ui-font-body-lg / heading-sm / heading-md / heading-lg` | 15 / 16 / 20 / 26 px |
| 正文行高 | `--ui-line-body` | 1.68 |
| 紧凑控件 / 普通控件与行 | `--ui-radius-control-compact / control / row` | 8 / 12 / 12 px |
| 分组 / 浮层 / 消息 / 输入框 | 对应 `--ui-radius-panel / modal / message / composer` | 16 px |
| 连续曲率 | `--control-corner / --surface-corner` | `superellipse(1.4)`；不支持时保留普通圆角 |
| 阅读列最大宽度 | `--chat-content-max` | `clamp(740px, 64vw, 1080px)`，同时受可用容器宽度约束 |
| 间距节奏 | `--space-1/2/3/4/5/6/8/10/16` | 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 64 px |

页面级主标题沿用已批准的至少 30 px 层级；紧凑任务标题、弹层标题、组标题按自己的语义层级处理，不把所有标题放大。全产品标题与正文统一 sans，代码用 mono。旧 `--font-serif-zh` 当前是 sans 兼容别名，不再要求宋体标题。

### 4.2 密度与可点击区域

- 设置页沿用共享 `SettingsGroup`、行网格与选择器；常规选择器沿用约 38 px 高、输入区和详情使用紧凑密度。放大文字时允许控件增高。
- 图标视觉尺寸通常为 16–20 px；点击区与视觉图标分开计算。Peer 普通独立按钮以至少 32×32 CSS px 为默认目标，触控主操作建议至少 44×44。
- 紧凑控件不得为了密度牺牲可达性。一般指针目标至少满足 24×24 CSS px，例外需符合 WCAG 的间距、行内或等价入口条件。[W3C 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- 长模型名、路径、英文文案应自然换行或有完整查看入口。关键决定的对象、风险和作用范围不能只剩省略号。

32/44 是 Peer 的设计目标，不是把 WCAG 的最低要求改写成这两个数字。

## 5. 边界、表面和排版

采用**一层主要分组边界**：外组建立归属，内部优先使用留白、标题带、细分隔和表面差。独立可编辑字段、代码块、可执行预览和键盘焦点允许有必要的边界。这是对上游“单闭合边框”的修订，不能为了去框删除可操作线索或焦点。

边框、背景或字重切换不得改变控件占位。可预留透明边框或用 outline/inset 表达；不强制把全部 border 换成 shadow。细边界用于组织内容，不能承担唯一的关键状态区分。

阴影按现有语义使用：`--shadow-card*` 只用于需要抬升的内容卡，`--shadow-popover` 用于浮层，`--shadow-drag` 用于拖动，输入框沿用 `--shadow-composer`。普通设置组和回复正文不自行发光。token 中已有白色与主题例外不等于允许组件硬编码纯白/纯黑。

文字通过字号、字重、行距、间距形成层级，低对比只用于非关键装饰。普通文本至少 4.5:1，大文本按 WCAG 定义至少 3:1；不能把 14 px 普通说明当“大文本”。[W3C 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

主机器人回复的身份行与首段组成一个视觉组：头像消费 `--space-8`（32 px），名称使用 `--ui-font-body`（14 px 随字号偏好缩放）及可读的主文字色，头像与名称、身份行与首段各使用 `--space-2`（8 px）。长名自然换行。消息别名锚点、空正文载体等非内容节点不得叠加段落间距；保留原消息定位身份与真实流式载体，不以删除引用目标换取紧凑。

识别控件和状态所必需的非文字线索，与相邻颜色至少 3:1；装饰分隔线不必都达到这个值。焦点可见性不能用“发丝细边”削弱。[W3C 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

## 6. 信息结构与组件契约

默认主区是当前项目代理的对话；任务由代理开出，用户按需进入任务现场。机器人列表表达跨项目行动权。高级配置、过程、原始参数和诊断逐层展开。

| 组件 | 默认表达 | 必须补齐的行为 |
|---|---|---|
| 按钮 | 动词 + 对象；图标按钮有可访问名称 | hover、pressed、focus-visible、disabled、busy；防止重复提交 |
| 选择器 | 当前实际值、稳定 caret 位置 | 搜索/无结果、键盘、选中、关闭后恢复焦点、保存失败 |
| 设置行 | 名称 → 说明 → 当前值/操作 | 作用范围、加载和保存状态；失败保留用户输入 |
| Composer | 一份草稿、引用/附件、当前模型、发送/停止 | IME、排队回执、失败恢复、稳定操作位置 |
| 过程行 | 可读的正在做什么、当前状态 | 有真实事件才显示；用户可以收起 |
| 决策卡 | 为什么需要你、将影响什么、具体动作 | 范围、待定/提交中/已决定/失效；运行时结果回执 |
| 结果交还 | 做成什么、验证结论、剩余限制 | 原任务、产物、Evidence 按需到达；不伪造完成 |
| 预览/抽屉 | 当前对象和来源 | 返回原现场、键盘关闭、焦点恢复、窄窗降级 |

状态至少评估 default、hover、pressed、focus、selected、disabled、busy、empty、loading、error、stale/recovery；不适用的状态注明理由，不造无意义界面。组件契约同时写清受控值、事件顺序、错误、焦点、键盘、减少动效和宿主边界。

所有已配置模型的单选／多选统一使用输入框提炼的 [标准模型选择器](model-picker.md)。`ModelPicker`／已有原生宿主内的 `ModelSelectionPanel` 是唯一模型列表交互实现；作用范围、准入、保存与恢复由原调用方负责，不再使用通用下拉或独立清单重建模型选择。

## 7. 自适应与无障碍

按组件容器的实际可用空间决定折叠，不把窗口宽度作为唯一依据：先压缩装饰与元信息，再换行，再把辅栏转为可关闭覆盖层。发送、停止、需要你决定的入口和错误恢复不能被压没。不得通过缩小字体解决所有窄窗问题。

文本放大到 200% 的设计目标是内容与功能仍可使用；长表格/代码可有局部滚动，普通页面不产生根级横向溢出。当前是否已达标必须以发布验证记录为准。[W3C 1.4.4](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)

所有主操作可经键盘完成；hover 才出现的操作也要能经 focus-within 或菜单发现。强制颜色模式保留系统边界；减少透明度与关闭玻璃时采用实色；减少动效时语义、终态、焦点和操作能力完整。

## 8. 开发与演进

新功能、修复、重构、原型都按[开发执行规程](../../playbook/product-experience-development.md)和[开发共识](../architecture/00-engineering-philosophy.md)工作：先写本次体验契约，复用共享部件，做内容/diff 审阅并执行与改动相称的隔离行为/交互/视觉验证；完整产品回归留到最终发布候选。纯文档/指令修改只审内容、差异与一致性。候选实现、行为验证、已有状态恢复及安装版验收分别报告，用户不承担试错验收。

这是 C 级规范与开发指令变更；文中的权限、Evidence、输入与恢复要求重申已有边界，不新增协议、运行时状态或存储。后续实现若需改变这些边界，升级分级并先更新对应 ADR。

存量逐步收敛，触及一处就处理该路径的偏差，不发起无范围的全产品重写。例外必须记录适用组件、原因、替代体验、退出条件及对应代码/设计位置，不能只写“特殊处理”。

研究依据及采用/拒绝原因见 [open-claude-ui 精读记录](../../design/product/open-claude-ui-study.md)。规范修改必须同步关联契约和开发入口；自动检查覆盖到哪里如实说明，人工条款不能宣称已被 CI 强制。

## 9. 标准化 UI 体系的组成与状态责任

以下是同一套 Frost 的角色分层，不是新建一套组件库。现有实现优先；没有共享 Module 时，先在本次路径收敛语义，重复需求成立后再提取有深度的 Interface。

| 层 | 角色 / 现有基础 | 统一责任 |
|---|---|---|
| 基础 | tokens、主题注册、PeerIcon/SVG、字体/间距/几何/材质/焦点 | 语义数值单一来源；主题覆盖不改变状态与行动权；静态/实色/强制颜色可用 |
| 原语 | button/link、input/textarea、Checkbox/Switch、Dropdown、slider、tooltip/menu | 名称、值、事件顺序、适用状态、键盘、禁用原因与错误；图标尺寸和点击区分开 |
| 组合部件 | SettingsGroup/行、Composer、搜索/选择器、标签/分段、消息/附件/引用、列表/图表 | 同一角色同一状态语义；编辑、选择、阅读与恢复由明确责任方保留 |
| 交互容器 | Overlay/Drawer、锚定层、Workbench、分栏/预览、独立 Quick Chat 窗口 | 命名、来源与目标、modal 边界、焦点/滚动、关闭/反向/卸载与窄窗降级 |
| 领域表达 | 主 Bot/子任务、批准/问答/结果/核验、记忆/目标/自动化、设置/能力 | 只消费现有事实；授权、执行、验证、签收与交回分开；有明确下一步和恢复 |
| 宿主适配 | Desktop、TUI、CLI/ACP、Remote、托盘/通知 | 同一行动与回执语义；宿主不支持的能力明示；命令行不伪造图形交互态 |

### 9.1 每个组件的最小 Interface

- 控件：受控实际值、onChange/提交事件的先后、busy 的范围、成功/失败/未知的事实来源。不能只给一组 className。
- 操作：名称优先“动词 + 对象”，说明影响范围；disabled 说明为什么不可执行，busy 防同一动作重入但不冻结无关阅读/编辑；提交未确认保留恢复责任。
- 表单：区分已保存值、草稿、dirty、校验、提交中、失败、失效与恢复；输入说明/错误有程序化关联，失败不清空。离开未保存编辑须保留或明确让用户选择保存/舍弃/取消；只在确有 dirty 时介入，不为普通导航增加确认。
- 选择：选中值与焦点分开，按 tabs/radio/listbox 的实际语义实现键盘；远程/昂贵内容不要方向键一过就触发副作用。Switch/checkbox 移动不等于保存成功。
- 阅读：有来源与稳定身份，缺数据/加载/失败/过期分开；复制、打开、定位有失败反馈。纯装饰不占焦点、不重复朗读外层标签。
- 浮层/布局：进入、退出、嵌套、反向、失焦、卸载、无 API 的行为写清；隐藏内容不能留可聚焦子控件；状态终态不依赖动画。

状态采用 default/hover/pressed/focus/selected/disabled/busy/empty/loading/error/stale/recovery；按照角色排除不适用项并写理由。逐页/逐组件使用[覆盖矩阵的状态模板](../../design/product/peer-interaction-standardization-matrix.md)，模板是要求，不是达标证明。

### 9.2 页面组合规则

页面以用户目标与行动权组织：页面标题/当前对象 → 必要说明与作用域 → 主内容/当前值 → 局部主操作 → 错误与恢复 → 按需细节。单一局部决定只有一个主操作；危险操作不因视觉醒目而变成默认选择。

分组优先留白、标题和稳定表面；导航与阅读保持各自滚动范围。窄容器按元信息收缩/换行/辅栏覆盖的顺序适配，关键输入、停止和恢复可达。空态给原因与合法下一步；loading 使用真实读取；error 说清保住什么、谁能处理、如何继续；stale/unknown 不假装失败或成功。

组件与页面转移遵循[过渡体系](transition-system.md)。U01–U16、M01–M18、T01–T10 的存量映射见[体系覆盖表](../../design/product/peer-ui-motion-transition-matrix.md)。所有新功能引用适用角色与状态，不另画一套孤立的默认 UI。
