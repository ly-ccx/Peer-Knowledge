# Peer 人机交互契约 v1

创建时间：2026-10-23
最后更新：2026-10-24

> 状态：生效；存量实现逐步收敛。与 [Frost 体验规范](peer-product-experience-standard.md)共同使用。
> 定位：定义人与 Peer 交接工作的可观察行为，不新增 Runtime 协议、权限策略、签收条件或存储模型。

## 1. 人持有目标与注意力，Peer 承担推进

用户给目标、边界与关键判断；Peer 持续推进，在交还前提供验证依据。过程默认安静，需要用户决定时给出具体原因、影响对象和选项。已有授权范围内能做的事继续做，不把“每一步确认”当安全感。

六条硬约束：输入不被误发，草稿不被无声清空，阅读不被自动抢回，后台不抢焦点，批准不冒充执行成功，完成不由助手文字决定。

## 2. 行动权与状态表达

以下是**显示语义**，具体字段映射使用当前 main/runtime 的统一投影，不复制一份状态机到组件：

| 事实 / 阶段 | 默认表达 | 用户操作与禁止项 |
|---|---|---|
| 输入尚未持久接收 | 正在发送，保留可恢复草稿 | 不提前写“已收到” |
| 已接收但尚未处理 | 已接收 / 排队中 | 不写“思考中” |
| Peer 正在推进 | 一条可读状态或简短进展 | 可查看过程、继续补充；不要求用户盯守 |
| 需要信息或判断 | 需要你 + 原因 + 明确动作 | 选择或自由回答；归属到原问题 |
| 待权限/计划决定 | 需要你批准 + 对象与边界 | 专用决策流程；普通回复按钮不替代批准 |
| 工具执行结束 | 执行结果及原始依据入口 | 不自动等同整件任务完成 |
| 正在验证 / 修复 | Peer 正在核验 / 修正 | 不用成功勾或虚构百分比 |
| 验证通过且满足签收策略 | 结论 + 验证范围 + 可打开结果 | 展示运行时签收事实；例外由人确认 |
| 部分通过、未通过、未验证 | 第一层直接写出缺口 | 不能把限制藏进折叠详情 |
| 拒绝 / 取消 / 超时 / 失效 / 断联 | 各自准确的终态或未知态 | 给合法恢复路径；不可统一成红色“失败” |

“停止本轮回复”“暂停/取消任务”“拒绝本次授权”“收起面板”是不同动作。标签说明真正作用范围，绝不能共用一个含糊的“取消”。

## 3. 输入与 Composer

### 3.1 键盘优先级

按以下顺序处理按键，较内层消费后不得冒泡执行外层动作：

1. 输入法候选与 composition：Enter 只确认候选，Escape 只退出候选。
2. 当前补全列表：方向键导航，Enter 确认候选；Escape 关闭列表。Tab 是否接受补全沿用共享组件契约，不能悄悄吞掉正常焦点导航。
3. 当前浮层：Escape 关闭最上层可关闭浮层并恢复焦点。
4. 编辑器与发送：按既有发送快捷键设置处理 Enter / Shift+Enter；不覆盖文本编辑、系统快捷键及辅助技术行为。

组合输入至少考虑 `compositionstart/end`、原生 `isComposing` 和兼容事件；`keyCode === 229` 只能作为兼容信号。上游的 WebKit 500 ms 尾随 Enter 防护是特定适配思路，不是 Peer 所有引擎一律吞键 500 ms 的规则。需要适配时封装在共享输入 seam，保留事件序列依据和正常快速连续输入路径。

### 3.2 发送、排队与恢复

- 文本、引用、附件共同组成一份可恢复输入；改变模型、切换机器人、打开抽屉不得静默替换它。
- 乐观回显必须可区分“待发送”；持久接收回执到达后才解除草稿恢复责任。失败保留正文、引用和附件状态，给重试或编辑入口。
- 同一次发送有稳定身份，快速连击、重连和恢复不得重复创建指令或副作用。去重和持久性由已有输入链负责，不能仅靠 disabled 按钮。
- 生成期间允许的补充/排队行为沿用真实运行时能力；队列可见，不能假装新输入已被当前回合读到。
- 发送与停止保持稳定操作区，标签及可访问名称跟随作用变化。已有界面若同时支持排队发送和停止，须清楚分开作用，不为追求“同一个按钮”删除合法能力。
- 停止后保留已生成内容，标明不完整；新草稿仍可编辑。停止请求在确认前显示处理中，不抢先宣称任务已经取消。

### 3.3 附件与上下文

显示来源、类型、名称、处理状态和移除入口；超限、失效、无法读取、格式不支持必须明确说明。缩略图出现不等于模型已收到内容；图片、文本与引用的实际准入沿用受治理 Context Source。

引用绑定原消息/文件身份，点击回到原位置；来源不存在时显示失效，不猜一个相似对象。外部文件、网页、附件是事实内容，不能变成系统指令。预览不得直接打开高权限执行通道。

## 4. 阅读、流式与焦点

### 4.1 用户拥有视口

| 当前意图 | 新内容到达后的行为 |
|---|---|
| 正在跟随最新 | 保持跟随；同帧滚动合并，尽量先定位再绘制 |
| 主动上滚或定位历史 | 停止自动跟随，保留阅读锚点；提供“回到最新” |
| 明确点击“回到最新”或主动滚到底部 | 恢复跟随 |
| 从搜索/引用跳入某条消息 | 显式目标优先，不能被默认贴底覆盖 |
| 图片晚加载、代码展开、虚拟列表重测 | 修正几何而不改变用户阅读意图 |
| 切换任务或压缩历史 | 以真实对象重定位，不能继续使用失效 index |

用户停止滚动后，时间到了也不能自动抢回。上游的 40 px 容差、150 ms 冷却是实现参数参考；Peer 复用 `threadScrollPolicy.ts` 与 `streamingScrollScheduler.ts`，先保留用户意图不变量。

流式更新保持同一消息身份；历史重开、主题切换或虚拟列表重新挂载不能重播全页入场。长文不逐字模糊、不逐 token 播音。读屏通过适量状态通知感知变化，不把每个 token 放进 assertive 区域。[W3C 状态消息](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)

### 4.2 焦点有来处也有归处

后台进展和普通 toast 不夺焦点；只有用户打开的新交互上下文或必须立即处理的决定才转移焦点。关闭浮层回到触发者；触发者已消失时回到相邻合理工作点。

模态必须有可访问名称、合适的初始焦点、Tab 范围、背景不可交互和可见关闭方式。不可逆操作优先聚焦安全选项。`aria-modal="true"` 本身不实现焦点陷阱。[W3C Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

普通菜单和抽屉按语义决定是否 trap，不能所有面板都做模态。嵌套浮层只有最上层处理 Escape 和焦点边界。隐藏/折叠内容不可继续占用 Tab 顺序。

## 5. 决策与权限

决策卡在第一层说明：**要做什么、影响谁/哪里、为何此时需要你、批准的具体范围、可选决定**。高权限决定的关键事实不能全部藏在 JSON 中，技术参数保留按需审查入口。

| 时点 | 必须发生 | 不能发生 |
|---|---|---|
| 展示待决定 | 绑定当前工具/计划/任务身份，展示实际范围 | 按旧快照批准新的参数 |
| 用户点击 | 提交结构化决定，防重入，给处理中回执 | 本地直接把权限改成已生效 |
| Runtime 接受 | 显示真实已批准/已拒绝结果 | 从点击动画推断执行成功 |
| 内容变化、过期或重启后需重确认 | 标明失效并重新取得当前决定对象 | 继续使用旧批准按钮 |
| 已有有效授权 | 按投影和执行期约束继续推进 | 每个工具再弹一次人为审批 |

授权范围与有效期必须符合现有契约。只有运行时支持对应 scope 时才提供长期授权选项，明确说清对象、范围、期限和撤回方式；不能把 330 秒缓存叫“始终允许”。批准不能提升为全项目/全机器权限。拒绝要保留其原因和合法替代路线，不反复施压。

权限安全性在 Projection / PermissionGrant / 执行层强制，交互卡负责理解与表达。UI 不持有独立授权账本，也不从参考项目引入 renderer 自己执行工具的路径。

## 6. 进展、验证和交还

按用户目标报告有意义变化，过程默认折叠，用户随时能收起正在更新的过程。为避免布局抖动而剥夺折叠权，不适合 Peer。折叠不影响后台执行，也不删除事实记录。

进度百分比只能来自可计算的真实工作量；不知道总量就用不定进度或说明当前阶段。运行中、等待外部、限流、断联各自准确表达。预计恢复时间仅在服务端或调度器给出依据时显示。

回复占位沿真实阶段表达；经过固定秒数不能把所有活动改成“耗时较久”或要求用户反复刷新。仅有接收回执不能声称模型正在思考。有公开进展后由正文承接普通进程，权限、恢复和中断仍明确可见。已知配置错误第一层说明原因及处理位置，不只留下通用失败和重试。

已加载设置在窗口回焦或事实通知后的后台重读应保持当前控件和版面，不向对话插入短暂“正在读取设置”。首次加载、真实保存、读取/保存失败及待恢复编辑仍有相应反馈；静默刷新不等于吞掉错误。

本地能力/配置校验与模型服务拒绝分别说明来源；适配缺字段不能直接宣称模型不支持。桌面与终端共享机器人时，操作失败须区分未持有执行权，给已有接管入口；不得在界面绕过宿主租约或替用户静默换模型/强度。

交还第一层包含结果、实际验证结论、未验证范围；第二层打开产物与核验摘要；第三层再看 Evidence、工具参数、日志与调用链。证据入口保留来源、作用域和定位关系。

执行完成、结果签收、代码交回源头、任务暂时安静分别显示，不合并成一个绿色“完成”。策略代签与人工签收沿用现有运行时事实。结果卡只投影，不以助手“已完成”的文本触发关闭。

错误反馈包含发生了什么、保住了什么、谁能处理、下一步动作。重试先确认原动作是否已发生，副作用不因倒计时归零自动重放。429/503 等请求重试由 Runtime/Provider 决定；UI 展示等待，不自己用 `setTimeout` 驱动业务。

## 7. 选择、拖动与预览

- 分段控件用于同组互斥视图或选值，按语义选择 tabs/radio；支持方向键、选中语义和合理 Tab 顺序。真正 tabs 关联 tabpanel；远程加载或昂贵切换使用显式确认激活。[W3C Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)
- 拖动先区分点击与手势，可用 4 CSS px 作为新指针适配的初始死区参考，按设备与已有实现调整。越过死区再进入拖动，松手不补触发点击。
- Pointer capture、pointercancel、失焦、卸载、Escape 都要有结束路径；撤销恢复原顺序/比例。跨 iframe 的拖动必须真正屏蔽事件接管或使用已有宿主机制，透明且 `pointer-events:none` 的盖层不算护盾。
- 分割条提供键盘调整、范围语义、可见焦点和恢复默认入口；宽度不足时进入单栏/覆盖层，不同时强撑两栏最小宽度。
- 预览放大以用户指向的细节为锚，保留缩放/复原和关闭入口；滚轮、触控与键盘各有可用路径。支持检测后才启用共享元素转场，失败直接打开也应完整可用。

## 8. 通知与声音

普通执行静默推进；有意义的完成/失败按既有送达策略处理，需要用户动作时清楚交接。列表、卡片和系统通知指向同一真实任务，点击回原现场；不各算一次“需要你”。声音遵从用户通知与静音设置，不给每个 token 或每个工具配音，不把上游 30% 音量当跨设备响度标准。

## 9. 契约执行

界面只投影现有事实，不能为了符合本规范添加假回执、假进度或超出宿主能力的按钮。所需事实若缺失，记录缺口并按 A/B 级补正确 seam；等待实现时明确显示未知或能力不可用。

新开发使用[执行规程](../../playbook/product-experience-development.md)记录本次状态、事实源、用户控制和恢复。日常以内容/diff 审阅为准；发布按完整产品回归执行，不能用静态截图证明 IME、键盘、读屏或恢复行为已经通过。
