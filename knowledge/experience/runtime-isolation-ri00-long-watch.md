# RI-00：长时同进程自然触发观察

创建时间：2026-11-12
最后更新：2026-11-12

用户要求不再重复短窗口负例。本合同将此前20分钟固定检查点改为最长4小时的单次纵向观察；只做诊断，RI-00未闭合前不启动RI-01或产品重构。旧密集30–40ms形成机制保持unknown，人工增量与周期GC不填补现场归因。

## 责任与事实归属

| Module | Interface、事实与依赖 | 失败及恢复 |
|---|---|---|
| Persistent Probe | 安装一次既有Supervisor/Evidence读口包装；记录自然同步入口、逐遍线程/进程CPU、新生代状态、根输出/索引身份及GC事件；保持返回值/异常/receiver，独立计量探针CPU | 原方法owner改变即失效，恢复时不覆盖新owner；硬期限或90秒控制器租约过期则恢复并关闭本轮Inspector |
| Natural Sentinel | 控制器纯函数；同数据代次、相同Evidence位置的自然读成本指纹，保存5个合格基线点；至少6个位置平均增加≥2ms且合计≥8%，连续3个自然根只产生触发建议 | GC不匹配、输出/数据变更或中断清除连续计数；不将自然异常判成密集残差或解释为GC |
| Capture Controller | 唯一拥有Inspector、常驻只读参照、计数侧车、预算、代次与触发队列；自然记录通知唤醒，30秒租约续期，不按时钟反复查询业务 | 一次在途夹测，触发合并；日志先落盘后ACK；超时/错误不重放读请求，独立收尾并验证端口拒绝连接 |
| Source Archive | 独立owned Node进程保存查询依赖的三Store、目标workspace的coordination-v2 canonical文件、当前SQLite一致备份及前后身份，私有目录；不改canonical、lease、任务、配置或模型 | 每次30秒硬超时、worker V8堆128MiB、1MiB散列缓冲；源变化/备份revision不符拒绝，不将不一致副本称为可复现基线；预算不足保留身份与缺口 |

参照使用现有完整只读生产读图，禁止Runner/模型/工具派发和源写入；实际main及参照的PID/OS启动身份、生产与探针代码摘要跨期固定。参照退出不得替换后继承原比较身份。本文不新增产品IPC或运行能力通道。

## 阶段和触发

1. `bootstrap`：参照自身预热；main-A8→同一参照8→main-B8建立原主指标的快态，完整保留首读。沿用原12遍Evidence用户CPU和配对/极差/校准门，不从自然读推算密集指标。
2. `learning`：不插入业务查询，收集自然根的逐位置指纹。每位置须有5个索引/输出身份一致、跨度内未记录major/incremental、读前后新生代均64MiB的点；至少6位置可用。根其它位置发生GC不抹掉这些跨度；未记录GC不证明无GC。记录后台CPU但不据此归因。
3. 指纹准备后再做一次完整夹测；前后均有合格快态才记为`armed`。若未取得快态，仍保存自然入口成本指纹并进入`armed-entry-unqualified`，其含义仅为“从该已观察入口态开始留存变化”，不能把该入口态称为快。每代次最多2次bootstrap，不为追求绿色判据反复查询。
4. `armed`：自然通知触发取回批次，纯函数比较同位置指纹；≥3个连续合格自然根达到自然阈值，或自然根墙钟≥2秒，封存前史并提出一次捕获。自然信号只负责唤醒，不作为残差证据。
5. `capturing`：自然触发后立即做同源main-A/参照/main-B密集夹测及短间隔第二次无profiler夹测，保留所有判定。只有有合格前置快态、两次均满足原≥25ms、≥8%且相对同代次快态增长≥25ms的两组差额才确认形成；两次之间不先开profiler。
6. 随后做bare/detailed、双宿主500µs CPU profile和无profiler复验，均不进入检测门。即使夹测不匹配，也取栈并明确未确认，不能用“判据不足”阻断取证。恢复或只触发自然信号而无密集残差时记录负例，冷却10分钟；最多3个自然捕获episode，并须有至少22秒剩余受控CPU预算才准入，预算可能更早限制次数。确认转换仍不是机制归因。

自然全量前史和GC记录持续写入私有追加日志；内存ACK后释放已归档记录，保留未确认批次及重叠GC窗口，不覆盖磁盘旧前史。没有事件通知时不进行全量查询；30秒租约续期只执行诊断状态方法。

`armed-entry-unqualified`不会伪造主指标基线，不改变旧15ms极差、GC配对、校准或增量判据。自然相对入口态的异常只触发取证；若缺少触发前已合格的快态，报告不得将随后取得的快点倒填成事件前史。bootstrap入场已慢可立即取一次栈并登记历史空窗，之后继续留存，不能反复采入场慢态替代形成。

逐遍新生代/进程CPU元数据仅在自然根采集；密集控制点沿用旧最小读体计量及根级堆/GC配对，避免为了自然哨兵给控制点增加24次heap-space采集。采样函数身份不切换。根级长观察元数据另保留所有堆空间、外部/分配内存和native/detached context计数，正向候选后读取具名V8 heap/code统计，不启用native-syntax或其它VM参数。

每根第一遍Evidence另存48帧上限的同步调用栈，连接自然入口与内部核验链；临时stackTraceLimit描述符立即恢复，栈采集在Evidence计量跨度之外，单独计入探针CPU。不能据此回填未观察到的异步父链或逐指令历史。发现读口时只将两个必要port转入owned Inspector group，立即释放整个发现Scope group；结束释放owned group，避免长时间保留无关调试句柄。

## 数据代次

自然根的索引stat、输出摘要、Evidence行数以及控制器三Store元数据/索引内容绑定代次。变更立即冻结原基线并保留变化前后事件，不跨代次比较CPU。源稳定5分钟后最多允许两次新代次重建，每次重新归档、建立快态并学习自然指纹，且必须保留捕获预算。持续写入、预算不足或再次变化时保持被动观察并登记无法比较，不能以自动重开进程、切换参照或修改个人数据恢复基线。

协调事实代次绑定现有只读Coordination port的revision、canonical文件及当前索引指针；不把host.lease心跳或派生SQLite的mtime/WAL/checkpoint当成事实变化。SQLite备份须核对同一revision。归档只复制当前读图：fenced legacy目录保留身份，不复制其内容；不复制恢复库存、旧索引或其它workspace协调文件。备份SQL用于既有CoordinationSnapshot只读适配器回放，不宣称能在新inode上重放原writer fence/source-token验证或恢复整个个人状态。相关成本与缺口继续单列。

## 有界预算与异常

- 最长4小时；实际进程不重启、不强制GC、不改JIT/GC参数、不取堆快照。90秒租约独立于4小时硬watchdog。
- actual main受控读体CPU准入上限60秒、原生校准3秒、探针自计CPU5秒；同步工作不能抢占，最后一次超额原值保留，随后停止。Inspector序列化与OS采样边界开销另列，不声称绝对硬实时CPU封顶。
- 最多3个捕获episode、2次数据重建；没有基线不因等待到期判通过。首次已慢仅为入场慢态，不冒称捕到完整形成。
- 未ACK记录最多256根、根外读2048项、GC保留32768项，元数据序列化预算16MiB；满即恢复并封存，禁止环形覆盖未归档前史。追加日志上限64MiB，源归档逻辑字节上限1.5GiB；所有原始内容留在0700私有目录。
- 16MiB是元数据序列化准入，不冒称V8实际RSS硬上限；另有固定4MiB原生控制缓冲。控制器自身CPU预算30秒；归档worker单独记录CPU、30秒墙钟硬截止。磁盘同样按已知逻辑大小准入，单个已开始复制/备份的越界须记录实际字节并停止后续归档，不把预算不足当作基线完整。
- 控制器中断、RPC丢失、ACK失败、源/返回身份变化、方法替换、参照退出、预算耗尽分别记录。失败不自动重放原查询，不发布伪造通过；watchdog恢复失败保持具体错误，不重新启动实际应用。

b3保留了5次未取得合格基线的尝试，源/返回身份、零丢失与恢复通过，但最终进入被动无基线，未通过“自然事件能触发取证”的可用性审查。这不是性能负例。由此修正为上述取证与确认分离、每代次只做两次bootstrap；不将原失败点追认为通过。

### 补充VM见证的已知干预

15:46:05 UTC在两个合格快态之后，另以脚本摘要、时钟和PID校验采集一次V8 heap/code统计，main线程27.532ms、参照23.158ms；未修改VM参数或做heap snapshot。此项不进入上述快态CPU中位数，也不是采集时刻仍快或CPU差额的证明。

随后核对匹配V8版本的[API实现](https://github.com/v8/v8/blob/14.6.202.34/src/api/api.cc)与[Heap实现](https://github.com/v8/v8/blob/14.6.202.34/src/heap/heap.cc)：`GetHeapCodeAndMetadataStatistics → CollectCodeStatistics`进入Safepoint，`MakeHeapIterable → EnsureSweepingCompleted`可完成已有V8 sweeping并使线性分配区可遍历，再遍历旧代/code等对象。因此不能把这个getter描述成纯被动计数，也不能用“没有显式强制full GC”排除其观测影响。私有前史另存源码摘录、摘要及见证的准确时钟。等待自然触发前不再重复；后续事件必须保留这条干预边界，不直接称为完全无诊断干预的自然形成。运行时harness保持冻结。
