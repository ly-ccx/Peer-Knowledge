## 封存 CPU 区间的结论

27 个旧窗口的 2187µs = 1928µs 粗窗口覆盖 +259µs 外侧区间；1928µs 又含 428µs 粗窗口扣除直接子窗口后的区间。差分均使用封存整数微秒原始快照，原件与旧失败不改写。

| 区域 | 余部 user/system/total µs | 粗簿记 user/system/total µs |
|---|---:|---:|
| root.pre | 5/2/7 | 45/12/57 |
| span.pre ×12 | 62/42/104 | 118/58/176 |
| span.post ×12 | 90/51/141 | 129/16/145 |
| root.post | 2/2/4 | 39/6/45 |
| root.keep | 1/2/3 | 5/0/5 |
| 合计 | 160/99/259 | 336/92/428 |

259µs 的 54 段在粗窗口前/后为 201/58µs；428µs 的 103 段按首子窗口前/子窗口之间/末子窗口后/无子窗口为 58/167/58/145µs。全部区间和边界 ID 保存在私有 `gaps.private.json`，未以拟合或取整凑和。

这里同时有原始对象构造、队列/计数/时间更新、旧 CPU API 返回算术，也有新 meter 的 `clocks.push`、返回对象、stage 字段、open/stages 数组与 wall 读取。不能把 span.post 的 141µs 余部或 145µs 簿记全部归为原始业务，也不能全部归为新增计量。55 个旧时钟 wall 上界 0.268957ms、242 个新增时钟 wall 上界 0.275997ms 仍不是精确时钟 CPU；本轮未减去它们。

## 唯一真实 Electron 槽

Node 资格仅一次：4 项检查覆盖严格 2ms、失败立即停止后续格/族、不替换、输出完整字节身份与不一致拒绝。CPU1020.577ms、wall1590.144958ms，低于 2500/20000ms。不是 Node 性能推断。181 项源码绑定、旧生产者逐文件校验、原始 journal 重放和输入内容绑定通过。

真实运行 Electron41.7.1/Node24.15.0/V8 14.6.202.34-electron.0，默认 VM。只调用一次封存副本上的生产 supervisor.list，保留返回对象在宿主局部变量；所有 8 个输出格均核对 23 sessions 对应的 130581 字节与同一 SHA。无记录器安装、Inspector、Profiler、强制 GC、heap getter、现场连接或额外业务查询。

固定顺序为每族 ABBA/BAAB，A 关闭新增 meter，B 使用未改的封存 meter。24 格全部完成，逐格 CPU0.047–0.523ms，均低于2ms；没有额外实例、丢弃首格或补格。

| 操作族 | ABBA 的 B−A CPU | BAAB 的 B−A CPU | A 返回漂移（两组） |
|---|---:|---:|---:|
| 空载 metadata 拓扑 | +0.353ms | +0.2875ms | −0.070 / +0.002ms |
| 13 次同步取栈 | +0.014ms | +0.049ms | −0.028 / +0.035ms |
| 原始输出 JSON→UTF8→SHA | −0.0875ms | −0.048ms | −0.051 / −0.070ms |

空载 B 每格均为 121 stages、297 clocks（55 旧调用+242 新边界），嵌套和零 open/invalid 通过。两组差分的 user/system 分别为 +229/+124µs 与 +164.5/+123µs。这个反事实在固定空载拓扑下观察到约 0.29–0.35ms 的新增开关差，**不是原业务根的可扣除净成本**；没有把它塞回 259/428µs 或历史 2.387123ms。

取栈 8 格各 13 次，所有当前完整向量一致且为35帧（固定32层递归），未截断。B 的具名 capture CPU 合计为0.256/0.258/0.270/0.277ms，含边界计量；对应操作 wall 上界0.233166/0.241085/0.252455/0.257833ms。两列含义不同，CPU 点区间多含边界 API，不能把 wall 数当作 CPU。35帧诊断链不冒充旧业务链，更不能用这里的0.225–0.275ms OFF CPU替换旧0.569ms具名区间。

输出 B 的 JSON CPU 点区间0.059/0.091/0.069/0.156ms，UTF8 0.173/0.181/0.185/0.182ms，SHA 0.042/0.050/0.048/0.053ms，均含边界。关闭 meter 的整操作仍为0.368–0.438ms；开启为0.282–0.398ms。负差和 OFF 返回漂移同时存在，不能认定“计量降低编码 CPU”或宣布编码计量无干扰。没有据此猜改编码算法。

实际格间隔0.164083–5.672917ms全部保留。固定一次 setImmediate 之外还有验证与不同大小的归档 I/O，工作集、分配和顺序前史并未完全相同；ABBA/BAAB 也不能证明所有状态影响已消除。不存在另设性能合格门或把结构通过改称低干扰通过。
