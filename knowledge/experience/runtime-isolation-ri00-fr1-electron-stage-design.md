# RI-00：真实 Electron 记录器分段诊断设计

创建时间：2026-11-14
最后更新：2026-11-14
状态：执行前冻结；只授权一宿主的分段诊断，不授予功能、低干扰、现场或重构资格。

## 问题与结论边界

用户授权先冻结设计和有界预算再执行。原63bd98bd失败的2.387123ms只已有粗账：root前CPU0.257、后CPU0.540、12遍self CPU1.348、plan计数wall上界0.230123、保留尾CPU0.012。新样本必须取得同一真实Electron线程中的阶段事实，不能用Node微基准、多个新进程的单点相减或序列化字节代理CPU。历史根缺少细分，不能事后精确回填；新根耗时不同也不按比例拉齐。

范围为C级诊断。保留工程总纲、Accepted ADR96和Proposed ADR128，产品边界不动。原记录器文件及2ms/3s门不修改；诊断由精确版本绑定的源变换生成，供单独owned入口使用，现场安装器不引用它。

## 执行入口、职责与数据

1. 私有owned Electron入口复用原read host、read-only guard、注册handler和关闭协议，固定Electron41.7.1/Node24.15.0/V8产物身份及原8534文件输入。原开发版保持进程，不附着、不重启、不读业务。
2. `fr1-stage-source`只在明确的语句接缝插入同步begin/end，所有替换均要求精确匹配一次，记录原文件、函数和生成源码SHA。取栈操作保持在原函数体内，不引入包住取栈的回调帧，不减少96帧或改变业务参数、顺序、结果和异常对象。
3. `fr1-stage-meter`拥有独立的有界数值账本、阶段栈及原生时钟句柄；不修改产品方法或全局时钟，不发业务查询。CPU读数和wall来自同一线程。每个区段记录父ID、起止CPU、起止wall、边界时钟窗口、完成/未完成状态。
4. 独立runner复用原安装/单槽journal/ACK/恢复。仅把该owned安装声明中的原记录器替换为绑定的生成版本；外部Controller不能把它用于运行中的Peer。先安装前选择读取，原Promise/异常检查，然后只发一根list-sessions；不执行完整资格的九根/Profiler/堵塞场景。
5. 业务读取后先停止、归档、恢复原owner与绑定，再冻结分段账本。最后只做一次64对相邻CPU时钟读数的同宿主控制，绝不在首根前热机、采堆或启动Profiler。

原CPU、2ms停止、原journal记录以及诊断账本分别保存；诊断账本不塞进原业务返回。保留原错误和失败、原始read输出SHA及计数、原件SHA链。取回账本只取元数据，未确认批次不重建、不覆盖。

## 分段与计量口径

| 范围 | 细分 |
| --- | --- |
| root前、后、日志保留；每个span前、后 | 粗区段，和原self CPU窗口核对覆盖及余部 |
| 当前栈 | 原生getCallSites；脚本核对/位置元组构造；签名JSON；字节上界/查重；新字典记录 |
| 源版本 | stat；版本字段编码；metadata散列 |
| 输出身份 | JSON；UTF-8；输出散列 |
| 每类原记录 | JSON；byteLength；排队/通知准入 |
| 时钟 | 原记录器调用与新增边界调用分别记录wall窗口及返回的CPU快照 |

所有阶段同步嵌套，CPU inclusive可重叠，exclusive只减直接子区段，不重复相加。根部粗区段彼此不重叠，分别落在原pre/post/keep与span self窗口内；原self CPU减粗区段和的余部保留，不能按比例摊进热点。原plan计数wall仍单列，不冒称CPU。

begin在原生CPU读数前后保存wall，完成自身入栈后记exit wall；end先记entry wall，再读CPU。CPU差是含边界成本的线程CPU区段，不是纯操作CPU。操作wall上界取begin exit到end entry；整个CPU bracket wall取最外两个端点。用边界观察wall上界和CPU读数的微秒量化不确定区间，给出被测区段CPU保守上下界；不把wall当精确CPU，也不从原2ms计费扣掉观察器。

时钟自身没有精确CPU归属：记录其wall上界；64对控制的CPU差是一个时钟及周边JS的CPU bracket，另有完整pair wall，不乘一个平均值回填原窗口。CPU越过wall的检查保留每个用户/内核读数的微秒量化误差，异常只使计量失效，不调整原性能门。

阶段begin/end也会改变所测工作。其新增时钟数、嵌套inclusive/exclusive、未覆盖余部和完整宿主成本全部单列；即使区段数据完整，也不得称observer中立或产品根因。阶段错误用finally闭合；不完整、溢出、未知取回或恢复失败均保留raw并标invalid，不补样。

## 冻结预算与停止

[机器预算](../../playbook/evidence/runtime-isolation-ri00-fr1-electron-stage-budget-20261114.json)为本次用户新授权的独立诊断，旧失败及累计成本不清零。

- 固定1个owned Electron，替换0；最多2次生产读，最多1根记录根；读CPU6s、完整等待子树CPU8s、wall30s含3s清理。23s后不再准入操作；私有子进程25s看门狗，外部28s仅TERM本轮进程组、30s仅KILL该组，留实际超限。绝不终止或重启Peer。
- 原2ms/root和3s累计self门保持，任何超门后不再发业务读或重装探针。分段数据允许解释失败，不授予功能通过。即使首根未超门，采完一根也停止。
- 最多512段、2048个时钟事件；分段快照512KiB，journal2MiB，总输出2MiB。超帽/错序/不闭合/未知结果即停止；容量损失必须报，不把部分记录当完整。
- 同宿主时钟控制仅64对、CPU50ms、wall200ms，放在业务读取和恢复之后，失败不重做。无Profiler、native采样、heap getter、强制GC、SHA热机或人工业务忙循环。
- 最终同候选单元和源/输入绑定CPU2.5s、wall20s。Node只做逻辑、源变换与数据身份检查，不跑性能微基准。诊断driver及分析另保留输出和完整返回成本；不声称未计量开发命令成本已知。

## 完成条件与恢复

交付一份同候选、同输入、同真实宿主的原记录和分段账本；CPU/wall/边界成本/余部的算术与父链可离线重放，原结果和所有失败保留，原方法/handlers/binding/ACK/专用端口恢复，自有进程退出确认。运行中的开发版保持原PID/birth且零业务查询/参照/重启。

任何区段CPU只能在其证据范围内命名，无法分开原生操作与边界就给上下界或unknown。诊断额度不含修正后的功能复验、现场窗口或机制复现，新增执行需另定具体范围。原记录器未合格前不进现场；没有现场同进程快到慢及机制证据前不重构。
