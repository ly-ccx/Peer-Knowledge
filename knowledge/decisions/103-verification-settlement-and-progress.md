# ADR 103：核验收口、进度与停滞治理

创建时间：2026-10-21
状态：Accepted（用户明确要求一起修复核验收口、核验阶段停滞检测与进度反馈，跑回归并确认续接修复进入新构建；不得影响当前任务）
级别：A（核验续接元数据和进度投影），B（核验运行时、事件映射）
关联：ADR93、94、95。续接修复与工作区 ADR102 草案兼容，但本次 PR 不携带其生命周期重构。

## 决策

保留 ADR95 有实际进展即继续的原则，不恢复系统默认累计请求/工具上限，也不以总耗时判定任务失败。五分钟仍是单片执行期限，不代表整体核验截止。修复的对象是无进展、格式修复重新开审、核验期不可观测与旧构建续接。

1. 核验沿既有 VerificationContinuation Module 和注册 checkpoint 存储保存开始时间、最后实际进展时间、已检查事实计数与稳定进度身份。请求次数、工具次数、时间和新的调用身份不是实际进展；重复观察不能续租。无进展达到既有十分钟窗口时终止该核验尝试，保留明确 verifier_no_progress，交回父代理处理责任。既有相同事实重复保护继续生效；有新事实的长核验不被累计次数或总时长截断。
2. 格式修复至多一次、一个认知请求，禁止再次执行工具和从头审查。仅使用先前报告及已准入的事实/证据引用修复结构；没有合法报告就返回 verifier_report_invalid，不能伪造通过。取消、拒绝、版本/模型变化、未知派发、检查点损坏与显式预算仍先行拒绝。
3. Watchdog 同时观察 running 与 verifying。核验期以当前核验最后事实进展/开始时间为锚，不能用 Worker 完成时间、请求计数或心跳掩盖停滞。相同停滞身份只发一次；新事实之后再次停滞可以产生新的事件。不得以时间直接制造验收或修改 Worker 成果。
4. 核验开始与新事实通过既有 session_progress / inbox / agent_activity 链路投影到主会话，使用可选类型化进度事实。合并节流保持最后未发进度，不因提前更新观察快照丢失。主代理可以静默等正在推进的核验；停滞和失败仍是真实唤醒。界面表达“正在核对结果”及已检查事实数，不把模型请求数冒充完成百分比，不伪造 assistant 回复或 Evidence。
5. 纠正 handoff 的续接规则：旧 verify 意图换执行体后转 execute；同执行体跨宿主恢复仍保留 verify。构建验收直接检查新 app.asar 内代码并运行打包模块定向用例。

## 边界与交付

不新增能力、执行旁路、授权、IPC 方法或存储路径。协议只增加既有 runner 元数据、工作会话和活动的可选进度字段。Runtime 负责事实、超时与事件，Renderer 只表达。工具/附件/检查点仍是事实，不提升为系统指令。

在包含当前工作区成果的隔离副本实现、测试和打包；只回填本次修改，发现冲突不覆盖。所有命令使用临时 PEER_AGENT_HOME，不写真实用户数据，不取消、接手、重启、升级当前运行实例。新构建保存到独立输出位置，安装与发布不在本次范围。

## 验收

先红后绿覆盖：格式修复不可重开工具；无新事实的累计空转与跨重启截止；实际有进展超过原96/512/五分钟；verifying 停滞、真实人工等待豁免；开始与节流后的进度不丢；主代理收进度但失败/停滞仍唤醒；正常核验通过与异常都释放所有权并产生既有结果/修复责任。补充打包模块检查与纠正handoff/同宿主恢复的生产入口回归。

跑受影响包完整测试、类型、架构、构建及产品 Capture → 逐图实施者自审 → Verify。明确真实云模型、安装版升级与读屏覆盖限制。机器结果与源码/构建身份追加到本文件，不以计划冒充完成。
