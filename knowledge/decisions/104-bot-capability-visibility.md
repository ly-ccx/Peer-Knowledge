## 1. 用户目标与本次范围

用户需要每个 Bot 有适合自身工作的能力、配置和内容，同时复用全局公用部分。例如：代码 Bot 使用代码审查 Skill 和某个仓库连接；写作 Bot 使用写作 Skill 和另一份资料；两个 Bot 仍可复用同一 Skill 原包和共享 MCP 定义。

外部能力页回答“这台设备安装和维护了什么”；Bot 设置回答“这个 Bot 挂载什么、绑定哪份配置、使用哪些内容”；运行时回答“当前主体此刻实际可用什么”。这三个答案有联系，但归属不同。

本 ADR 定义：

- 共享能力库、共享默认配置与 Bot 专属绑定的关系。
- MCP 连接、Skill 参数／变体、内容引用及自定义指令的归属。
- 继承、显式覆盖、默认全开、身份与版本失效规则。
- 投影、执行、上下文快照、撤回、任务恢复和多宿主边界。
- 实施所需 Interface、迁移与验收反例；不宣称这些能力已经实现。

本 ADR 不重新设计模型分工、权限档位、工具执行、任务核验或记忆系统；不增加远程写入权限，不自动安装、登录或复制凭据。内置文件／Shell／Web 能力仍由现有角色、模式和权限链控制，不纳入本期 MCP／Skill 挂载开关。

## 3. 决策与不变量

1. 安装一次、按 Bot 绑定。公共定义可以共享，绑定配置与内容可以独立；不为每个 Bot 强制复制安装包或启动进程。
2. 默认全开保留。没有 Bot 覆盖记录时，对该主体原本可用的共享 MCP／Skill 继承启用；以后新装的合格共享项也默认启用。默认全开不代表登录成功、越过权限、跨工作区挂载，或自动共享其它 Bot 的专属内容。
3. 启用、配置、内容和权限是不同事实。启用不会生成 PermissionGrant，选择资料不会授予文件权限，填写提示词不会增加工具。
4. Bot 主体沿 ADR 101：`workspaceId + 当前 profile.agentConversationId`。不能用名称、路径、模型、客户端传来的 parentId 或字符串中的 Bot 名称替代。
5. Worker／Explorer／Verifier／嵌套子任务动态继承所属主 Bot 的能力边界，不独立保存更宽策略；只读角色等约束始终保留。
6. 共享对象的修改有共享影响；Bot 覆盖只影响本 Bot。保存入口必须明确其作用对象，不能修改公共 Skill 来模拟 Bot 私有化。
7. 投影与执行双重检查，继续唯一能力链：Provider → Manifest → Runtime Projection → Tool Call → PermissionGrant → Evidence。
8. 内容与工具使用同一主体和有效绑定视图；内容准入仍由受治理的 Context Source 负责，不能把资料正文提升为系统指令。
9. 已发出的上下文、已完成工具结果与 Evidence 是历史事实。配置修改不改写历史，不重跑完成写入，不把撤回伪装成从未执行。
10. 目录／策略读取失败显示未知或不可用；缺省兼容只适用于可信地确认“尚无记录”，不能用于损坏、身份错误或缺失绑定。

## 4. 对象与归属

### 4.1 三层结构

| 层 | 持有内容 | 修改作用 |
| --- | --- | --- |
| 全局能力库与本机目录 | 共享 MCP 定义、Skill 原包、安装来源／版本、现有设备管理开关、可复用连接与共享内容索引 | 安装／更新／卸载归这里；共享配置变更影响实际继承它的 Bot |
| Bot 配置与内容 | 启用覆盖、连接／参数覆盖、选用 Skill 变体、共享内容引用、专属内容引用、自定义指令 | 只改变当前主 Bot 及所属子任务的后续行为 |
| 有效运行视图 | 可信主体、来源明确的绑定、实际版本、配置摘要、工具映射、上下文引用及不可用原因 | 宿主计算，供界面和运行时使用；不是新的授权真源 |

共享表示可复用，不表示所有内容必须进入每次请求。安装默认全开只控制挂载；发现、按需加载与上下文预算沿现有策略，不全量注入所有 Skill 正文或资料。

### 4.2 身份与引用

- `CapabilityRef` 至少包含 kind（mcp_server／skill）、稳定的定义身份及来源作用域。作用域区分 global、workspace、bot_owned；本机安装实例另有本地安装身份与版本，不以显示名或原始绝对路径充当可移植 ID。
- `BotCapabilityBinding` 指向一项能力定义，可包含启用覆盖、配置覆盖、选用变体和内容引用。由宿主核对 owner；客户端不能指向其它 Bot 私有项。
- `ConnectionBinding` 引用已有本地连接或 Bot 专属连接配置，秘密仍由现有凭据存储管理。连接引用、能力定义和安装实例不能混用一个 id。
- `ContentRef` 声明来源、所有者／共享范围、用途与可恢复版本定位。内联／每 Bot 自定义指令兼容沿既有 per-Bot / per-project 配置槽位（统一重构留待后续 `132+` ADR）；文件正文、知识库片段、MCP 资源按实际来源处理。
- `EffectiveBinding` 记录最终 enabled、各字段来源、配置／内容版本、就绪状态及原因。至少区分 disabled、missing、needs_login、invalid_configuration、unavailable、ready；enabled 与 ready 不可合并。

同名全局／工作区 Skill 在管理列表分别可见。无显式选用时延续旧工作区优先规则，同一逻辑工具只投影一次；选择具体变体后使用限定来源的引用。别名冲突由宿主确定映射并检测，不能按清洗后的模型可见名推断身份或随意覆盖另一项。

### 4.3 共享项与 Bot 专属项

全局共享安装项进入默认继承候选。为某个 Bot 新建的连接、内容或 Skill 变体默认属于该 Bot，不因本机能发现它就变成所有 Bot 的新共享项。将专属项提升为共享项必须是明确的本地用户管理动作，说明影响范围；缺凭据／权限时仍不可用。

共享 Skill 可以供多个 Bot 选用；Bot 参数与补充指令存为覆盖。需要修改 Skill 步骤正文时，应创建有独立身份和来源记录的 Bot 变体，保留原包；不得覆盖原包或把未经管理的文本冒充已安装 Skill。

## 5. 继承、覆盖与默认全开

### 5.1 启用语义

Bot 保存三态 `inherit | enabled | disabled`；未记录等价于 inherit。共享默认值未记录时为 enabled，保存空表不能变成安装快照或全关。

| Bot 决定 | 共享默认启用 | 共享默认关闭 | 设备／原有工作区准入不通过 |
| --- | --- | --- | --- |
| inherit | 启用 | 关闭 | 不可用并说明限制来源 |
| enabled | 启用 | 启用 | 不可越过该限制 |
| disabled | 关闭 | 关闭 | 关闭；保留用户决定 |

共享默认是挂载偏好，可由 Bot 覆盖；设备硬禁用、工具可见性、既有工作区准入和权限拒绝是另一层约束。第一阶段没有新的共享默认配置时按 true 解释，不要求为此新增一个全局开关。

旧 Skill 兼容规则：先使用现有全局／工作区挂载规则计算资格，再应用本 ADR 的 Bot 绑定。旧工作区显式启用仍可按原规则优先于旧全局禁用；旧工作区关闭等限制不被新的 Bot enabled 绕过。不得把旧 globalDisabled 直接迁移成设备硬禁用，也不得在本轮悄改 `skills:enable` 的含义。未来若合并旧挂载配置与新默认配置，必须另列映射、迁移与反例，不能留下两个名字相同却优先级不明的开关。

### 5.2 配置覆盖

配置按“共享默认 → Bot 显式覆盖”解析，但只能覆盖 Provider／Manifest 明确声明可覆盖的字段。每个字段必须标记来源，不使用未知键任意深合并。

- 未提供字段表示继承；恢复继承删除对应覆盖。空字符串、空数组与 null 是否有效由字段 schema 明确定义，不能一律当未设置。
- 标量替换；集合明确 replace／append／remove 语义，默认整项替换并去重。秘密、路径、账号、资源范围不能藏在自由文本参数中绕过宿主校验。
- 选择另一连接是原子替换引用，不合并两个账号的认证头。连接不存在或参数不合法时保留配置并报错，不自动换共享连接、账号、模型或其它能力。
- 共享默认变化影响仍继承该字段的 Bot；显式覆盖保持。schema／版本变化导致不兼容时标记待处理，不静默删除覆盖或改成其它有效值。
- 端点、命令、环境与认证头只能通过现有安装／连接管理 seam 的已声明能力校验和管理；不新增一个任意命令或秘密写入入口。

### 5.3 内容归属与组合

| 内容 | 缺省与组合 | 修改位置 |
| --- | --- | --- |
| MCP／Skill 共享定义 | 合格共享项默认挂载；正文按现有发现／加载策略准入 | 全局能力库；Bot 不原地改原包 |
| Bot 参数及 Skill 变体 | 未设参数继承共享默认；变体显式选用 | 当前 Bot 绑定或有所有者的变体 |
| Bot 自定义指令 | 未设／空值表示无附加指令；不自动继承旧全局个性化文本 | 沿既有 per-Bot / per-project 指令配置与迁移入口（完整重构待后续 `132+` ADR） |
| 共享资料 | 发布为共享或被用户明确选用的集合才可被引用；挂载不等于全文注入 | 共享资料来源；Bot 保存引用及筛选参数 |
| Bot 专属资料 | 只供所属 Bot 及合规子任务使用；其它 Bot 不自动发现或继承 | 归属明确的现有内容存储／Provider |
| 项目文件、记忆与任务结果 | 延续原工作区、记忆、检索、文件授权及 Evidence 归属 | 各自现有 Module；不复制到本 ADR 的配置表 |

自定义指令的来源与层序沿 [System Context 架构](../architecture/19-system-prompt-context-architecture.md) 与既有每 Bot／每项目配置槽位（完整重设计待后续 `132+` ADR）；Skill 提示沿已注册来源，必须与 Skill 挂载一致。资料、MCP resource/prompt 返回正文、工具结果和附件不因被绑定而升级为系统指令。内容引用必须支持受治理的检索或读取、预算与错误，不以字符串拼接绕过 Context Source。

“Bot 专属”约束正常发现、投影、检索与访问；不宣称创建了操作系统沙箱。另一个 Bot 的底层文件访问仍由原权限／资源范围规则约束；不能只靠隐藏 UI 或提示词证明数据隔离。

## 6. MCP 连接与实例复用

能力定义可共享，MCP 会话是否共享由有效连接决定。实例键至少涵盖 Provider 定义／安装版本、传输配置、凭据引用与有效认证代次、资源／租户范围、必要的 Bot 上下文及配置指纹；指纹不得包含可输出的明文秘密。

- 两个 Bot 的所有有效连接维度一致，且 Provider 声明不含 Bot 私有可变状态时，可以复用既有连接池。
- 账号、资源范围、工作目录、环境、配置或 Bot 私有状态不同，必须隔离实例／会话命名空间。不能只以 serverId 为池键。
- Bot 的开关只改变该主体的挂载，不卸载共享服务器，也不默认断开其它消费者。独占资源与无消费者实例沿既有生命周期清理。
- 修改共享连接只影响实际引用它的绑定；Bot 专属配置不回写公共连接。凭据变更、退出登录和异步授权刷新仍沿既有凭据 seam，不把旧连接的成功当作新绑定就绪。
- 不支持实例隔离或配置覆盖的 Provider 必须声明限制并禁用相关编辑；不得表面保存成功，执行时悄悄使用另一份配置。

## 7. Module、存储与 Interface

### 7.1 BotCapabilityBindings Module

共享策略与解析放 runtime-node；Desktop／TUI 装配可信目录、主体解析、存储和 Provider schema 端口。Module 的 Depth 是把归属、覆盖、版本、错误及跨宿主一致性收在同一 Interface；它不执行 MCP、读取文件正文、维护秘密或拼接系统提示。

拟定 Interface（命名与类型需实施前在 protocol 落定，当前不是可调用 API）：

| Interface | 调用者需要知道的契约 |
| --- | --- |
| `read(identity)` | 返回已保存覆盖、revision 和来源；可信无记录与 unavailable 分开 |
| `describe(identity, catalog)` | 返回该主体可管理的全部候选及有效值、来源、不可用原因；关闭／缺失项保留，不用运行时过滤结果充当设置列表 |
| `update(identity, expectedRevision, patch)` | 只允许经宿主校验的本地用户入口；CAS、字段 schema、owner 及引用校验；成功原子提交，无变化不加版本 |
| `resolve(context)` | 复用 ADR 101 的完整归属解析，定位当前主 Bot；独立经典会话返回不适用，委派错误结构化拒绝 |
| `compile(identity, observedVersions)` | 产生工具／内容引用共用的有效绑定快照及可信别名映射；不生成 grant，不输出秘密 |
| `admit(context, bindingRef, observedVersions)` | 实际执行／资源交付前核对当前主体、绑定和版本，返回允许继续检查或结构化拒绝；沿既有 gate 的 validate seam 再检 |

已装目录仍由原 MCP／Skill Module 持有；配置字段及实例隔离由 Provider 负责；内容由既有内容存储与 Context Source 读取；PermissionGrant 和 Evidence 保持原责任。不得将这些责任都塞进一个新“大能力管理器”。

### 7.2 设备本地真源

Bot 绑定策略存于已登记的 `project-runtime` 数据域，以 ADR 101 的主体分区。拟采用独立的版本化 `bot-capability-bindings.sqlite`，借用既有 Node／Bun SQLite adapter seam，避免侵入权限库 schema；实施前登记数据目录、schema 与迁移版本。

事务保存当前配置及追加版本历史，CAS 支持多窗口、多进程和重启。记录能力引用、三态覆盖、非秘密参数、连接引用、内容引用及变体引用；正文与大二进制不塞入该策略库，秘密不进策略版本或诊断。Bot 自定义指令暂保留在既有 per-Bot / per-project 原存储槽位，不在这里建立第二真源。

全局默认、安装目录、Bot 策略、有效连接、内容来源分别有版本；运行视图携带相关版本向量。历史快照仅保存可审计引用、版本与必要的安全摘要，不冻结权限，不复制 token，也不把诊断当作执行 Evidence。跨存储更新需要验证所有引用已持久可用后再提交绑定；中途失败保留旧有效绑定，孤立资源由所有者感知的生命周期处理。

各类数据的持有方明确如下：

| 数据 | 真源与存储边界 |
| --- | --- |
| 共享定义、共享默认与非秘密配置 | 现有 MCP registry／Skill 安装管理 Module 的版本化配置；扩展字段须有 schema 与迁移，不由 Bot 策略库代持全局真源 |
| Bot 覆盖与引用 | 本节的设备本地绑定库；主体和 revision 均由宿主验证 |
| 共享或外部原始资料 | 保留原文件／知识库／MCP 资源来源；绑定保存引用，读取仍经原 Provider 与权限链 |
| 新建的 Bot 专属正文／Skill 变体 | 拟在 `project-runtime/bot-content/<ownerKey>/` 管理不可变内容版本及来源元数据；ownerKey 为宿主验证主体后生成的本地不透明键，路径本身不是身份凭证 |
| 自定义指令与秘密 | 分别沿既有 per-Bot / per-project 原存储与现有 Vault；不复制进内容目录或策略历史 |

专属内容的管理接口须复用受治理的文件／内容 Provider，校验 owner、允许的文件类型与大小、路径归一化及符号链接边界；renderer 只提交 typed 内容／引用操作。内容路径与索引写入均需登记数据域，不能因已建立目录就绕过权限；不可变版本必须在绑定提交前完整持久化。删除与回收不得破坏仍被有效任务／快照引用的版本；取消共享或删除正文时，未交付内容的准入仍按当前事实停止。

编译视图前后核对相关版本向量，异步读取期间变化则只允许在请求未发送前有界重新装配，无法取得一致视图时返回 unavailable。不得重发已发送请求或重跑已派发工具来修正混合版本。通知与缓存失效按实际受影响的主体／绑定处理，不清空不相关 Bot 的配置或批准。

读操作无写副作用，不因目录缺失清理配置。库损坏、未知 schema、权限／磁盘错误返回 unavailable，不重建成空库。无记录的兼容默认需在主体与存储健康均确认后才能解释；被删除的主体不以另一 Bot 或全局默认兜底。

## 8. 投影、上下文与执行链

```text
已有 Capability Provider → Manifest／已安装目录
  → 宿主解析当前主 Bot 身份
  → 设备／原有工作区资格 + 共享默认 + Bot 覆盖
  → 同一份 EffectiveBinding 与版本向量
      → 工具：Runtime Projection → Tool Call → 当前绑定再校验
              → 原角色／计划／租约／取消／PermissionGrant → Provider → Evidence
      → 内容：已注册 Context Source → 原信任层／来源／预算准入 → System Context
```

- MCP 关闭覆盖该绑定的工具、资源发现／读取、prompt 入口及缓存索引；未支持的面明确列为覆盖缺口，不默认开放。resources／prompts 的实际能力仍需走现有治理入口。
- Skill 关闭同时裁去工具、自动发现／提示及按需加载入口。明确写入某 Bot 的独立自定义指令不是可被自动删改的 Skill 正文。
- 执行复核放在共享投影／Provider 准入 seam，Desktop／TUI／CLI Bot 宿主共用；不能只在 renderer 或 Desktop 的 `mcp__*` 名称路由前补判断。
- 旧 transcript、模型猜测、压缩摘要、隐藏入口及缓存调用仍可能提出已关闭的工具；不能声称“投影移除了，所以绝不可能收到调用”。宿主必须拒绝，且不弹无意义审批。
- 有效视图和私有缓存的复用键包含主体、绑定及必要版本；不能把未经 Bot B 重新裁剪的 Bot A 有效工具 schema、私有检索结果或连接状态交给 Bot B。公共不可变定义可共享缓存，仍须按各自身份编译。
- 工具被拒／执行结果继续使用既有结构化 ToolResult／Evidence 约定。配置审计不是工具 Evidence；没有执行不能伪造成功或已完成。

## 9. 生效边界、撤回与恢复

### 9.1 两种时间尺度

配置提交是新版本的生效点。能力／权限边界按当前版本检查；指令／内容按受治理快照进入模型，二者不得混为一个“下轮生效”。

| 对象／阶段 | 生效规则 |
| --- | --- |
| 新逻辑回复／新任务 | 读取当前 Bot 配置，按既有策略装配工具与内容；挂载仍不自动加载全部正文 |
| 当前已发送的模型请求 | 不修改已发送上下文；记录实际使用版本，不重发请求来假装从未看到旧内容 |
| 同一回复的请求重试、调度让出与压缩续接 | 自定义指令及已准入内容快照保持；工具的当前可见性、连接及权限仍重新检查 |
| 子任务后续模型请求 | 回读主 Bot 当前能力边界；其同一逻辑回复内容快照按上条保留，新逻辑回复取最新内容 |
| 已生成但尚未派发的调用 | 执行前按当前绑定检查；关闭、换连接、失效引用不能按旧配置派发，也不能自动转发到新账号 |
| 等待审批、队列、连接／授权／资料读取期间 | 等待结束和副作用前重检主体与绑定版本；旧批准不因重新启用而复活 |
| 已开始执行 | 不承诺撤销已发生行为；可取消部分沿原 Provider 合同处理，不默认杀掉共享进程或重跑命令 |
| 结果／资源返回但尚未交给模型 | 按既有输出交付 gate 检查当前可交付性；失效则保留执行记录、结构化结束当前交付，不悄悄泄露到另一 Bot 或新连接 |

连接／配置的最新边界与旧请求里模型看到的描述不一致时，旧调用返回 configuration_changed／binding_changed 等原因；新配置从后续重新装配的合法请求使用。参数、资源范围及账号必须按批准的绑定匹配，不能在同一旧调用上“热替换”。

快照保留的是实际已准入的指令／内容及其版本，不冻结 `tools.registry`／`skills.available` 等当前能力目录。下一模型请求的工具与自动发现提示按最新边界重建；未发送过的 Skill 提示／正文不得借旧快照首次准入。已发送的历史 Skill 内容可作为历史连续性保留，但不能恢复其工具、资源访问或审批资格。

### 9.2 动态继承与快照一致性

子任务不复制主 Bot 的永久开关或独立提权策略。每次投影与执行复核复用同一个可信父链解析；跨 workspace／Bot、断链、循环、超限、临时复核角色及历史展示与当前执行的区分沿 ADR 101 的宿主契约，不增一套宽松解析器。

能力关闭后，保留历史消息和已发送模型上下文是连续性事实，不等于继续授权。关闭资源后的检索缓存不得再次准入新上下文；压缩／恢复不能绕过新的撤回事实加载未交付内容。重新打开后重新准入，不自动恢复过期批准或重放旧调用。

共享包／内容版本更新时，已有快照必须可定位到原版本或原已准入结果；不能只保留一个会指向新正文的可变路径。旧版本无法恢复时明确暂停并说明缺失，保留任务和成果，不无声换版本。自定义指令沿用当前逻辑回复已准入的 System Context 快照规则，不重新启用旧全局个性化注入。

### 9.3 停止、任务与故障

- 暂停／取消、租约丢失或主体更换后，任何晚到的读取、连接或刷新结果都不能重新启动调用。
- 配置失败只阻断相关能力或受影响的请求；不得为“修复配置”重新派发已完成 Worker、复制任务、清零预算、丢弃工具结果或改写验收事实。
- 不可用项不自动改用另一账号、连接、Skill 或资料。重试从原检查点与已完成事实继续；如需替换配置，由用户明确保存后在合法的新请求中使用。
- 结构化错误至少区分 invalid_identity、capability_disabled、binding_missing、configuration_invalid、credential_unavailable、binding_changed、content_unavailable、policy_unavailable。界面说明发生了什么、保住了什么以及应到哪里处理，不泄漏凭据或其它 Bot 的私有路径。
- 部分 Provider 无法撤销正在进行的外部动作时记录真实覆盖限制；不以一个统一取消动画宣称所有副作用都已撤回。

## 10. 目录变动、迁移、复制与导出

### 10.1 默认全开与既有配置

- 已有／新建 Bot 无覆盖记录：继承主体可用的共享扩展，默认 enabled；保留原全局／工作区资格、同名 Skill 选择及权限档位。
- 新装合格共享项：已有 Bot 默认继承，不生成固定的已启用快照。需要凭据、必填参数或信任处理时显示待配置，不假装已经可调用。
- 新建 Bot 专属项：只归其 owner，不对其它 Bot 默认全开。共享内容也不因文件恰好位于同一磁盘目录就自动公开。
- 旧关掉名单若已有真实落盘数据：幂等迁移为对应限定引用的 disabled，不依赖当前目录在线；无法唯一解析的旧 ID 保留待映射，禁止猜测后启用。
- 默认全开不改 ADR 101 的新 Bot 权限初始化规则，也不自动把旧全局个性化文本复制到所有 Bot。

### 10.2 卸载、缺失与重新安装

读取目录不清除覆盖或私有绑定。暂时不可发现、扫描失败、卸载和缺权限分别展示原因。真正卸载后保留 missing 引用及显式关闭决定；重新安装可信相同身份的兼容版本仍保持 disabled。相同显示名不能证明是相同能力，身份／来源变更需映射或作为明确的新安装项处理，不暗中复用旧批准。

目录刷新不能清空离线实例的全部设置。删除覆盖／变体／私有内容是单独的本地用户动作；共享内容不能随某 Bot 删除而删除，仍在任务中被引用的历史版本按原留存合同处理。

### 10.3 可移植声明与本地绑定分开

设备安装实例、凭据／连接引用、绝对路径、策略版本、PermissionGrant 与 Evidence 不进入可移植 BotProfile。本 ADR 不在通用 profile 更新入口开放这些字段。

未来允许携带逻辑能力需求、非秘密参数模板与用户明确选择的内容包；这些是可移植声明，不是新设备的已授权／已安装事实。此能力需先落专用 schema、导出清单、来源与脱敏规则及导入映射，不能直接将本地策略库打包。当前阶段不宣称已有该导出能力。

同设备复制 Bot 或跨设备导入时，默认只继承合法共享项；专属引用不得指向原 Bot 的私有存储。显式携带的绑定需求若无法映射，显示待映射并保持该需求阻断，不退回共享账号来伪造成功。专属内容只有明确选择复制后生成新 owner 引用；权限仍按 ADR 101 初始化。换机无任何绑定声明的旧 Bot 继续默认全开兼容。

## 11. 产品表达与多入口

本节约束未来实现，本轮不改界面或覆盖矩阵。

- 全局能力页保留安装、更新、卸载、共享连接和已有设备管理入口，清楚标识共享影响；不把 Bot 私有配置冒充全局默认。
- Bot 设置提供“能力与内容”：可管理项完整可见，分别显示实际启用、继承／覆盖来源、当前连接／变体及待处理原因。关闭项留在列表中，可恢复；被上层约束时说明来源。
- 采用共享组件表达三态与字段继承，不要求把三个状态都做成并列按钮；圆角、SVG、键盘／焦点、草稿、读取／保存反馈、动效及减少动效遵循当前产品规范。
- 保存回执来自宿主事务；失败保留当前草稿和已保存值，CAS 冲突展示最新事实，不静默覆盖。切 Bot／窗口与晚到结果按身份隔离，不在对话中插入短暂保存小字。
- 内容区区分共享引用与本 Bot 内容；自定义指令复用原设置入口，不出现两份编辑器或另一个“全局个性化”。删除引用、删除正文、卸载能力说明不同作用。
- 子任务只读展示继承来源与实际不可用原因；不新增子任务独立配置写入口。缺身份时显示无法确认，不假装继承成功。
- Desktop／TUI 等执行宿主必须执行同一准入规则。首期配置写入口限已授权的本地管理面；TUI／CLI／远程没有写入口时可按现有访问授权只读，不新增远程编辑／批准 API。
- Quick Chat、Automation、恢复与经典独立会话均按其真实身份处理；同路径的独立会话不自动继承某 Bot 的私有绑定。

## 12. 实施分期与退出条件

实施前再次核对实际代码、目录、ADR 101、[ADR 58](58-local-skill-scope-and-workspace-mounting.md) 与当前体验规范。分期不能用来绕过共享宿主或执行复核。

| 阶段 | 交付范围 | 必须保持的边界 |
| --- | --- | --- |
| A：基础身份与挂载 | protocol 限定引用／版本／失败类型；共享 Module、CAS／迁移；完整管理列表；MCP／Skill 工具及内容投影、执行再校验；Desktop／TUI 同链 | 默认全开、旧 Skill 规则兼容、关闭可恢复、不产生权限；无绑定功能的宿主不能宽松回退 |
| B：Bot 独立配置 | 共享默认与字段覆盖 schema、连接引用、实例隔离、凭据归属与配置变更失效 | 不改变公共原包、不串账号、不支持的覆盖明确拒绝 |
| C：专属内容 | Skill 变体、共享／专属 ContentRef、来源／预算与版本快照；接已有自定义指令、检索与内容存储 | 不重开旧全局指令、不把资料当系统指令、不扩大访问权限 |
| D：可移植声明 | 专用可移植 schema、明确选择的复制／导出、导入映射及兼容处理 | 不携带本机秘密和授权、不让缺失需求静默变成共享绑定 |

A 只能称为挂载子集，不能宣称已经实现每 Bot 独立配置和内容。每阶段在原有文件边界落 Interface 与 adapter，不扩张 god module，不在 renderer 使用 fs／进程／秘密存储。

普通开发按当前 Validation Scope 审阅内容与 diff；需要的契约／边界用例随实施补充，除用户明确要求外不自动运行测试、构建或截图回归。实施产品面时再更新对应覆盖矩阵；发布或 RC 在最终合并候选上执行完整构建、测试、类型／架构／IPC 与产品回归，记录真实 Provider、安装包、辅助技术及审阅独立性限制。

## 13. 必须验收的反例

| 场景 | 必须证明的结果 |
| --- | --- |
| 旧 Bot、新 Bot、新共享安装项 | 无覆盖继续默认全开；原工作区／设备资格和权限仍有效；无凭据不显示 ready |
| 三态与字段覆盖 | inherit 跟随默认、enabled 可覆盖软默认、disabled 保留；不能越过硬限制；恢复继承不改全局 |
| 旧 Skill 挂载 | 旧工作区显式启用优先关系、原工作区关闭、同名版本优先及旧名单迁移均无隐式重解释 |
| A／B Bot 隔离 | A 的开关、参数、Skill 变体与内容修改不改 B；Bot 专属新项不进入其它 Bot 默认目录 |
| 多账号／资源范围 | 同一 MCP 定义不同账号／目录／租户不会共用错误会话；相同安全配置才允许实例复用 |
| 名称冲突与身份 | 同名、重命名、不同来源及清洗后同别名不串绑定；客户端伪造 owner／父链拒绝 |
| 关闭完整性 | MCP 工具／资源／prompt 入口及 Skill 工具／提示／加载入口同时受控，内置能力规则不被改写 |
| 管理列表 | disabled、missing、needs_login、invalid 配置仍可见、可恢复；运行时不可用项不投影 |
| 卸载／离线／重装 | 扫描失败不清空配置，卸载保留记录，相同身份重装保留关闭；不复活旧许可 |
| 子任务继承 | 已创建 Worker／Verifier、嵌套任务、临时角色、恢复与宿主切换使用同一主 Bot 边界；角色只读继续成立 |
| 中途关闭或换绑定 | 已提出未派发调用、等待审批／排队／授权刷新／资料读取后都复核；旧调用不转发到新账号 |
| 降后升与并发 | 旧批准不因重新启用复活；两窗口 CAS、另进程修改及晚回执不覆盖新事实 |
| 上下文快照 | 修改指令／内容不改当前已发送请求或同回复重试快照；新回复取新版本；工具撤回仍立即约束后续执行 |
| 内容撤回与恢复 | 未交付资料／缓存不再准入；旧版本可定位或明确暂停；不伪称能抹去模型已看到的内容 |
| 故障与损坏 | 无记录与损坏／未知 schema／磁盘错误分开；无效身份、缺失引用不回退另一 Bot 或默认共享连接 |
| 任务连续性 | 停止／取消／失去租约后晚结果不重启；保留任务、预算、检查点、已完成写入与原 Evidence |
| 可移植与删除 | 不导出秘密／授权／绝对路径；缺失声明待映射；复制不串专属存储；删 Bot 不删共享内容 |
| 多入口与表达 | Desktop／TUI 同一执行策略，远程无新增写权；错误／保存／继承来源准确，键盘与草稿／焦点／读位保持 |

每项以实际结构化事实、ToolResult、PermissionGrant、Evidence 和来源版本证明。模型口头承诺、开关颜色、安装成功或单个 happy path 都不能替代验收。

## 14. 备选方案与明确不做

| 方案 | 结论 |
| --- | --- |
| 每 Bot 复制整套安装、连接和内容 | 不作为默认：重复维护，公共更新困难；仅需要专属实例／变体时隔离相应对象 |
| 只保留关掉名单 | 作为旧数据迁移来源；不足以表达配置覆盖、连接与内容，不能充当完整目标设计 |
| 为所有 Bot 固定保存启用快照 | 拒绝作为兼容默认：新共享安装项不再自动可见，违背默认全开；本期不新增固定集合模式 |
| 只改提示词或隐藏控件 | 拒绝：不能约束旧调用、跨宿主、资源读取、缓存或权限 |
| 所有配置与权限装进 BotProfile | 拒绝：可移植声明、本地绑定、秘密和授权需分开；不新增通用 profile 越权入口 |
| 只在 Desktop 按工具名判断 | 拒绝：共享宿主／Provider seam 才能覆盖实际执行，不按模型文本宣称身份 |

不在本 ADR 引入工具级新 Bot 编辑器、每子 Agent 独立提权、任意 Provider 参数注入、远程管理写权限、OS 沙箱、跨设备秘密同步或独立执行通道。未来扩展须先明确 Interface 和治理边界。
