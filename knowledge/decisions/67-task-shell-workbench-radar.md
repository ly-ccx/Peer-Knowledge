# 67. 任务壳 + 工作台雷达（原型 A）

创建时间：2026-08-22
最后更新：2026-08-22

## 状态

Accepted。阶段 A 已在 `peer_agent` `0.0.6` 交付（C 级 UI，未改 protocol / Evidence / Git 闸门）。

## 级别

A 级 —— 锁的是产品信息架构与用户称谓，不是运行时契约。后续壳层改动不得回到工单台或把工作台当成默认家。

## 背景

2026-08-22 改造草案要把已有治理链抬成第一眼结构。当时代码默认落地已是任务页，工作台也在，但侧栏没有任务树和待办计数，待验收没有「标准 × 证据」，点工作区会把人赶走。

对照了三套壳：

- A：任务是家，工作台是雷达
- B：分栏收件箱 / 工单页
- C：任务顶栏雷达，不单独开工作台页

## 决策

1. **产品面只说任务。** 实现名可以继续叫 `conversation`。
2. **主壳锁定原型 A。** 主区默认当前任务；侧栏工作台常驻 `需要你 N · 待验收 M`；Workspace 下挂可折叠任务树。
3. **工作台不是唯一入口，也不是默认落地页。** 第一期不因有待办把落地改回 `home`。
4. **从雷达点进去必须落回原来的任务或验收对照。** 禁止另起无历史工单页。`result_ready` 先看依据，确认验收只出现在看过之后。
5. **点工作区只激活新任务落点**，不跳走。
6. **轻量问答不进待验收。**
7. **不做原型 B。** 原型 C 的顶栏计数可以后用，不能替代独立工作台页。

完整路线、阶段 B/C 与 Git 拍板见 `design/product/peer-transformation-charter.md`。

## 后果

- 任务顶栏不再挂「待用户验收 · 任务详情」平行入口。
- 验收抽屉是对照页，不是第二套聊天或计划说明书。
- 「确认验收」写 `resultAcceptance`；有隔离工作树时，签字才是交回闸门。
- Git `baseBranch` 不在本 ADR 的交付范围内。关闭时 evidenceRefs 强制校验已在阶段 B 落地，见改造总纲与 `acceptance-close-gate.ts`。
