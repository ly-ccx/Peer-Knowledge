# 84. 机器人列表壳：工作台不再是页面，应用本身就是机器人列表

创建时间：2026-09-26
最后更新：2026-09-26

## 状态

Proposed。四项选择由用户拍板（2026-09-26）：没有文件夹时自动建受管文件夹；档案默认收起、按需滑出；列表按最近活动排序；不做市场。实现未开工。

落地修订见 ADR 85：机器人档案存 `projects/<workspaceId>/profile.json`，不写进工作区条目（决策 7）；机器人模式首启不再自动建 `~/PeerAgent`，老的 `~/PeerAgent` 迁为普通绑定机器人，旧会话迁为历史对话，经典界面开关保留到 0.1.x（决策 10）。

## 级别

A 级。锁定产品信息架构（壳层），部分取代 ADR 67 与 ADR 80 的壳层条款；新增受管文件夹这一存储位置。

## 背景

ADR 80 的壳是「左栏项目列表 + 中间代理对话 + 常驻右栏（任务 / 目标 / 记忆）+ 工作台降级为角标与收件箱」。用户参照即时通讯式的机器人产品，提出更彻底的形态：每个机器人负责一个项目，左边就是机器人列表，点进去就是对话；工作台不应该再是一个需要单独去看的地方。

## 决策

1. **应用就是机器人列表。** 一个机器人 = 一个项目的项目代理（ADR 80 的一对一关系不变）。默认两栏：左边机器人列表，右边当前机器人的对话。
2. **工作台不再是页面。** 原工作台的职责拆到列表上：
   - 需要你：机器人行上的深色数字角标，加列表顶部的「需要你 N」筛选；
   - 推进中：头像旁的进行中标记与预览里的「推进中 N 条」；
   - 待验收：大部分已由策略代签取消（ADR 80 决策 8），需要你确认的并入「需要你」；
   - 任务清单与历史：机器人档案 → 任务；
   - 跨项目查找：顶部搜索，覆盖所有机器人的消息、任务与记忆。
3. **机器人行。** 头像、名字、最后一条消息预览、时间，右侧状态（需要你角标 / 未读小圆点 / 进行中）。排序按最近活动。
4. **身份。** 每个机器人有名字和头像：名字默认取文件夹名，可改；头像由 `workspaceId` 确定性生成（形状 × 颜色，彼此易区分），可改。身份只用于辨识，不代表不同的能力或权限。
5. **档案按需打开。** 任务、目标、记忆与机器人设置收进「档案」，从右侧滑出，默认不占位：概况（绑定文件夹、项目简报、在推进的事）· 任务 · 目标 · 记忆 · 设置（名字与头像、模型分工覆盖与模型范围、这个机器人的主动性、权限）。对话里点「来源：某任务」直接打开档案并定位到任务现场。
6. **新建机器人（+）两条路：**
   - **绑定已有文件夹**：选文件夹，机器人就位，先只读熟悉项目（产品稿 §1.1）。
   - **新建空白机器人**：输入名字，自动在 `~/Peer/<名字>/` 建一个受管文件夹作为它的项目（重名追加序号）。熟悉项目时发现是空文件夹，就直接问「这个机器人主要负责什么」，回答记为「你说的」职责记忆并固定进项目简报；要不要在文件夹里建 README 记录职责，由代理提议、你同意后以任务方式执行。
7. **不做市场。** 没有机器人模板、没有模板市场；新建机器人只有上面两条路。现有技能 / 插件的管理入口保留在设置里，不作为列表页的主入口。
8. **主动消息在对话里。** 目标触发、今日小结等主动消息按时间出现在该机器人的对话中，带时间分隔；是否推送、是否只进对话，按 ADR 80 决策 9 的送达规则。每个机器人可以单独设置主动性（含静音），默认跟随全局。
9. **受管文件夹的边界。** `~/Peer/` 是用户可见的普通目录，不是隐藏数据目录；受管文件夹与绑定的已有文件夹在能力、权限、证据上没有区别。删除机器人不自动删除文件夹（二次确认后才删受管文件夹）。

## 被取代与保留

| 原条款 | 本 ADR 之后 |
|---|---|
| ADR 80：侧栏是项目列表，每个项目带「需要你 / 待验收」角标 | **改写**：侧栏是即时通讯式机器人列表，行上显示需要你 / 未读 / 进行中；顶部「需要你」筛选 |
| ADR 80：常驻右栏（任务 / 目标 / 记忆） | **取代**：默认两栏；档案按需从右侧滑出 |
| ADR 80：工作台降级为角标与全局收件箱，独立页进入退场评估 | **取代**：工作台不再是页面，职责全部落到列表与档案 |
| ADR 67：主区默认当前任务、侧栏工作台常驻计数 | 继续被取代（已由 ADR 80 部分取代） |
| Muse 调研：代理命名 / 头像不采纳 | **改为采纳**：列表形态下身份辨识是刚需 |
| ADR 80 决策 1：一个项目一个项目代理；不做多个常驻机器人共管一个项目、不做机器人之间互相聊天 | **保留** |
| 任务、验证、签收、记忆、目标、模型分工的全部契约 | **保留**，只改变它们在界面上的位置 |

## 后果

- 用户的日常动线变成即时通讯的习惯：看列表 → 点有角标的机器人 → 在对话里处理。没有「去工作台看看」这一步。
- 远程 / 手机入口（路线图 #4 / #4b）天然对应：机器人列表 + 对话，是手机上最熟悉的形态。
- 非代码的事（研究、写作、个人事务）也能有一个项目：受管文件夹。产品人群仍以本机工作委托为主，不因此转向消费级助手。
- 界面实现：新建机器人列表与档案组件（`apps/desktop/renderer/src/project-agent/`）；旧 `Sidebar.tsx`（工作区 + 任务树）与工作台页面在开关打开时隐藏，关闭时照旧；第 5 阶段默认开启后退场。
- 数据：工作区条目增加 `displayName`、`avatar`（形状与颜色，或用户上传的图片引用）与 `managed: boolean`；受管文件夹根目录 `~/Peer/` 需要登记（可配置位置）。

## 不做什么

- 不做市场、不做机器人模板。
- 不做多个机器人共管一个项目，也不做机器人之间的群聊或互相派活。
- 不因为有了头像和名字而引入「人格」层面的能力差异；能力差异只来自项目、记忆、模型分工与权限。
- 不自动删除受管文件夹。
