# ADR 95：以实际进展驱动持续执行

创建时间：2026-10-18
最后更新：2026-10-18
状态：Accepted（用户确认六项方案并要求执行）
级别：A（执行预算、持久恢复及投影契约），B（协调与核验运行时）
关联：ADR88、91、93、94。本决策取代 ADR88 §8 的系统默认工作总额、ADR93 的核验累计次数和总截止硬停止；用户明确预算及单次调用超时仍有效。

## 1. 现场与目标

安装版 RC15 的一项工作累计 256 次模型请求、468 次工具调用，触发程序写死的 256/2048 默认工作硬上限。主 Bot、子任务、重试和核验共用累计计数，子任务返回后主 Bot 也可能无法处理结果。Renderer 仍显示“继续尝试”，宿主却因原上限未增加而拒绝。上限来源是系统默认，不是账号余额；此表达和生命周期与持续委托冲突。

目标：默认情况下，仍有实际进展和明确下一步的工作持续推进；在安全边界让出并从检查点继续。异常重复停止具体执行分支，主 Bot 保留接手与说明责任。用户明确设置的次数、Token、费用上限及 Provider 硬拒绝继续执行。保留真实用量、PermissionGrant、Tool Result 与 Evidence，不以删除计数恢复任务。

## 2. Module 与 Interface

| Execution Continuity | 现有 yield/checkpoint、Progress Fingerprint、技术阻塞接手与事件唤醒；循环无进展不能因 UUID、重启或换叙述清零 | Runner/Continuation/Repair 与 Session Supervisor |

不添加存储路径、IPC 或本地能力旁路。所有工具仍经过 Provider → Manifest → Projection → Tool Call → PermissionGrant → Evidence。策略事实通过既有执行画像/上下文通道传递，不拼接新系统提示。

## 3. 执行与保护

1. `modelRequests`、`toolCalls`、Token、费用等累计事实照常保存。只有存在显式有限上限时才判断预算耗尽，策略来源持久化。零上限仍为禁止执行，不按无上限处理；未知费用/Token 不按零计。
   显式 Token/费用预算由另一执行占用的剩余额度必须单列为临时 reservation；释放后重新按实际累计用量准入，不要求用户提高原上限，不将占用误报为已经耗尽。
2. 每片执行后保存已配对 Tool Result、Evidence 和 native checkpoint，释放执行机会。不能将片段结束投影为整件事失败，不设置另一个累计默认上限替代 256。
3. 等待推进中的子任务沿 ADR94 静默等待；结果事件自动唤醒。新的失败、结果、用户输入不能被静默吞掉。
4. 无进展沿现有事实指纹、目标版本和执行主体持久记录；排除随机身份、时间与重复顺序。反复同一错误、空回应、相同读结果或同义汇报不能续租。停止问题任务/尝试，主 Bot 可按既有协调能力查询、取消、修复或替换；不得循环重派同一失败来清零保护。
5. 显式工作预算达到或 Provider 额度硬拒绝时，不额外调用模型来汇报。宿主用已有记录生成具体未完成回执与可行恢复动作；不伪造模型结论或签收。无显式预算时，一个任务的无进展/核验故障不耗尽其他任务和父 Bot 的处理资格。
6. 单次 Provider/工具调用仍有截止；挂起和超时产生结构化结果并回到协调生命周期。核验总运行时间改为可续接切片，不以 5 分钟累计截止结束正常审查；旧检查点恢复时保留用量和事实，重建单片期限。

## 4. 旧任务迁移与恢复

- v1 系统默认来源且保存的次数上限精确等于 256/2048、没有 Token/费用上限、当前没有显式预算时，才认定旧系统默认停止。不同数值、显式配置或不明来源保守保留硬限制。
- 追加 v2 策略与迁移回执，保存旧上限、原因和时间；不改写历史会话、卡片原文、累计用量和工具执行记录。
- 在持有租约的协调恢复阶段重新检查取消/暂停、真实人工等待、未配对或未知执行结果及检查点。只有准入成立才能恢复；不直接在预算注册时把终态改成 runnable。
- 已有子任务结果时处理待交付结果，仍运行时静默等待；被旧默认次数限制中断的执行从可靠检查点接续，不重新执行已完成写入。
- 真实用户数据只读用于诊断；实现和验收使用隔离副本/临时目录。安装新版后的宿主按上述逻辑自动迁移，不在开发阶段直接操作正在运行的用户任务。

## 5. 表达与恢复动作

- 默认系统次数限制不再出现“执行额度已用完”。真正显式预算停止要说明预算类型、已用/上限和来源。
- 宿主返回结构化可恢复事实。继续按钮仅在能从当前安全检查点恢复且准入允许时显示；预算未调整时不显示注定失败的重试。
- 取消、暂停、历史失败、主 Bot 回复和子任务执行沿 ADR94 独立表达。新回合或迁移不代表成功恢复，只有同工作正式回复实际送达才显示恢复成功。

## 6. 实施范围与顺序

代码分支沿用当前 PR163，知识变更沿用 PR43。允许修改 Protocol 的工作预算/恢复投影类型；runtime-node/project-agent 的预算策略、Guard、协调恢复、核验、会话故障及其测试；Desktop 的既有 Provider/核验适配、事实投影、Renderer 状态和 i18n；标准产品回归夹具及检查。优先新深 Module，避免增长中央宿主与大 React Surface。不开新能力或 IPC，不安装、不合并、不发 RC。

顺序：ADR → 回归复现 → v2 策略/迁移 → 核验切片及分支故障 → 宿主恢复动作和界面 → 定向/全包测试 → 标准 Capture/逐图审查/Verify → 证据及覆盖限制。

## 7. 验收

- 超过 256 次模型请求、2048 次工具且有新事实的生产链路任务不会被默认截断，能交付；明确上限仍在边界拒绝，不增加额外模型通知请求。
- 核验跨原 96/512 与累计 5 分钟边界保存结果继续；请求/工具超时、取消、源版本、模型、租约变化、未知派发和检查点缺失仍拒绝不安全重放。
- 重复同事实/同错会停止问题分支，父 Bot 能接手，无关子任务继续；重启、UUID 或同义回复不重置。
- 旧默认 budget_limited 的隔离工作副本恢复，计数和证据不丢、已完成写入不重放；显式预算、暂停、取消、权限拒绝、未知结果及不明来源不误恢复。
- 宿主动作投影与实际 retryJob 准入一致；真正预算停止不能显示无效“继续尝试”；错误原文留在详情。
- 受影响包全量、typecheck、architecture、CI。标准产品 Capture 全图实现者自审及 Verify；明确受控认知、源码 Electron、非独立审查和安装版覆盖限制。

## 8. 取舍与回滚

默认持续执行依赖现有无进展、调用超时、并发调度和取消机制，不能承诺模型永远选对步骤。已有 Evidence 只证明动作事实，不等同语义完成；质量签收闸门不变。无用户预算时仍记录资源使用，不宣称费用为零。

回滚不得擦除用量或 v2 迁移回执。旧二进制不具备 v2 兼容判断，不能承诺它会安全恢复迁移后的工作；需要先停止宿主，再使用支持 v2 的修复版本，不能将旧默认值重新套用或重放动作作为回滚步骤。实际 Provider 额度和显式用户硬预算始终独立生效。
