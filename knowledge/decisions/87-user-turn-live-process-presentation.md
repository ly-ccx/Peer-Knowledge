# 87. 用户回合可展开的实时过程

日期：2026-10-05
创建时间：2026-10-05
最后更新：2026-11-09（追加过程叙述与正式交付分离修订；同日经用户（负责人）接受，D1 表"接受本草案后修订的范围"列所列条款替代生效；实施未完成，V01–V17 待验证）
状态：Accepted
来源：负责人要求修复 RC6 的静态思考提示，并参照提供的 Codex 截图实现进行中扫光、本轮过程与嵌套详情。
级别：A（ProjectAgentActivity 展示协议）；档位保存与几何稳定性为 C。

## 决策

在 ADR 85 的既有 TurnSink → ProjectAgentActivity → 主窗口展示链上增加有界工具展示预览。该决定替代 ADR 85 流式边界中“工具参数、结果、路径不进入摘要”的限制，只对同一用户回合的本机展示生效。不增加 IPC、工具、执行器、权限或持久存储。

- 每个工具保持 toolCallId、名称、准备/执行/完成/失败/停止状态，实际事件时间，以及可选对象摘要、参数预览、返回预览。事件时间沿用 Runner 的时钟 seam。只有 tool-call 可进入执行中；参数生成进度称准备中，不称文件已读取。
- 预览 Module 统一递归过滤凭据/认证/隐藏 reasoning 字段与密钥模式，限制深度、节点数和字符串长度。单参数最多 2,000 字符，单结果最多 4,000 字符，一回合预览累计最多 32,000 字符，条目仍受既有 100 段上限。截断和脱敏必须明确标注。快照只含不可变字符串/标量，调用方修改副本不影响宿主。
- 正文/commentary 仅来自可见 delta 和既有 post_reply 字符串进度。内部 thinking 内容永不展示；没有公开内容时显示“等待模型返回可展示内容”，不编造思考过程。post_reply 的参数和结果不作为普通工具过程展示。
- 主窗口可按需展开实时步骤与每一步详情。默认一行当前动作加耗时，使用低对比文字扫光，无卡片光晕；完成/失败/停止及 reduced-motion 停止移动。展开读取现有快照，不发起能力执行。程序可读状态和键盘展开必须保留。
- tool-result 结束对应步骤；停止/失败会将尚在进行中的步骤转为停止/失败。失败撤销未接受的回复预览，但保留已发生工具的有界过程。disposed 清理所有预览；恢复/重试清理本次尝试，不把旧结果拼进新尝试。旧 turnId、静默唤醒与低优先送达仍按原可见性边界拒绝。
- 正式回合记录仍为历史真源，实时快照仅用于当前回合展示。消息交接后使用既有 agent_turn rounds 查看历史过程，实时与历史统一复用 protocol 内的纯展示预览函数；历史展示也遵守同样的脱敏、条目和累计预算，不改变存储事实。不能把瞬时预览当 Evidence、执行成功或用户验收。

## 档位稳定性

滑块提交保持用户选择直到现有异步保存结束，保存失败回退实际配置并展示已有错误。提交期间阻止重复提交，标签预留最长档位宽度；弹层观察自身与触发器尺寸。不得用 renderer 乐观值充当实际生效模型的真源。

## 验证

协议/投影测试覆盖真实调用前后、参数进度、嵌套拒绝、停止、失败、恢复、乱序、静默、隐藏 reasoning、凭据过滤、截断与总预算。正式 Electron 的受控认知夹具覆盖等待扫光、执行中展开、嵌套参数/结果、键盘/reduced-motion、完成交接、停止/失败及档位延迟保存/失败回退/几何稳定。夹具验证展示链，不宣称验证真实能力执行。

### D3. Module、事实所有者与流向

现有入口与流向：用户输入队列 → Runner/TurnExecutor → TurnSink 的公开流与工具边界 → `createTurnActivity`（`turn-activity.mjs`）→ 有界 Activity 快照 → `finishAgentTurn` / Conversation；正式回复经 Manifest → Projection → Tool Call → PermissionGrant → Evidence → ReplyComposer/协调提交与 delivery 回执 → canonical `agent_reply`；Renderer 只消费读投影。

| Module / Seam | Interface 与责任 | 不承担的责任 |
|---|---|---|
| protocol 的公开更新/Activity 契约 | 定义来源、段身份、版本、顺序、未知字段和预算；用于所有消费者 | 判定工具成功、授权或任务签收 |
| runtime-node 的 Activity 与回合收尾 | 从真实公开事件记录过程身份，沿已有回合存储保存有界过程；处理尝试隔离和公开准入 | 依靠模型自报角色或文本内容升级交付 |
| ReplyComposer / coordination / Conversation | 校验完整 Tool Result、来源与当前状态；沿原事务与投递账本提交唯一 canonical 消息 | 从 UI 参数预览推定成功，因展示变化重做工具 |
| 共享只读展示投影及宿主适配 | 关联过程、活动预览和正式消息，形成一致的正文/过程/状态视图 | 复制一套交付账本或创建第二份消息真源 |
| Renderer、TUI、远程消费者 | 渲染宿主给定的身份和状态，提供合法原操作入口 | 按语义猜重复、读本地文件或自行制造完成事实 |
| 既有 Project Agent Prompt Source | 说明简短开场、有价值进展和 post_reply 交付纪律 | 成为唯一治理门禁或新增系统注入来源 |

复用现有 seam。若需抽出共享投影 Module，其 Interface 必须一次收敛跨消费者的分类、兼容与交接规则，增加 Locality；不添加仅转发字段的包装，也不继续扩张中心 Runner 或大型 React 表面。

### D4. 身份、分类与顺序

采用“过程段”和“交付”两个对象域，不把三种身份塞回同一个 `publicUpdates` 数组：

- 过程段：既有 `id/text` 增加宿主生成的 `role: opening | narration` 及可验证的段顺序；回合记录增加展示契约版本。字段名为本草案的逻辑名，最终类型/schema及序列化必须在实施前绑定到 protocol，不使用 ad hoc IPC 对象。缺失版本属于 legacy，不猜成新版。
- opening：同一次可见回复的首个、发生于工具准备/调用边界之前的公开文本段；仅表示时序上的开场，不证明“已记住”或“已完成”。其余公开文本均为 narration。工具后真实发现同样属于 narration，交付须经 post_reply。
- 工具准备/参数进度或真实 tool-call 任一先到即关闭开场窗口；单纯 thinking 事件不展示私有内容。没有工具准备 seam 的 Provider 使用真实 tool-call 边界；不依赖 wall-clock 先后推断。
- 一个未交付回复可跨同一 work 的多个调度切片/尝试。续接不是新开场；沿既有 work 与输入锚点、回复分组关联保留开场已出现的事实。新输入/新交付的分组按已有宿主归属判断，不以同一 work、相邻时间或文字相同强行合并。
- 每个段的身份至少由所在 turnId 与段 id 区分；跨尝试通过显式来源关联。重试、discard、Provider 恢复必须沿真实事件撤回/隔离对应草稿，不能把旧尝试拼入新尝试的正文。分类事实不足时保守记为 narration，不补造 opening。
- `conclusion` 是已准入 canonical `agent_reply` 在展示中的角色，不是 delta 的自动标签。唯一性限定于同一交付 messageId；同一 work 后续真实新结果可以有另一条正式消息。ADR80 的 `reportFactKeys` 重复报告抑制继续在宿主生效；换 messageId 或改写措辞不能绕过既有事实判重。展示层保留的是宿主实际准入的独立消息。
- 答案预览以现有 post_reply 的 toolCallId 标识，宿主在正式提交后将其关联到 canonical messageId。不要从预览文字反查正式消息，不发明第二份交付 ID 或独立事实存储。

分类在真实流事件进入宿主时完成，同一身份随快照和回合记录流转，不能等收尾后才把气泡重新分类。沿现有节流推送和有界回合持久化，不逐 token 写日志。沿用 100 段 / 32,000 字符及工具预览脱敏预算，截断明确可见；不得因新增元数据绕过预算。中途崩溃可能丢失尚未落盘的临时 delta，应按现有事实显示未知/中断，不承诺完整逐字审计。原 Tool Result/Evidence/检查点的保全与恢复仍由原链路负责。

### D5. 正式交付准入与无交付处理

新契约下只通过完整、配对的 post_reply 执行回执和既有提交/送达规则建立正式答案。参数生成、收到 tool-call、UI 有界预览和模型正文都只是候选。工具返回成功、消息持久化、送达和任务签收是不同事实；正文可见性遵从原读投影与 surfacing，不能把工具成功直接当已送达或整件工作完成。

| 情形 | 正文与过程的处理 | 状态与恢复责任 |
|---|---|---|
| 正在生成 post_reply 参数 | 答案位置显示明确未提交的真实前缀预览；不另加普通过程气泡 | 保留真实生成/提交状态；无参数流能力时显示等待，不伪造逐字流 |
| 校验并提交正式消息 | 以 canonical messageId 幂等承接同一答案位置；开场与叙述转入过程 | 送达账本未知仍为未知；任务核验与签收另行表达 |
| post_reply denied/failed/cancelled/timeout/invalidated | 撤销该调用的未接受答案预览；原过程和已发生工具结果保留可查 | 显示宿主真实原因与合法恢复入口；不得从最后一段文本补发答案 |
| suppressed / silent / digest | 遵循原送达渠道及可见性，不擅自提升为前台正文 | 不能为避免空白而制造第二次交付或通知 |
| user 回合只有自然语言结束、从未调用 post_reply | 不从 `rounds[].text` 或最后一段公开文本构造新正式回复 | 新契约禁用隐式 fallback；沿既有纠正预算/恢复路径处置，仍未交付则明确未交付，不新建无限重试 |
| wake 静默等待或调度让出 | 无正式答案；按原可见性展示已有过程/状态 | 持久 wait/yield、开放责任与后续唤醒不变，不能把安静显示为完成 |
| 已提交，回执返回前断联/崩溃 | 按 canonical 消息与原投递账本读回原结果 | 对原调用 reconciliation；未核实时保持未知，不重做记忆/写操作或另发新回复 |

正式提交完成后的晚到失败只影响其所属执行尝试或后续操作，不撤销已存在的 canonical 交付；缺失送达状态仍通过原账本核对。对“未调用 post_reply”的纠正只补尚未完成的表达，不重跑本轮已配对工具，不把重启或重试当作重新执行副作用的授权。

简单问答同样通过既有 post_reply 交付，不要求先说开场；记忆更新成功后可以直接交付一次。若 Provider/Adapter 未能走该路径，明确表现为未交付的兼容失败，不能静默回到自由文本 fallback。本次不新增自然语言交付 Adapter；今后如需另开，应独立记录完整准入和审计边界。

### D6. 展示、控件、焦点与静态终态

- 生成中：一个稳定回复容器；至多一条过程摘要，过程可展开/收起。opening 可以成为摘要，narration 不再逐段生成同级正文气泡。未提交的 post_reply 答案有独立、明确的预览位置。
- 交付后：主阅读列保留正式答案、必要的状态/限制及原产物和 Evidence 入口；opening 与 narration 都归入“查看过程”。默认过程收起，用户主动展开的选择在交接中保留。正文不是“开场 + narration + conclusion”的拼接。
- 内容归档不意味着强制移动用户正在阅读的 DOM。正在选字、焦点位于过程内部、视口停在该过程时，保留原过程容器和节点到用户主动收起；答案在自己的位置承接，不能清除选择、抢焦点或自动贴底。几何变化使用既有阅读锚点策略，不靠 timer 恢复自动跟随。
- 用户收起过程后，后续 delta 不自动展开；折叠移除隐藏内容的 Tab 停靠点。用户主动折叠且焦点在内部时，焦点返回该过程触发器。新正文与历史恢复不重复播放入场或逐 token 读屏广播。
- 错误、未知效果、未验证范围、停止恢复、有效权限请求和原生用户问题保持主层可见。自然语言 narration 不会自动产生权限或问题身份；模型提出需要用户操作的问题必须经原结构化入口交付。
- 过程保留公开文本来源与顺序，内部 reasoning 永不展示；有界展示不替代完整工具结果/Evidence。没有正文的停止/失败保留未完成公开内容与真实终态；不强制折叠唯一现场，也不生成成功气泡。
- 复用 Frost、共享 SVG、现有 details/焦点/滚动/motion seam。无动画、减少动效/透明、动画 API 缺失或中断时，正文、状态、过程入口和恢复操作必须完整可用；动画不驱动提交或业务重试。

### D7. 持久化、历史兼容与已有状态恢复

1. 新记录沿既有 Conversation `agent_turn.publicUpdates` 保存公开过程元数据，canonical `agent_reply` 保存交付。Activity 是临时投影，不另建权威日志；不持久化整份高频快照，也不复制 Tool Result/Evidence。版本须覆盖字段验证、读取适配、跨宿主投影和降级写入约束。
2. 新记录恢复时只按保存的身份与原交付账本重建；工作切片/失败尝试保留来源，不清除历史、权限或未知效果。新输入仍走正常队列，旧迟到 delta/结果不得改写下一次回复。
3. 旧记录有已存 canonical `agent_reply`、明确 turnId 关联及显式 `publicUpdates` 时：只读将 canonical 回复作为答案、已存公开更新作为 legacy 过程；即使旧更新缺 role，也能消除本次三段重复，不需要猜 opening，不比较文字相似度。
4. 旧 fallback 的 canonical 回复按原身份保留并标识其来源；不追溯撤回、重发或冒称经新 post_reply 门禁。与该回复明确关联的公开更新仍可归入过程。
5. 缺正式回复、跨页关联暂缺或旧格式无法确认公开来源时：保持 legacy/unknown 的保守展示与原文访问，不从 `rounds[].text` / 私有检查点推导公开文本，不把加载中当不存在。通过已有分页/定位接口补读，来源仍缺失才明确未知。
6. 全部恢复是只读投影。个人 Conversation、输入游标、协调账本、任务、记忆、PermissionGrant 和 Evidence 原文件不改写；检查前后哈希，升级/重启前后同一交付身份一致。语义去重不参与 recovery。
7. 旧客户端可能忽略新增字段。实施必须验证未知字段的原链路行为，并沿现有格式/最低执行版本门禁阻止不理解新交付语义的旧宿主继续写入；需要回退时使用版本支持的完整一致备份。新增字段不等于可无条件降级写入。

### D8. 模型契约与字符串补丁退出

原 Project Agent Prompt Source 及 post_reply 工具说明在同次实施中对齐：多步骤任务可用一句开场确认；之后只报告有价值的新发现、变化或阻塞；正式结果与可操作用户问题通过原交付入口；简单操作可直接 post_reply。删除“逐字复用开场才能显示一次”，不增加第二处散落提示拼接。提示词减轻重复生成，宿主结构隔离提供确定性边界；不承诺模型永不复述。

现有字符串补丁在本轮方案补齐中保持原样，不宣称核实了特定 PR 的最新状态。结构契约实施时：新版回复彻底退出 `refinesText` 等相似/包含匹配；重复快照按段身份处理，重复交付按 messageId/回执处理。旧版确需保留的精确字符串兼容只存在于隔离的 legacy Adapter，并记录退出条件，不能作用于两个独立正式消息。

### D9. 实施顺序与兼容风险

1. 本草案明确接受并登记替代条款后，以去标识最小夹具固定本次事故和异常出口；记录实际候选及原失败基线。不得把本次函数重放冒称新实现验收。
2. 先定义 protocol 与宿主分类/交付准入，确保实时快照、回合持久记录及各 parser 不丢字段；沿原最低执行版本机制处理旧宿主。正文交接与失败回滚同批完成，不能只落 role 字段就开启新版。
3. 接入共享只读投影及 Desktop/TUI/远程消费者；新旧记录分别验证。保持经典模式原行为，独立正式消息不被合并。
4. 对齐 Prompt Source 与工具说明，移除新版字符串推断；跑定向宿主/契约/恢复与隔离交互验证，核对相关候选 CI。发现边界变化先修订本节。
5. 验收记录绑定候选、夹具、源数据身份和检查结果；发布仍须 merge-all PR、最终组合门禁与完整产品回归。本方案不授权发布、安装、重启日常实例或改写个人任务。

主要风险：消费者丢失新增元数据导致实时/历史不一致；“无正文”被误判为空闲或成功；自动折叠破坏读位；旧宿主静默恢复 fallback；跨切片误合并后续真实结果；有界过程被误宣称完整审计。各项必须由下表覆盖，不能靠放宽断言或文本算法修补。
