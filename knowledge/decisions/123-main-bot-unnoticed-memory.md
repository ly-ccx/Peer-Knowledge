## 背景

人在长谈里不会宣布「我现在开始压缩记忆」。刚说过的话还在，更早的事变成能接着用的印象，需要时再去回想原话。主 Bot 现在做不到这一点：窗口一满，压缩横幅、进度和一条插进记录的交接消息会让用户感觉对话被工序打断；命令行甚至下一轮又把全文带上，压缩没有留下来。

目标只覆盖主 Bot 与用户的那条会话。里面派出去的任务、子会话和 `prepare_context_handoff` 保持原契约。

## 本次修订与验证范围

本次只修改本 ADR 与图谱，不修改实现、不迁移个人数据。目标是让长谈在有限请求内连续，并保留约束、出处、用户控制及可恢复的异常出口。

2026-11-06 本轮替代本草案上一版的以下条款：

- §1 的启发式 `pressureTokens` 触发、低于 soft 时恢复全文、整理失败时裁掉未覆盖历史。
- §3 的所有情节始终入模、只缩短文字解决容量、仅凭时间先后覆盖旧事实。
- §4 的仅按已提取 `sourceIds` 回读与无短期引用续接。
- 临界点中的新输入一律取消整理、并发写输后继续使用旧投影，以及工程落点中的旧会话首轮无条件发送全文。
- 原验收中的“整理失败时用户仍能收到回复”改为：容量允许时继续回复；无法保真准入时结构化阻塞并保留恢复入口。

这些是 Proposed 方案内的修订，未替代 ADR 56、57、81、111 的现行边界。本文接受后才会改变主 Bot 新回合的分界表示与情节存储；经典对话、子会话、权限、Evidence 与系统指令层序保持原契约。本轮按文末 D1–D5 做内容、差异与一致性审阅；运行验收 A1–A16 全部待实现后验证。

## 决策

用户看见的主 Bot 记录保持原样。模型看见的是一份投影，不是第二份聊天记录。投影在桌面和命令行的 `executeTurn` 上是同一个模块。两边都不准再各自拼一段历史。

投影分三层，从近到远：

| 层 | 给模型什么 | 存在哪 |
|---|---|---|
| 逐字尾 | 最近若干完整来回，以及尚未回答的用户回合 | 不另存。每次从交互记录切出来 |
| 情节 | 更早对话的带来源陈述，按本轮相关性和预算选入；仍适用的用户约束必须保留 | 会话旁的情节全集。不写入 `user_input` / `agent_reply` |
| 回读 | 按源 id 或历史检索取回的有界原文 | 本轮事实层；后续仅保留有界的短期引用，不晋升为系统指令 |

正常整理不出现压缩横幅、整理进度或整理百分比，也不插入「已压缩 N 条」的系统句。现有上下文用量仍只消费 ADR 56 的权威快照；无新计量时保持未知/待计量语义。输入框、草稿、焦点和阅读位置不因整理情节而改变。容量确实阻塞回复时，按 §8 表达真实失败和恢复，不用“无感”吞掉错误。

### 1. 什么时候整理

常规整理发生在一轮主 Bot 回复已落成 `agent_reply` 之后，只处理已经闭合的历史前缀。它不读取未提交草稿，不依赖 renderer 报告打字状态，也不干扰输入法组字。发送前已到 hard、首次读取旧会话超窗或 Provider 返回 overflow 时，允许先整理已结束的历史，仍不得收走未答用户回合。

触发与放行进入 ADR 56 的共享容量流水线。`decideContextCompaction` 只可复用现有阈值计算，不得把该文件的启发式 estimator 升为容量权威，也不得让宿主另拼一套触发逻辑。

| 名字 | 现有值 | 含义 |
|---|---|---|
| `triggerRatio` | 0.8 | soft。`softLimit = floor(contextWindow × 0.8)` |
| `hardRatio` | 0.92 | hard。`hardLimit = floor(contextWindow × 0.92)` |
| 窗口 | 当前 Provider/model 的声明 | 未知时不制造阈值或百分比，沿用 Provider capability 与 overflow 契约 |

容量证据只接受下一份最终请求的 `nextCountedInputTokens` 和同 model、同有效 epoch 的 `lastObservedInputTokens`。前者绑定将发送的请求；后者保留已发送请求的实测与高水位保护，不能冒充下一请求的精确计数。两者携带 fingerprint、content revision、model key、来源与时间，遵守 ADR 56 的新旧证据规则。字符比例和固定消息开销只可作整理策略诊断，不进入自动触发、soft/hard 判断、请求放行或权威快照。

soft/hard 仍沿用 0.8/0.92；发送还必须满足 `inputBudget = min(providerMaxInputTokens（若有）, contextWindow - requiredOutputReserveTokens)`。阈值没到不能覆盖更小的输入预算。计数与 send 消费同一个 immutable canonical request，包含 System Context、tools、附件、情节和回读。情节覆盖边界提交推进 `compactionEpoch`，旧实测保留但标记已被替代，不得再次触发。每次投影变更重建 fingerprint 并重新计数，不能按压缩比例推导新值。

| 条件 | 行为 |
|---|---|
| 有效容量证据低于 soft，且输入预算允许 | 不新增情节。仍排除已提交情节覆盖的原文；只有无情节、无旧分界时逐字尾才是全部可准入交互记录 |
| 达到 soft，且最老的一段已经有回复、工具调用和结果成对、没有未答卡片 | 在后台把这一段收成一条新情节。下一轮起这段离开逐字尾 |
| 达到 hard、超过输入预算或发生 overflow | 在有界预检/恢复流程中同步整理已闭合范围，再重建和计数；无法安全发送走 §8，不能循环到“成功”为止 |
| 整理失败、超时、摘要为空或保真校验未过 | 不提交覆盖边界；上一份情节加全部未覆盖历史仍能准入时继续回复，否则结构化阻塞，不能只取“放得下的尾部” |
| `observed_usage_only` 或 `unavailable` | 沿用 ADR 56 §2.7：待计量/未知，不借估算放行；保留 Provider overflow 的有界恢复 |

摘要请求本身也必须能装入其模型输入预算。大范围按闭合来回分批处理，每批独立校验与提交；单个不可拆单元仍超限时进入容量阻塞，不能先发送同样超限的摘要请求。

### 2. 先分类，再写事实

一次整理只处理已结束的来回，以现有输入/回复锚点判断闭合。多条输入合并回答时作为一个完整单元；存在未答输入、开放提问或未决工具结果时，不越过该单元。先给记录贴来源，再决定能否入情节。

| 来源 | `kind` 或对象 | 进情节正文吗 |
|---|---|---|
| 用户的话 | `user_input` | 可以，标为用户明确要求或陈述，带消息 id；用户引用的外部内容仍是引用材料 |
| 主 Bot 给用户看的回复 | `agent_reply` | 只收结论和未完成项，标为助手陈述，不收内部思考，不因此成为已验证事实 |
| 工具 | `tool_call` 与 `tool_result` | 不进正文。逐字尾之外收成一条引用：工具名、一行结果、引用 id。调用和结果必须在同一边 |
| 子 Session 内部 | `work_session` 自己的日志 | 不读、不摘要。只有已经写进主会话 `agent_reply` 的那一句可以入账，并带上回复里出现的会话编号 |
| Agent 来信 | `agent_message` | 留在现有有界信箱；未关闭问题沿原结构化事实源准入并保护关联单元，不抄进情节或伪装成用户消息 |
| 工作笔记和交接 hint | `prepare_context_handoff` | 留在那个工作自己的记录里，不并进主会话情节 |

先抽取决定、未完成事项与用户点名的对象，再允许一次短模型压缩。每条保留陈述身份、源消息、适用对象/范围，以及原话中的条件、否定、例外和时间限制。源 id 必须存在于提交范围且内容哈希匹配；这只证明可追溯，不能单独证明语义正确。

明确用户约束优先保留短原文和完整限定。例：「这次先别改支付，等接口升级后再统一调整」不能写成全项目永久「支付不动」。无法可靠保留限定时，该单元继续留原文；不得只靠模型自称校验通过而提交边界。实施需包含原文锚定、结构校验及固定语义样本复核，不能声称这些检查能证明任意摘要绝无遗漏。

网页、文件、工具内容或用户转述不能借摘录晋升为用户要求。助手说“已验证”只保留陈述身份，涉及真实状态时回查权威记录。情节可引用原批准/证据对象的位置，但不能重建 PermissionGrant、批准结果或 Evidence。秘密与凭据沿用现有敏感信息校验；命中时不提交该单元，未脱敏材料不得因此新增发送路径。

### 3. 情节记录的形状

本地情节全集是多页，按闭合前缀推进覆盖分界。每条保留原始来源，新页不把旧页收成没有出处的总摘要。以下为语义形状，协议与存储格式须在实施入口定型：

```text
episode {
  id: "ep-1"
  revision: 1
  conversationId
  sourceHash
  range: { from: "m1", to: "m9" }
  facts: [
    { id: "f1", kind: "user_constraint", text: "这次先别改支付，等接口升级后再统一调整",
      sourceIds: ["m1"], scope: { workRef: "w1", object: "支付" } }
    { id: "f2", kind: "assistant_claim", text: "已向 s1 交代按钮使用现有绿色",
      sourceIds: ["m6"], sessionRef: "s1" }
  ]
}
```

`range` 是已结束来回的闭区间，按持久化顺序而非 id 字符串排序。范围、源哈希与会话共同确定幂等身份；同一范围的并发模型输出不同也只能提交一份。范围重叠、越过未闭合单元或来源不匹配时拒绝新写；修正已有条目必须显式带预期版本，不伪装成重叠新页。

本地全集与本轮准入分开：

- 本地保存完整情节与来源索引，不因一次请求选不中而删除；遵守用户删除与撤销。
- 本轮只选入有限的相关情节、近期情节和必要对象引用；未选页仍可本地检索，来源编号不必全塞进请求。
- 所有仍适用于本次工作且未明确撤销的用户约束，必须在准入情节或逐字原文中存在。适用范围不明时保留原文或阻塞，不能仅凭相关性打分丢掉。
- 可选旧情节优先退出本轮投影；需要缩短文字时保留身份、来源与限定，不原地破坏本地记录。必要约束仍超预算时走 §8，不截字伪造完整性。

共享预算策略必须给出有限的情节条数/字符数、工具引用数、单次回读条数/字符数、每轮检索次数及短期引用数/保留轮次。实施入口冻结默认值、配置来源和策略版本，并以注入的小预算验证上界；缺失或非法预算不能退化成无限。字符/条数上界约束材料准入，不充当 token 证据；最终请求仍按 §1 计数。必要内容超界时显式阻塞。

选中的情节按历史顺序渲染，原文保持 canonical history 顺序。回读与工具引用走既有事实层，保留身份、来源标签和原时间；不冒充新用户发言，不因为排在后面就拥有更高权威：

```text
已选情节 + 回读 + 工具引用 -> 现有事实层 Context Source（归入 L7_CONTINUITY）
未覆盖逐字尾 -> canonical active history
两者 -> System Context / Provider Encoder / 容量流水线
```

- **`L7_CONTINUITY` 与 ADR 81 的预算仲裁**：本会话情节摘要、回读引用与 [ADR 81](81-project-agent-memory-system.md) 的长期记忆共同写入 [System Context 架构](../architecture/19-system-prompt-context-architecture.md) 中的 `L7_CONTINUITY` 连续性层；当主 Bot 上下文共享 ADR 81 的可执行 **6000 字符**连续性／简报上限时，两者必须在同一 `L7_CONTINUITY` 预算账本内显式扣减与仲裁，优先保留本轮适用用户约束与当前任务指令，禁止长期记忆与情节整理各自叠加撑破上限。

当前用户纠正优先于情节；记忆与情节不得越过项目指令或系统规则。只有同一对象、同一范围内明确的后续更新才能取代旧陈述。旧情节可保留历史并标记被取代，来源编号仍指向原话；较新的助手猜测、不同任务要求或回读的旧原文不能自动覆盖用户决定。无法判断冲突时回读或询问，不自行扩大全局适用范围。

### 4. 回读

整理不删除交互记录。回读有两种入口：

1. 已知情节与 `sourceIds`：按精确身份读取原消息。
2. 摘要未保留的细节：按用户指代、对象、时间或关键词，在当前授权会话的情节及交互历史中做有界本地检索，再回读命中原文。索引可重建，不能把“没找到情节”直接当“历史从未说过”。本地全文检索直接复用 [ADR 104-progressive](104-progressive-interaction-and-coordination-storage.md) 既有交互 SQLite/FTS 派生索引机制，**禁止新增向量服务或第三套独立全文索引**。

检索/读取须复用或扩展受治理的只读 Provider seam：Capability Provider → Manifest → Runtime Projection → Tool Call → PermissionGrant → Evidence。模型可见能力需在实施前完成协议、投影与权限评审；投影模块不隐式执行 shell、任意文件读取或跨会话搜索。**非阻塞回读约束**：回合内情节整理后的自动／上下文被动回读仅允许消费已授权且立即可读的当前会话只读切片，缺权或越界时按 fail-closed 结构化返回缺失／拒绝原因，**严禁在模型回合装配或续跑中途弹出交互式 `PermissionGrant` 审批框而阻断主回合**。无现成能力时明确记录缺口，不宣称方案已可回读。拒绝、超时、缺源与范围外读取分别返回结构化结果，不猜测相似对象。

正文只在本轮事实层使用。后续在有限轮次保留源消息 id、对象与检索定位作为短期引用，支持“那第二个呢”一类追问；不复制整份回读正文，不绕过再次读取权限。引用仍受预算、源版本、撤销及删除检查。回读旧话不会获得当前用户消息的时效或指令地位。

### 5. 工具痕迹

只处理主会话已准入记录能解析的工具痕迹，不读取子会话内部日志补全主会话。逐字尾之外的调用和结果只形成有界引用：调用名、一行带身份的结果描述和原结果/Evidence 引用；描述不能代替原结果或证明。逐字尾内仍复用 ADR 57 的工具配对、附件与 thinking 排除规则。缺结果或结果未落盘时，包含调用的单元不能推进覆盖分界。

### 6. 与长期记忆及用户控制的关系

本文情节是本会话上下文的派生记录，不自动成为 ADR 81 的项目知识、跨项目偏好或已验证经验。需要长期复用时仍经过 ADR 81 的 Curator 与准入，不建立第二个偏好/约定真源。相同来源在长期记忆与情节中重复时，事实层按来源、对象和范围去重，并保留两者出处。

关闭 ADR 81 的长期记忆学习/使用，仍可进行必要的本会话容量整理；不得借此继续长期提取或跨会话注入。关闭项的作用范围必须准确表达。查看、纠正或撤销情节可复用按需来源/记忆入口，不向聊天插入日常整理通知；所需入口尚未实现时列为实施验收缺口。

用户撤销某条长期记忆不等于删除全部聊天原文，但同一源命题不得借情节、索引或短期引用重新作为当前有效约定注入；撤销须能传播到这些派生准入。显式回顾历史时只能作为已撤销的历史陈述返回。源消息被编辑、删除或用户明确要求遗忘时，对应情节/索引/短期引用按身份失效；派生失效与请求版本校验防止在途旧结果复活。未完成重建的范围回到可读取的原文或明确缺源，不沿用失效摘要。

删除会话时清理其情节与派生索引；不因此删除独立任务历史、未知副作用或 Evidence。情节存储登记于现有数据清单，明确会话 scope、版本及迁移/导出行为，不写入代码仓，不新增云同步。

### 7. 整理的提交、并发与调度

交互记录是双方说过什么的真源；情节 store 持有已提交范围与版本；现有容量流水线持有请求容量事实。两宿主共用一个整理服务和投影算法，宿主只适配读取、提交、模型执行及通知。

1. **取快照。** 绑定会话、闭合范围、源内容哈希、情节预期版本及宿主 lease/generation，锁内只做必要读写，不在模型网络请求期间持锁。
2. **生成与校验。** 在锁外分类、抽取、压缩及校验。已有完整前缀不因尾部新增输入而自动作废；涉及范围被编辑、删除、重新打开或新增关联未决事实时作废候选。
3. **原子提交。** 在现有跨进程提交/租约边界下复核范围、源哈希、预期版本与有效宿主身份，将情节、覆盖范围、版本及对应 epoch 作为一个逻辑提交单元。提交要么全部可见，要么都不可见；不得先推进分界再写正文。容量证据按新版本失效，不能继续信任旧指纹。
4. **冲突与采用。** 重复范围按幂等身份返回已提交记录。并发写输的一方丢弃候选，读取权威新版本并重建下一请求；不覆盖、不长期保持旧投影。已发出的 immutable 请求不回溯修改；尚未发送的请求在 send 前复核源/情节及撤销版本，变化则重建。
5. **重启。** 只恢复完整提交，丢弃未提交候选，不自动重放上次未完成的模型请求。需继续整理时从当前已闭合范围重新调度，并沿用预算与去重身份。

常规后台整理使用现有低优先级后台调度及模型通道，不占用户回复槽、不抢焦点；同一会话不并发启动重复整理。每次运行有明确范围、请求数上限、超时与取消信号，失败不自建重试循环。hard 路径允许等待有界预检，等待不影响草稿编辑或停止。

用户停止本轮时取消属于本轮的摘要等待与未提交候选，不自行续跑回复；lease 丢失、宿主交接或退出后旧 generation 不可再提交。模型切换取消旧路由候选并按新模型重建/计数，已提交情节仍保留。摘要请求标记 `requestPurpose=compaction_summary`、`capacityBearing=false`，按 ADR 56 记录正常、失败与停止的 usage；摘要费用不能覆盖主会话 `lastObserved`，也不能复用上一轮计费数。

### 8. 容量失败与已有会话恢复

回退先保留上一份有效情节与所有未覆盖的可准入原文，去除可选情节/重复引用并重新计数。不得为了回复成功而裁掉未摘要历史、当前未答输入或仍适用的约束。摘要更长、敏感校验失败、没有可整理的闭合单元或必要内容仍超预算时，返回绑定原 inputId/attempt 的结构化容量阻塞：保留输入、情节版本、失败原因与诊断引用，明确尚未产生业务答复，不写假 Bot 成功回复。

容量阻塞沿现有错误/恢复入口表达，不使用整理进度横幅、不抢焦点。展示实际可用的重试、编辑输入或用户选择更大窗口模型等恢复动作；没有相应宿主能力就说明缺口，不画假按钮，不静默切模型、清空历史或请求用户盲目重试。恢复后重新核对版本和容量，以稳定输入身份去重；阻塞整理不永久占住回复槽，后续用户输入仍按既有队列准入，不因解除容量阻塞重放工具副作用。

Provider overflow 继续按 ADR 56：记录该请求的实测错误证据 → 有界紧急整理 → 重建/精确重计（可用时）→ retry once → 再失败结构化终止。没有发生完整覆盖提交时，不能伪造新边界；同一恢复链不能通过换宿主或重启清零重试预算。

旧主 Bot 没有情节时也先经过容量检查：能安全发送才按现有记录发送，回复后再补情节；超窗则发送前分批整理已闭合前缀。首次调用就无法保真准入时同样返回容量阻塞。旧 `_compaction` 保持 ADR 57 的原分界与连续性语义，不改写成情节；新情节从该 active history 的有效范围衔接，不复活旧分界前的全文，也不把旧摘要说成逐字源事实。显式回读旧原文仍须校验来源存在与读取范围。

## 临界点

这些情况必须在实现前有测试，不能靠提示词碰运气。

1. **未答完。** 已提交未答输入与开放问题保护相应单元；未提交草稿始终只属于输入现场，不进入逐字尾或后台摘要。尾部追加输入不自动取消安全前缀整理。
2. **工具成对。** 只有调用没有结果，或结果还没落盘，这段不能收成情节。
3. **决定不能丢。** 仍适用的用户决定、否定、条件和例外必须出现在本轮情节或逐字原文之一；范围不明时回读、保留或阻塞，不能只留摘要套话。
4. **两扇窗。** 按预期版本、源哈希与宿主身份提交；写输的一方重读权威版本并重建下一请求。
5. **崩溃。** 情节要么连同源范围一起提交，要么完全不存在。不允许只写下半段摘要。进程重启后按已提交的情节投影，不重放未提交的摘要请求。
6. **摘要更长。** 先减少可选准入，必要内容仍放不下则阻塞。不得截断限定、删除当前输入、裁掉未覆盖历史或以丢失来源的总摘要腾空间。
7. **摘要说错。** 当前用户纠正、撤销与源编辑让派生准入失效或更新；旧编号仍可审计，但不能继续作为当前约定。
8. **命令行和桌面一致。** 相同源快照、情节版本、预算策略与回读事实产生相同 canonical messages、事实块及投影指纹；Provider wire 差异仍由 Encoder 处理。
9. **界面不动。** 整理前后，交互记录的消息 id 和顺序不变。用户滚动位置、草稿和焦点保持原状。
10. **不是子会话。** 主 Bot 不进入 `resuming_after_compaction`，不使用 `goalKeepPolicy`，也不调用 `prepare_context_handoff` 来代替情节。
11. **摘要没记住。** 情节中没有某个细节时仍可检索原历史，不能把未提取当成不存在；旧话回读不晋升为新指令。
12. **长谈有界。** 本轮可选情节、回读、工具引用及短期引用均有上界。必要约束超预算允许明确阻塞，不能宣称无限历史总能无损装入有限窗口。

## 工程落点

新增一个共享主 Bot 上下文 Module，由两边 `executeTurn` 使用；投影与整理提交在 Module 内保留清楚的纯计算/宿主 I/O Seam，不能用两份宿主实现拼出相似行为。Interface 接受源快照、情节版本、预算策略与本轮已准入事实，输出 canonical messages、事实块、覆盖/选入来源、版本与稳定投影指纹，或结构化阻塞。分类、选入、约束保留、版本和失败语义集中，提高 Locality；不新增只转发的包装层。

主 Bot 复用 ADR 57 的 canonical 消息解释原语，不复制工具配对、附件、thinking 排除或 Provider 格式规则。现有 `projectConversationHistory` 继续解释经典对话及旧 `_compaction`；主 Bot 新分界来自已提交情节，且不能被后续普通压缩旁路再次写成假用户交接。事实块经现有注册 Context Source 进入事实层，不新增系统指令层序或 renderer 拼接路径。

情节存在会话数据根下的旁路记录，带 schema/reader/writer 版本、源范围和内容哈希；跨进程提交及数据登记复用现有存储机制，衍生全文索引复用 [ADR 104-progressive](104-progressive-interaction-and-coordination-storage.md) 的 SQLite/FTS 底座而非另建第三套索引。实施时必须定义旧宿主遇到新情节数据的兼容门禁（若需扩展协调/可读格式版本，**必须取 `> 11`（`12+`）未占用代次**，不得复用已被占用的 `<= 11` 门禁），不允许忽略情节后重新发送全文或降级覆盖。只有派生索引可重建；重建不能覆盖未知源数据、历史或 Evidence。

预检、计量、计费、Provider overflow 和取消继续由已有运行时拥有。接受并实施本文前，冻结预算默认值、最小 reader/writer、只读检索能力的复用/扩展方案及恢复入口映射，并写入实施记录；不能将这些必要 Interface 留给两宿主自行猜测。没有相应模块/宿主验证时，本 ADR 不可标注实现完成。

## 明确不做

- 不把正常整理过程画进主 Bot 界面；真实容量阻塞必须可见、可恢复。
- 不把摘要伪装成用户说过的话。
- 不改子会话、Goal Runner 和 `prepare_context_handoff`。
- 不把情节当成权限、批准或 Evidence。
- 不新写触发百分比；soft/hard 沿用 0.8/0.92，容量证据与放行服从 ADR 56。
- 不把旧情节再摘要成丢掉 `sourceIds` 的一页。
- 不为本轮准入删除历史，不承诺无限历史和无限约束总能无损进入有限窗口。
- 不自动建立跨会话偏好，不绕过长期记忆的撤销，也不新增云同步或向量服务。
- 本文被接受之前不实现。
