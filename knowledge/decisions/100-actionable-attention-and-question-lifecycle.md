# ADR 100：待处理事项与对话提问生命周期

创建时间：2026-10-20
最后更新：2026-10-20
状态：Accepted（按用户要求实施）
级别：A；Protocol 展示契约与宿主提问准入调整。

## 背景与根因

机器人角标把所有未回答历史提问、waiting_user / result_ready 子任务、授权直接相加。会话卡片使用另一条投影。后来的提问、替代流程和用户答复没有结束更早的决策；主 Bot 应接手的等待也被算作用户责任。点击数字只筛选机器人，无法解释或处理数字。

## 决策

### 1. 一份待处理投影

新增 Attention Module：Interface 是 workspace、当前简化消息、当前 session、审批与确认事实以及宿主投影的任务提问卡；Implementation 产出有稳定 ID、来源、类型、摘要与目标的条目。角标严格等于条目数量。明细使用相同 Module，不能另加计数规则。跨机器人入口按机器人分组，单机器人角标只看该机器人。无事项时明确空态。

只计入当前可操作的主对话问题、尚有效的待批准、明确需要用户签收的结果与人工完成检查。结果确认由 Supervisor 的实际签收判定和关闭闸门共同投影，不能只看机器人默认配置；目标任务的独立策略与用户显式要求复核仍然生效。waiting_user / 技术阻塞 / 主 Bot 的后续处理本身不等于需要用户。已批准/过期/取消的权限、已接受/取消任务和旧错误不计入。相同来源按 ID 去重；审批覆盖同一任务结果确认时不能重复占位。

人工完成检查的确认一旦持久化，就撤掉待用户复核事项。即使后台续跑失败或重启后暂时仍看到原 manual DoD 阻塞，恢复由 Bot 接手，不能要求用户重复确认；后续报告发生实质变化时仍由原 reviewToken 闸门重新判定。

发布前复核补充：子任务实际 `request_user_input` 及前置依赖的明确决策同样是用户可操作问题。必须从既有 Card Projection 获取开放且含回答动作的任务提问卡，按 cardId 去重；仅 `waiting_user` 仍不增加计数，已解决或已取消任务不能重新进入。列表用专门的轻量任务提问读取，复用相同提问事实与卡片解决记录；禁止为 200 个机器人读取全部协调日志、记忆与旧错误卡。主会话答复不应替代另一条子任务问题的显式回答。

### 2. 对话问题是当前决策，不是永久待办

每个机器人主会话同时只有一个当前对话决策。新正式 agent_reply 开始新的决策代次；更早问题被 superseded。公开 Activity 和内部 agent_turn 不结束决策。当前问题收到明确 answerTo 或既有无引用直接答复即 answered；有明确 expiresAt 的问题到期为 expired。宿主按最近截止时间发出刷新事件，角标、已打开明细和历史页自动回读；取消或替代截止时间会撤掉旧定时器。定时器不批准或拒绝权限。没有任意固定时间猜测授权失效，也不靠文本相似度识别重复。

历史问题保留正文及来源，分页响应携带当前可操作问题 ID，已缓存的旧页同步撤掉失效动作；自动收尾只改变问题可操作投影，不删除或改写消息、不代替授权、签收或取消。重启后从相同 canonical 事实重建相同结论。旧客户端的失效 answerTo 必须在宿主入队前拒绝为 QUESTION_CLOSED，返回可刷新反馈；不将迟到点击唤醒为新工作。重复 inputId 沿用原队列幂等语义。

生命周期使用一次扫描，缓存只依托已有历史 projection/revision；禁止逐问题对完整历史重复扫描。主对话历史卡片、列表、明细共用生命周期结论。

### 3. 明细与操作

数字打开“需要你处理”面板，显示机器人、事项内容、类型及明确动作，可定位原消息/任务。复用现有 CardView 及 submit-input / decide-approval / confirm-result 入口；完整报告应先展示，人工 DoD 不允许用摘要一键跳过。

所有写操作重读当前宿主事实、检查 workspace 和当前卡状态。失败保留事项与可重试反馈；成功后重新读取明细及机器人列表。面板关闭、换机器人、迟到请求、重复点击、并行刷新均不得混入旧数据。键盘可打开/关闭、焦点进面板并回触发按钮；窄窗与 reduced-motion 可用。

消息定位按实际到达顺序仲裁明细与通知，不比较两个独立来源的序号大小或墙上时钟。明细定位记录当时的通知代次；后到通知立即取得焦点，之后新明细操作仍可接手。连续定位同一消息也保留独立请求身份。

### 4. 边界与后果

PermissionGrant、Evidence、任务状态与接受闸门不变。Renderer 只表达事项并发既有请求，无 fs、密钥或权限真值。自动关闭问题不是自动同意任何动作。旧 waiting_user 的主 Bot 接手/任务取消缺陷仍须由原 Supervisor 治理，本 ADR 不伪造其终态。

新协议仅承载有界展示事实，不含 Tool Result/检查点/完整历史。仅当前对话问题附带至多 2000 字符的公开上下文；旧提问不复制长正文。原文入口保留完整内容。明细按需加载；角标只用已缓存的简化历史与会话事实，避免重新引入全历史 I/O 卡顿。

## 验证

- 重放用户截图时的三条历史问题与 waiting_user：回答最新问题后角标 0；新提问出现后为 1，旧问题不复活。
- 新提问替代、直接答复、明确答复、带引用无关输入、内部进度不替代、到期、重启、重复来源、被取消结果、权限隔离与迟到点击。
- 完整 Desktop：点击全局/机器人数字、可读明细、实际答复入队/授权/结果确认、失败保留、成功计数归零、外部状态更新、空态、键盘与深浅/宽窄窗口。
- 用用户数据的只读最小事实副本及同等历史规模检查投影与交互；不在个人任务上模拟批准或取消。
- 标准 qa:product:capture → 每图 AI 审查 → qa:product:verify；记录实现者自审、真实模型/安装包/读屏覆盖限制。
