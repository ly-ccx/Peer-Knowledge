# 机器人模型选择与推理强度

创建时间：2026-10-04
最后更新：2026-10-04
状态：按负责人本轮请求实施；ADR 83 的增量契约

## 范围与层级

这是 A 级模型配置契约补齐。每个机器人可以直接选模型与推理强度，输入框显示实际解析的对话模型。复用现有模型级联选择器、推理强度滑块、profile.json 和 project-agent:get / update-profile；不新增 IPC、依赖、存储路径、能力或权限。

## 配置与解析

- `RoleSetting` 的 fixed 模式增加可选 `reasoningEffort`。缺省继续使用模型默认强度，旧配置保持兼容。
- 更改强度会把当前解析的模型固定到本机器人该角色；恢复“跟随全局”会同时删除该角色的模型与强度覆盖。
- 主进程校验强度必须是所选模型支持的档位。未声明推理能力的模型不显示可调滑块，也不能持久化虚假的强度。
- 模型目录投影透传可用性与实际推理档位。可选模型继续经过角色能力、项目范围、本地限制过滤。过滤失败明确返回，不用 renderer 的选中状态替代运行配置。
- 模型切换时只保留新模型支持的强度；否则选择新模型实际默认档位。按声明显示，不给不支持的模型发明档位。
- `resolveRoleRoute` 返回最终强度，执行器将冻结的 `turnProfile.modelSelection.reasoningEffort` 送给已有 Provider encoder。新任务快照冻结各角色的模型与强度；运行中的任务保持原快照。

## 表达与实效

- 输入框底部显示当前对话模型与强度，可以原地修改；不是只显示“跟随全局”。继承来源在设置提示和 tooltip 中披露。
- 设置页同样使用级联模型选择器。主要入口为对话模型、任务执行、复核；其他角色与范围限制按需展开。
- 正在生成时显示当前回合冻结的模型，不把下一轮配置冒充当前模型。流式 Activity 增加可选模型快照；回合结束后显示下一轮解析结果。
- 主进程以当前目录和设置计算轻量只读投影，不在每个菜单渲染时反复读取完整用量账本。
- 设置写入失败保持原值并展示错误；切换机器人不串配置；全局配置变化后重新读取投影。

## 验证边界

需要覆盖：profile 重启、非法强度原子拒绝、范围/能力过滤、固定强度进入真实执行请求、任务快照冻结、活跃回合与下一轮区分，以及原生选择器/强度滑块/窄窗口交互。实机 Demo 使用隔离数据和受控 Provider；它验证请求参数，不代表真实订阅请求或真实推理质量。

## 角色实效与兼容

对话、任务执行、复核、探索、视觉复核、记忆整理、目标探查的模型覆盖沿已有角色路由生效。本轮补正记忆整理宿主遗漏的项目策略和强度转交。压缩目前沿正在使用的对话 Provider 执行，没有独立 compactor 路由接缝；设置页隐藏该未接入角色，不把保存偏好冒充实际生效。协议及旧配置中的 compactor 数据保留兼容。
