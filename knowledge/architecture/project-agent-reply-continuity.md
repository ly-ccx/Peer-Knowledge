# 项目代理连续回复投影

创建时间：2026-10-22
最后更新：2026-10-22

用户授权：统一等待、流式表达、正式回复和异常恢复；保留任务、对话、Evidence 与在制改动。本次只实现与代码审阅，测试在发布前执行。

## 分级与边界

状态投影为 B 级；`ProjectAgentActivity` 的可选展示字段扩展为 A 级，本设计先于实现。Renderer 仅表达既有事实；输入、调度、权限、工具执行、宿主回复校验和 Evidence 沿用原链路，不新增执行入口、存储或日志快照。

## 身份与状态

- 一次用户交互包含一个或多个输入、多个调度切片或恢复尝试。执行 `turnId` 不能单独充当视觉消息身份。
- Activity 新增可选 `workId`，复用宿主协调工作的现有身份；新增可选 `recovery: connection | provider`，仅由真实恢复事件设置。旧客户端可忽略，旧记录缺字段仍按输入锚点、turnId 兼容。
- 连续回复 Module 汇合输入回执、公开段落、Activity、持久 `agent_turn.meta.workId` 与正式回复，生成稳定的显示行。按明确 replyTo/turnId/workId 关联，不通过正文相似度猜测任务归属。一次正式投递结束一条回复；后来的主动结果仍是新消息。
- 等待行、流式行与正式回复使用同一个容器及段落身份；完成不重建头像、已公开段落和正文节点。独立问题与权限卡保持原动作身份。原始消息 ID、引用、详情与 Evidence 仍可定位，不以视觉合并覆写存储。
- 每条本地输入单独等待自己的答复；接收回执、内部回合、无关 wake 或其他输入的回复不能清掉它。连续输入可被宿主批量承接。重开时只恢复最近尚未收尾的输入；缺少活跃宿主事实时显示尚未确认的回复状态，不伪造正在执行，也不自动重发。

## 恢复与表达

- 无首字时只显示轻量存在反馈，常规 waiting/thinking/tool 切换不轮播内部文案。公开文字到达即接上，不制造首句、思考正文或人工打字延时。长等待只说明客观耗时，不能凭定时器宣布失败、恢复或任务完成。
- 恢复保持同一回复位置；废弃尝试的临时段落和未校验结论仍按治理 §十四撤回，不拼接到新尝试。已经持久化的公开段落、正式回复、失败诊断、工具记录和 Evidence 不删除。
- 正式投递前的草稿不是宿主确认的结果；被拒绝或抑制时撤回草稿并继续同一交互。失败、停止和待授权进入同一回复位置，使用原结构化卡片与恢复动作。无执行结果的操作不能自动重放。
- 后台任务继续由任务区表达；主 bot 本轮答复结束即可停止回复动效。历史头像静态；可见当前交互的头像与标题共享当前回复状态，减少动态设置继续生效。
- 正在阅读历史时保留阅读锚点；只在用户发送或位于底部时跟随。等待区域必须纳入同一滚动几何，避免独立尾部提示高度漏算。
